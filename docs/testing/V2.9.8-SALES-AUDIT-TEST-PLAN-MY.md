# v2.9.8 Sales Audit Test Plan

| Test | လုပ်ဆောင်ချက် | မျှော်မှန်းရလဒ် |
|---|---|---|
| A | Cashier Online Sale တစ်ခုလုပ် | Sale + Stock deduction + `SALE_CREATED` Audit Event တစ်ခုတည်း transaction အတွင်း သိမ်း |
| B | Owner Activity Log ဖွင့် | နောက်ဆုံး ၁၀၀ Cloud Audit Event ကို fetch-on-demand ပြ |
| C | Owner မှ Cash Sale ကို reason ဖြင့် Void | Sale status voided၊ Product/Batch Stock ပြန်တိုး၊ `SALE_VOIDED` Event ဖန်တီး |
| D | Void ခလုတ်ကို ထပ်ခေါ်ရန်ကြိုးစား | Stock ထပ်မတိုး၊ Event ထပ်မဖန်တီး |
| E | reason မထည့်ဘဲ Void | UI မှ တား |
| F | Cashier အကောင့်ဖြင့် Void လုပ်ရန် | Owner-only UI/Firestore Rules က တား |
| G | ကြိုတင်ပေးထားသော Credit Sale ကို Void | UI နှင့် transaction က တား |
| H | Cloud ထဲမရောက်သေးသော Local Sale ကို Void | Cloud Sale မရှိကြောင်းပြပြီး မလုပ်ဆောင် |
| I | Offline Cashier Sale Queue | Queue ထဲ pending; Cloud audit မပေါ်မီ Synced လို့ မပြ |
| J | Firestore Rules မPublish ရသေး | Permission error ပြ; Sale ကို duplicate မတင် |

## Post-check

- Sale Record တစ်ခုသာ ရှိရမည်။
- Product Stock သည် မူလအရောင်းပမာဏအတိုင်း တစ်ကြိမ်သာ ပြန်တိုးရမည်။
- Batch Allocation ရှိသည့်အခါ သက်ဆိုင်ရာ Batch များသာ ပြန်တိုးရမည်။
- `auditEvents` doc ကို Update/Delete မလုပ်နိုင်ရ။
- Owner ကသာ Audit History ဖတ်နိုင်ရမည်။
