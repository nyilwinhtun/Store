# v3.2.0 Preview 1 — Barcode Sticker Unit Test Plan (မြန်မာ)

## စမ်းသပ်မည့်ရည်ရွယ်ချက်
ဆိုင်မှ ဝယ်ထားသော Unique Barcode Sticker တစ်ခုစီကို Physical Stock Unit တစ်ခုအဖြစ် စာရင်းသွင်းပြီး POS တွင် တစ်ခုချင်း ရောင်းချနိုင်ကြောင်း၊ ရောင်းပြီးသော Barcode ကို ထပ်မရောင်းနိုင်ကြောင်း စစ်ဆေးရန်။

## A. Product နှင့် Sticker စာရင်းသွင်းခြင်း

1. Branch 1 တွင် Product အသစ်တစ်ခုဖန်တီးပါ။ ဝယ်ဈေး/ရောင်းဈေး သတ်မှတ်ပြီး Opening Stock ကို 0 ထားပါ။
2. Inventory ထဲက “Sticker Scan ဖြင့် Stock ထည့်ရန်” ကိုဖွင့်ပါ။
3. Product ကိုရွေးပြီး ဆိုင်က ဝယ်ထားသော Barcode Sticker ၃ ခုကို Scan လုပ်ပါ။
4. Save ပြီးနောက် Product Stock = 3၊ `in_stock` Unit = 3 ဖြစ်ရမည်။
5. Barcode တစ်ခုကို ထပ် Scan လုပ်ပါ။ Duplicate အဖြစ် ငြင်းပယ်ရမည်။
6. Product SKU သို့မဟုတ် Product-level Barcode နဲ့ တူညီသော Sticker ကို မှတ်ပုံတင်ခွင့်မပြုရ။
7. ရှိပြီးသား Product Stock ၅ ခုကို စတင် Unit Tracking ပြောင်းရာတွင် Sticker ၄ ခုသာ Scan လုပ်လျှင် Save မအောင်မြင်ရ။ ၅ ခုလုံး Scan လုပ်မှ အရေအတွက် မတိုးဘဲ Registry ချိတ်ဆက်ရမည်။

## B. POS Scan / Checkout

1. Branch 1 Cashier Account ဖြင့်ဝင်ပါ။
2. `in_stock` Barcode Sticker တစ်ခုကို POS တွင် Scan ဖတ်ပါ။ Cart ထဲတွင် Product Quantity = 1 ဖြစ်ရမည်။
3. Quantity ကို 2 တိုးရန် + နှိပ်ပါ။ နောက်ထပ် Sticker Scan မရှိလျှင် တိုးခွင့်မပြုရ။
4. ဒုတိယ Sticker Scan လုပ်ပါက Quantity = 2 ဖြစ်ရမည်။
5. Checkout ပြီးသောအခါ Sale, Product Stock, Batch Stock နှင့် Unit Registry မှတ်တမ်းများကို စစ်ဆေးပါ။ ရောင်းထားသော Unit သည် `sold` ဖြစ်ရမည်။
6. အဲဒီ Barcode ကို POS မှာ ထပ် Scan ဖတ်ပါ။ ရောင်းပြီးသားအဖြစ် ငြင်းပယ်ရမည်။
7. Barcode တစ်ခုတည်းကို Cart ထဲ နှစ်ကြိမ်ထည့်ခွင့်မပြုရ။

## C. Cloud / Offline / Void

1. Internet ရှိချိန် Cashier Sale ပြုလုပ်ပါ။ Cloud Transaction တစ်ခုတည်းတွင် Sale, Product Stock, Batch Stock နှင့် Unit Registry အားလုံး ပြောင်းလဲကြောင်း စစ်ဆေးပါ။
2. တူညီသော Sale ကို Retry လုပ်ပါက Stock နှစ်ကြိမ် မလျော့ရ။
3. Internet ပိတ်ပြီး Sale ပြုလုပ်ပါ။ Local မှာ Barcode `sold` ဖြစ်ပြီး Sale က Pending Cloud အဖြစ် ကျန်ရမည်။
4. Internet ပြန်ချိတ်ပြီး Sync လုပ်ပါ။ Cloud မှာ Sale အဖြစ် တစ်ကြိမ်သာ သိမ်းရမည်။ Status မကိုက်ညီပါက `needsReview` အဖြစ် ထိန်းထားရမည်။
5. Owner က Void လုပ်လျှင် Sale Audit ရှိရမည်။ Exact unit ကိုသာ `in_stock` ပြန်ဖြစ်ရမည်။ Barcode record ကို ဖျက်မပစ်ရ။
6. Void ကို ထပ်လုပ်ပါက Unit ကို နှစ်ကြိမ် Stock ထဲပြန်မထည့်ရ။

## D. Quantity-only Operations Guard

1. Unit Barcode ရှိပြီးသား Product ကို Manual Stock Adjustment လုပ်လျှင် ပိတ်ထားရမည်။
2. အဲဒီ Product ကို Supplier Purchase / Quantity-only Stock Receiving ဖြင့် ထပ်တိုးလျှင် ပိတ်ထားရမည်။
3. အဲဒီ Product ကို Supplier Return ဖြင့် Quantity-only လျှော့လျှင် ပိတ်ထားရမည်။
4. အဲဒီ Product ကို လက်ရှိ Quantity-only Branch Transfer ဖြင့် ပို့ရန် ကြိုးစားလျှင် ပိတ်ထားရမည်။
5. Unit-tracked Product အတွက် Quantity-only Shipment Cancel / Branch Transfer ကို မခွင့်ပြုရ။ Barcode-aware Branch Transfer ကို မပြီးမချင်း ဒီ Product ကို ဆိုင်ခွဲအချင်းချင်း မရွှေ့ရ။

## E. Security / Multi-Branch Emulator Tests (မဖြစ်မနေ)

1. Owner က Branch 1/Branch 2 Registry နှစ်ခုလုံးကို ဖတ်နိုင်ရမည်။
2. Branch 1 Cashier က Branch 1 Registry ကိုသာ ဖတ်နိုင်ရမည်။ Branch 2 Registry ကို မဖတ်နိုင်ရ။
3. Cashier က Sale ဖန်တီးခြင်းမရှိဘဲ Registry ကို update လုပ်၍ မရရ။
4. Cashier Sale နှင့် Registry update တူညီသော Transaction ထဲမှာ link ဖြစ်ရမည်။
5. Registry update က `branchId`, `productId`, Unit အရေအတွက်တို့ကို ပြောင်းလဲခွင့်မရှိရ။
6. Security Rules ကို Firebase Emulator ဖြင့် အတည်ပြုမပြီးမချင်း Production Rules သို့ မတင်ရ။

## Preview အတွက် သိရှိထားရန်

- ဒီ Preview တွင် Barcode-aware Branch Transfer မပါသေးပါ။ Unit-tracked Product ကို Quantity-only Transfer ဖြင့် ပို့ခြင်းကို တားထားသည်။
- Owner Auto Sync Sale path သည် Cashier သီးသန့် Transaction Path နှင့် မတူသောကြောင့် Owner အနေနှင့် Unit Barcode ပါသော Sale ကို Production မှာ မသုံးခင် အထူး regression test လုပ်ရန်လိုသည်။
- Full TypeScript/Vite Build၊ Firebase Emulator Rules Test နှင့် Live Firebase Test မလုပ်ရသေးပါ။
- အထက်ပါစမ်းသပ်ချက်များအားလုံးကို လက်တွေ့အောင်မြင်ကြောင်း မှတ်တမ်းမတင်မီ Production အသုံးမပြုရ။
