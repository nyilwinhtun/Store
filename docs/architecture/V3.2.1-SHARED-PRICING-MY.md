# Minimart POS v3.2.1 — Shared Pricing

## ရည်ရွယ်ချက်

ဆိုင်တစ်ဆိုင်ချင်းစီ၏ Product Catalog နှင့် Inventory ကို သီးခြားထားပြီး Owner က တူညီသည်ဟု အတည်ပြုချိတ်ဆက်ထားသော Product များ၏ Retail / Wholesale ဈေးနှုန်းကိုသာ မျှဝေထိန်းချုပ်ရန် ဖြစ်သည်။

## အဓိကဆုံးဖြတ်ချက်များ

- Branch တစ်ခုချင်းစီ၏ Product Record၊ Product ID၊ Stock၊ Cost Price၊ Batch၊ Purchase၊ Sale၊ Cash၊ KPay၊ Expense၊ Shift နှင့် Finance သီးခြားဖြစ်သည်။
- Product များကို အလိုအလျောက် မပေါင်းစည်းပါ။ Owner က အနည်းဆုံး Branch ၂ ခုမှ Product တစ်မျိုးစီကို ရွေးချယ်ပြီးမှ Price Group တစ်ခုတည်းသို့ ချိတ်နိုင်သည်။
- Price Group တစ်ခုတွင် Branch တစ်ခုမှ Product တစ်မျိုးသာ ပါဝင်နိုင်သည်။
- Shared Price Group သည် MMK Retail / Wholesale Price ကိုသာ မျှဝေသည်။ Cost Price နှင့် Stock ကို မမျှဝေပါ။
- Product တွင် `priceGroupId` နှင့် `priceVersion` ထည့်ထားသည်။ မျှဝေဈေးကို Product Record ထဲတွင် Mirror လုပ်ထားသဖြင့် Cashier သည် Price Group Collection ကို သီးခြားဖတ်ရန် မလိုပါ။
- Shared Price Group Master ကို `businesses/{businessId}/shared/priceGroups/records/{priceGroupId}` တွင် သိမ်းသည်။
- Group Master တွင် `membersByBranch` Map (Branch ID -> Product ID) ပါဝင်သည်။ Branch တစ်ခုလျှင် Product တစ်ခုသာ ခွင့်ပြုသည်။ Firestore Rules သည် Product Link / Price Update / Unlink / Delete အချိန်တွင် Post-transaction Group Membership နှင့် Price Mirror ကို စစ်သည်။
- Branch Product များကို မူလ Branch Collection တွင်ပင် ထားသည်။ Product ID / Branch ID မပြောင်းပါ။ Branch တစ်ခုကို Archive လုပ်ခြင်းသည် Shared Price Group ကို မဖျက်ပါ။ Group ထဲရှိ Archived Branch Product ကို label ဖြင့်ပြပြီး Owner က Unlink / Group Update ကို ဆက်စီမံနိုင်ရမည်။
- Cart Item တွင် `priceGroupId` / `priceVersion` Snapshot ပါနိုင်သည်။ Sale ၏ `unitPrice` သည် historical authoritative value ဖြစ်ပြီး အရင် Voucher များကို Price Change လုပ်ခြင်းဖြင့် မပြောင်းစေရ။
- Checkout မတိုင်မီ Cart Snapshot ၏ Group / Version / Unit Price ကို လက်ရှိ Branch Product နှင့် နှိုင်းယှဉ်သည်။ မကိုက်ညီပါက Cart ဈေးနှုန်းကို Refresh လုပ်ပြီး ငွေရှင်းမှုကို တစ်ကြိမ်ရပ်ကာ Cashier က Total ကို ပြန်စစ်ရသည်။
- Cashier Offline Queue သည် Cloud Transaction အတွင်း Product ရဲ့ လက်ရှိ Shared Group / Version / Unit Price ကို ထပ်စစ်သည်။ မကိုက်ညီပါက Sale ကို `needs-review` အဖြစ် ထိန်းပြီး Cloud Stock ကို မလျှော့ပါ။

## Owner လုပ်ဆောင်ပုံ

1. Sidebar မှ `မျှဝေဈေးနှုန်း` ကို ဖွင့်ပါ။ Active Branch ၂ ခုနှင့်အထက်ရှိ Owner က Group အသစ်ဖန်တီးနိုင်သည်။ ရှိပြီးသား Active Price Group တစ်ခုတွင် Archived Branch ပါနေပါက Active Branch တစ်ခုသာ ကျန်သော်လည်း Owner သည် ရှိပြီးသား Group ကို ဆက်လက်ကြည့်ရှု၊ Update / Unlink / Archive လုပ်နိုင်သည်။
2. `ဈေးနှုန်းအုပ်စုအသစ်` ကိုနှိပ်ပါ။
3. အနည်းဆုံး Branch ၂ ခုမှ Product တစ်မျိုးစီကို ရွေးပါ။ Branch တစ်ခုမှ Product နှစ်မျိုးရွေးမရပါ။
4. Group Name၊ Retail Price၊ Wholesale Price ထည့်ပြီး ချိတ်ဆက်ပါ။ ရွေးထားသည့် Product များ၏ မူလဈေးကွာပါက သတ်မှတ်ထားသော Price အသစ်ဖြင့် အားလုံးကို အစားထိုးမည်ဟု Warning ပြသည်။
5. နောက်ပိုင်း ဈေးပြောင်းလိုပါက Group Card မှ Retail / Wholesale Price ပြင်ပြီး Update လုပ်ပါ။ လက်လီ / လက်ကားဈေး အမှန်တကယ်ပြောင်းမှသာ Price Version တိုးပြီး ချိတ်ထားသော Branch Product များသို့ Mirror Update လုပ်မည်။ Group Name သာပြောင်းလျှင် Price Version မတိုးပါ။
6. Product တစ်ခုကို Unlink လုပ်ပါက လက်ရှိဈေးနှုန်းကို Standalone Price အဖြစ် ထိန်းထားမည်။ Group ထဲတွင် Branch ၂ ခုထက်နည်းသွားပါက ကျန် Member များအားလုံးကို Unlink လုပ်ပြီး Group ကို Archive လုပ်မည်။

## Migration / Compatibility

- Zustand persisted-state version ကို 20 သို့ တိုးထားသည်။ v3.2.0 version 19 Data မှ `priceGroups: []` အဖြစ် additive migration ဖြစ်သည်။
- လက်ရှိ Product များကို အလိုအလျောက် Group မချိတ်ပါ။ မူလဈေး၊ Product ID၊ Branch ID၊ Stock၊ Cost၊ Batch နှင့် History မပြောင်းပါ။
- JSON Backup schemaVersion ကို 20 သို့ တိုးပြီး `priceGroups` ထည့်ထားသည်။ Old backup တွင် `priceGroups` မရှိပါက Empty Group List ဖြင့် Restore လုပ်မည်။
- Rollout မလုပ်မီ Owner JSON Backup နှင့် Firestore Export ယူရန်။ Branch Product / Price / Stock Count ကို မှတ်တမ်းတင်ရန်။
- v3.2.1 Shared Pricing ကိုအသုံးပြုပြီးနောက် v3.2.0 Client ဖြင့် Price ပြောင်းလဲမှု မလုပ်ရန်။ All devices ကို release တူညီသော Version သို့ အဆင့်မြှင့်ပြီးမှ အသုံးပြုရန်။

## Firebase / Security

- Shared Price Group Master သည် Owner-only Read/Write ဖြစ်သည်။ Cashier သည် ၎င်း၏ assigned Branch Product Document မှ mirror price ကိုသာ ရရှိမည်။
- Firestore Rules တွင် Price Group Envelope / Payload Shape၊ Name၊ MMK၊ Retail / Wholesale Price၊ Version၊ Status နှင့် Owner UID ကို စစ်သည်။
- Owner Auto Sync သည် Shared Price Group ပြောင်းလဲမှုရှိလျှင် ပြောင်းလဲထားသော Product Documents နှင့် Price Group Documents အားလုံးကို Transaction တစ်ခုတည်း၏ ပထမ Bundle အဖြစ် စုစည်းသည်။ Bundle သည် 400 Documents ထက်ကျော်ပါက တစ်စိတ်တစ်ပိုင်း Sync မလုပ်ဘဲ Fail-Closed လုပ်သည်။ ဤကန့်သတ်ချက်ကို ကျော်နိုင်သည့် ကြီးမားသော Group များအတွက် Cloud Function အခြေပြု Server Operation လိုအပ်သည်။ Live Firestore Rules / real device concurrency test မပြီးမချင်း Production Guarantee အဖြစ် မယူဆရ။
- Cashier အတွက် Price Group Listener အသစ်မထည့်ထားပါ။ ထို့ကြောင့် Shared Group Master ကို Cashier က အပိုဖတ်ရန် မလိုပါ။
- Firebase Rules ကို deploy မလုပ်မီ Emulator တွင် Allow / Deny Cases စမ်းသပ်ရန်။
- သတိပြုရန်: Firestore Rules သည် variable-length `sale.items` array တစ်ခုချင်းကို loop မလုပ်နိုင်ပါ။ လက်ရှိ official Cashier Cloud Transaction က Shared Price Snapshot ကို ပြန်စစ်သော်လည်း direct custom client write အပါအဝင် server-authoritative enforcement အပြည့်အဝအတွက် နောက်ထပ် Callable Cloud Function / trusted server checkout endpoint လိုအပ်သည်။
- Checkout စတင်မီ Cart ထဲရှိ Shared Price Group / Version / လက်ရှိ Mode Price ကို စစ်ပြီး မကိုက်ပါက လက်ရှိဈေးသို့ refresh လုပ်ကာ Cashier ကို Total ပြန်စစ်ရန် တစ်ကြိမ်ရပ်သည်။
- Cashier Offline Queue ကို Cloud Transaction ပြန်ချိတ်သည့်အခါ Group / Version / Unit Price ထပ်စစ်သည်။ မကိုက်ပါက `needs-review` သို့ ရွှေ့ပြီး Product Stock ကို မလျှော့ပါ။
- Group Price Update ကို အတည်ပြုမီ သက်ရောက်မည့် Branch နှင့် Product အရေအတွက်ကို UI မှ ပြသပြီး Confirm တောင်းသည်။

## မပြီးသေးသော ကန့်သတ်ချက်များ

- ဤ Build တွင် Owner UI, Local Store Actions, Cloud Sync Data Mapping နှင့် Rules Validation ကို ထည့်ထားသော်လည်း Firebase Emulator / Live Firebase Test မပြုလုပ်ရသေးပါ။
- npm install သည် build environment တွင် timeout ဖြစ်နေသဖြင့် Full `tsc --noEmit` နှင့် `vite build` ကို မအတည်ပြုနိုင်သေးပါ။
- Stock Receipt နှင့် Branch Shipment အတည်ပြုမှုသည် Shared Pricing ချိတ်ထားပြီးသား Product ၏ ရောင်းဈေးကို မပြောင်းစေပါ။ Linked Product ကို Delete မလုပ်မီ Group မှ Unlink လုပ်ရန် လိုအပ်သည်။
- Stock Transfer သည် Product Group ကို အလိုအလျောက် မချိတ်ပါ။ Destination Branch တွင် သီးခြား Product ဖြစ်နေပြီး Owner က Shared Pricing Page မှ ကိုယ်တိုင်ချိတ်ဆက်ရမည်။
- Shared Price Group နှင့် ပြောင်းလဲထားသော Product Mirrors စုစုပေါင်း 400 Documents ကျော်ပါက Sync ကို Fail-Closed လုပ်သည်။ Data အားလုံး တစ်ပြိုင်နက် Atomic ဖြစ်နိုင်ဖို့ အဲဒီအရွယ်အစားတွင် Cloud Function အခြေပြု Server Operation သီးခြားတည်ဆောက်ရန်။
