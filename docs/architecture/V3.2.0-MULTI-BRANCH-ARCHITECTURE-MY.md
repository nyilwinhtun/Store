# Minimart POS — Multi-Branch Architecture Decision

## အတည်ပြုထားသော Business Rule

- Branch တစ်ခုချင်းစီတွင် မိမိ Product Catalog ကို သီးခြားထားမည်။
- Product တစ်ခုသည် Owner က တူညီသောပစ္စည်းဖြစ်ကြောင်း ကိုယ်တိုင်ချိတ်ဆက်မှသာ Branch များအကြား ဈေးနှုန်းမျှဝေမည်။ အလိုအလျောက် Product Merge မလုပ်ရ။
- ချိတ်ဆက်ထားသော Product များတွင် Shared Price Group တစ်ခုတည်း၏ Retail / Wholesale Price တူညီရမည်။
- Stock, Cost Price, Purchase, Stock Batch / Expiry, Cash, KPay, Expenses, Cash Shifts, Finance နှင့် daily operations များသည် Branch-specific ဖြစ်ရမည်။
- Sale Voucher ထဲရှိ historical unitPrice / cost snapshot များကို Shared Price ပြောင်းလဲမှုကြောင့် နောက်ကြောင်းပြန်မပြောင်းရ။
- Owner သည် All-Branches Overview မှ စတင်ပြီး Branch တစ်ခုချင်း Dashboard သို့ ဝင်နိုင်ရမည်။
- Cashier သည် မိမိခွင့်ပြုထားသော Branch များကိုသာ အသုံးပြုနိုင်ပြီး All-Branches Overview မမြင်ရ။

## Phase 1 အကောင်အထည်ဖော်ထားသောအရာများ (v3.2.0)

- Read-only Owner All-Branches Overview ထည့်ထားသည်။
- Active Branch ၂ ဆိုင်နှင့်အထက်ရှိသည့် Owner သည် state hydration ပြီးနောက် Overview သို့ စတင်ဝင်ရောက်သည်။ Single-Branch မှာ မူလ Dashboard ဆက်သုံးသည်။
- Branch summary တစ်ခုချင်းတွင် ယနေ့ Completed Sales, Product Count, Expired Batch ကို နုတ်ထားသော Low Stock Count, Open Shift Count နှင့် Pending Expense Approval Count ပြသည်။
- Recent completed sales ကို Active Branch များအကြား Branch Name နှင့် ပြသည်။
- Header Selector တွင် `ဆိုင်အားလုံး` Option ထည့်ထားသည်။ Branch ရွေးလျှင် သက်ဆိုင်ရာ Branch Dashboard သို့ ဝင်သည်။
- Branch Management ထဲတွင် Branch တစ်ခုချင်း `ဖွင့်ရန်` Action ထည့်ထားသည်။
- Non-empty Cart ကို branch switching လုပ်စဉ် အတည်ပြုချက်မရှိဘဲ မဖျက်ရ။ Sale save / persistence / receipt completion အတွင်း Branch မပြောင်းနိုင်ရ။
- All-Branches Overview သို့ ဝင်ရုံဖြင့် မူလ Active Branch Cart မပျောက်စေရ။ Overview တွင် လက်ရှိ Cart သည် ဘယ် Branch အတွက်ဖြစ်ကြောင်း ပြသည်။
- PWA cache identifier ကို v3.2.0 သို့ တိုးထားသည်။

## Phase 2 အတွက် Shared Pricing Design (v3.2.1 — မပါသေး)

အကြံပြု Data Model:

```ts
type SharedPriceGroup = {
  id: string;
  name: string;
  retailPrice: number;
  wholesalePrice: number;
  currency: 'MMK';
  memberProducts: Array<{ branchId: string; productId: string }>;
  version: number;
  updatedAt: string;
  updatedByUid: string;
};
```

Branch Product ထဲတွင် backward-compatible fields ထည့်ရန်:

```ts
priceGroupId?: string;
priceVersion?: number;
```

- Existing Product IDs / Branch IDs ကို မပြောင်းရ။
- Initial migration တွင် Product တစ်ခုချင်းကို သီးခြား Price Group တစ်ခုစီ ဖန်တီးရမည်။
- အမည်တူ၊ SKU တူ၊ Barcode တူသော်လည်း အလိုအလျောက် မချိတ်ရ။ Owner ရဲ့ explicit match လိုအပ်သည်။
- Shared Price Group ချိတ်ပြီးမှသာ Retail / Wholesale Price ကို ထို group မှ ထိန်းရမည်။
- Branch Product Document ထဲတွင် POS အတွက် mirror price နှင့် priceVersion ထားနိုင်သည်။ Owner Price Editor မှသာ group update လုပ်ပြီး version ဖြင့် consistency စစ်ရမည်။
- Branch-level Cost Price ကို မည်သည့်အခါမျှ Shared Price Group ထဲ မထည့်ရ။
- Stock, purchase, batch, cash, KPay, expense, shift, finance နှင့် sales history ကို migration က မပြောင်းရ။
- Shared Price Group နဲ့ အဖွဲ့ဝင် Product များကို atomic update လုပ်ပြီး partial success မဖြစ်စေရ။ Product count အလွန်များလျှင် staged migration + pending version gate ကို သုံးရမည်။

## Data Migration Gate

1. Firestore backup/export နှင့် POS JSON backup ပြုလုပ်ရန်။
2. Pending offline sales အားလုံးကို reconcile လုပ်ရန်။
3. Branch/Product/Sale/Batch/Transfer counts နှင့် checksum/report ထုတ်ရန်။
4. Price Group ကို additive migration အဖြစ် ဖန်တီးရန်။
5. Product-to-group link များကို owner-confirmed mapping ဖြင့်သာ လုပ်ရန်။
6. Old clients က shared price ကို အဟောင်းအတိုင်း update မလုပ်နိုင်စေရန် version gate / release coordination ထည့်ရန်။
7. Read-back verification ပြီးမှ shared pricing feature ဖွင့်ရန်။
8. Rollback သည် Price Group link disable လုပ်ခြင်းနှင့် backup restore plan ရှိရမည်။ Historical records ကို overwrite မလုပ်ရ။

## v3.2.0 ကန့်သတ်ချက်များ

- Overview သည် လက်ရှိ local store / Owner sync မှ ရရှိထားသော records ကိုသာ ပြသသည်။ Server-side aggregate summary အသစ် မဟုတ်ပါ။
- All-Branches Overview သည် read-only ဖြစ်သည်။ Cash / KPay / Finance balances ကို အားလုံးပေါင်းထားသည့် ငွေစာရင်းအဖြစ် မပြပါ။
- Shared Price Group ကို ဒီ release တွင် မတည်ဆောက်သေးပါ။
- Firebase Listener Cost Optimization, Firestore Rules Hardening, Live multi-device tests နှင့် production build validation မပြီးသေးပါ။
