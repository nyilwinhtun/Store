# Minimart v3.0.0 — Central Inventory & Branch Receiving

## ရည်ရွယ်ချက်

Owner က ပစ္စည်းနှင့် ဈေးနှုန်းသတ်မှတ်ပြီး ဆိုင်ခွဲတစ်ခုသို့ ပစ္စည်းအမျိုးအစားများစွာကို Shipment တစ်ခုတည်းဖြင့် ပို့နိုင်ရန်၊ Branch Receiver က အမှန်တကယ်ရောက်ရှိသော အရေအတွက်ကို စစ်ဆေးမှတ်တမ်းတင်ရန်၊ Owner အတည်ပြုပြီးမှ Destination Branch Stock တိုးရန် ဖြစ်သည်။

## အသစ်ထည့်ထားသော လုပ်ဆောင်ချက်များ

1. **Multi-item Branch Shipment** — Shipment တစ်ခုတွင် ပစ္စည်း ၅၀ မျိုးအထိ ထည့်နိုင်သည်။ ပို့မည့် Source Branch နှင့် လက်ခံမည့် Destination Branch ကို ရွေးချယ်နိုင်သည်။
2. **Price and Product Snapshot** — ပို့သည့်အချိန်က Product Name, SKU, Barcode, Category, Unit, Cost, Retail, Wholesale နှင့် Low-stock threshold ကို Shipment ထဲတွင် Snapshot သိမ်းသည်။ နောက်ပိုင်း Source Product ဈေးနှုန်း ပြောင်းလဲလည်း အရင် Shipment ၏ Snapshot မပြောင်းပါ။
3. **Source Stock Deduction** — Dispatch လုပ်သည့်အခါ Source Product Stock နှင့် FEFO Batch လက်ကျန်ကို ဒေသခံ Store ထဲတွင် အရင်တွက်ချက်ပြီး၊ Owner Auto Sync မှ Cloud သို့ ပြောင်းလဲမှုများကို တင်ပို့သည်။ Dispatch ကို Request ID ဖြင့် Idempotent လုပ်ထားသည်။
4. **Assigned Stock Receiver** — Owner က Profile → ဝန်ထမ်းအကောင့် / Branch Permission မှ Cashier တစ်ဦးကို Branch တစ်ခုတည်းသတ်မှတ်ပြီး `Stock Receiver ခွင့်` ဖွင့်ပေးနိုင်သည်။ ထိုခွင့်ရှိသူသာ သတ်မှတ်ထားသော Branch ၏ Stock Shipment များကို ကြည့်ပြီး လက်ခံစာရင်းပို့နိုင်သည်။
5. **Receiving Acknowledgement** — Receiver က Received Quantity, Damaged Quantity နှင့် Note ကို ထည့်သည်။ Received quantity သည် Shipped quantity ထက် မပိုရ၊ Damaged quantity သည် Received quantity ထက် မပိုရ။ ဒီအဆင့်တွင် Destination Stock မတိုးသေးပါ။
6. **Owner Approval** — Owner က လက်ခံစာရင်းကို ပြန်စစ်ပြီး Approve လုပ်မှ Net Accepted Quantity (`received - damaged`) ကို Destination Branch Product/Stock Batch ထဲ ထည့်သည်။ Destination Branch တွင် Product မရှိသေးလျှင် Snapshot အချက်အလက်ဖြင့် Product ကို ဖန်တီးသည်။ ရှိပြီးသား Product နှင့် ကိုက်ညီပါက ထို Product ထဲ Stock တိုးသည်။
7. **Cancel Before Receipt** — Receiver မလက်ခံမီသာ Owner က အကြောင်းပြချက်ထည့်ပြီး Shipment ကို Cancel လုပ်နိုင်သည်။ Source Stock နှင့် မူလ Batch Allocation များ ပြန်တိုးသည်။ လက်ခံပြီးနောက် Cancel မလုပ်နိုင်ပါ။
8. **History and Audit** — Dispatch, Receive, Approve, Cancel အခြေအနေများနှင့် Actor/Date/Note များကို Shipment Record နှင့် Local Activity Log တွင် မှတ်တမ်းတင်သည်။
9. **Backup/Restore** — `stockShipments` ကို JSON Backup နှင့် Restore ထဲ ထည့်ထားသည်။
10. **Cashier Cart clarity** — Cart အပြင် ခဏဖယ်ထားသော ပစ္စည်းစာရင်းကို `ခဏဖယ်ထားသောပစ္စည်း (Cart ထဲမပါသေး)` ဟု ရှင်းလင်းစွာ ခွဲပြထားသည်။

## Permission အကျဉ်း

- **Owner:** Shipment ဖန်တီး/ပို့၊ Cancel၊ လက်ခံမှုစစ်ဆေး/Approve၊ Product/Price/Stock စီမံနိုင်သည်။
- **Limited Cashier:** မိမိတာဝန်ပေးထားသော Branch တွင် POS နှင့် မိမိ Sales History ကိုသာ အသုံးပြုနိုင်သည်။ Product အသစ်ဖန်တီးခြင်း၊ ဈေးနှုန်းပြင်ခြင်း၊ Stock တိုက်ရိုက်ပြင်ခြင်း မရပါ။
- **Assigned Stock Receiver:** Limited Cashier အခွင့်အရေးများအပြင် Owner က `canReceiveStock: true` ဖွင့်ပေးထားမှသာ သတ်မှတ် Branch ၏ Shipment ကို လက်ခံအတည်ပြုနိုင်သည်။ Receiver က Product/Stock ကို တိုက်ရိုက်မပြင်နိုင်ပါ။

## အသုံးပြုရန် Workflow

1. Owner က Source Branch တွင် Product, Barcode, Cost/Retail/Wholesale Price နှင့် Stock ကို စီမံထားသည်။
2. Owner → `ကုန်ပို့ / လက်ခံစီမံ` မှ Destination Branch ရွေးပြီး Item များ၊ Qty များထည့်ကာ Dispatch လုပ်သည်။ Source Stock လျှော့သွားမည်။
3. Destination Branch ၏ Assigned Receiver က `ရောက်လာသောကုန် စစ်ဆေးရန်` ကိုဖွင့်၊ အမှန်တကယ်ရောက်သည့် Qty နှင့် Damaged Qty ကို မှတ်တမ်းတင်ပြီး Confirm လုပ်သည်။
4. Owner ရဲ့ Device တွင် Shipment Status `လက်ခံပြီး · Owner Approval စောင့်နေ` ဖြစ်လာသည်။ Owner က စစ်ဆေးပြီး Approve လုပ်သည်။
5. Approve ပြီးမှ Destination Branch Stock ထဲ Net Accepted Qty ဝင်သည်။ Cashier က POS မှာ Scan လုပ်ရောင်းနိုင်သည်။

## Firebase / Rules

- Project: `minimart-production`
- Business Document ID: `store-mini-main`
- Owner UID သည် `firestore.rules` ထဲတွင် လက်ရှိ Project အတွက် သတ်မှတ်ထားသော UID အတိုင်းဖြစ်ရမည်။ မပြောင်းပါနှင့်။
- ဒီ Version တွင် Receiver အတွက် `stockShipments` Read နှင့် Receipt Acknowledgement Update ခွင့်ကို Rules ထဲ ထည့်ထားသည်။
- Owner က Team Access မှ `Stock Receiver ခွင့်` ကိုဖွင့်ပြီးနောက် Receiver သည် Sign Out / Sign In ပြန်လုပ်ရန်လိုနိုင်သည်။
- ZIP ထဲမှ `firestore.rules` ကို လက်ရှိ Rules နှင့် နှိုင်းယှဉ်ပြီး Backup ယူကာမှ Publish လုပ်ပါ။ Owner UID/Business ID မကိုက်လျှင် Rules ကို မတင်ပါနှင့်။

## Data Safety / အရေးကြီးကန့်သတ်ချက်

- Product, Sales, Stock Transfer, Cashier Cloud Sales နှင့် Firebase Project Config အဟောင်းများကို မလိုအပ်ဘဲ မပြောင်းထားပါ။
- Dispatch/Approval Local Store ပြောင်းလဲမှုများကို Owner Auto Sync က Cloud သို့ ပို့သည်။ Sync အောင်မြင်ကြောင်း မမြင်မချင်း Cloud ပေါ်ရောက်ပြီးပြီဟု မယူဆပါနှင့်။
- Firestore Sync transaction သည် ပြောင်းလဲသော Record များကို ၄၀၀ စီ chunk ခွဲပို့သည်။ Shipment တစ်ခုတည်း၏ Record များသည် ပုံမှန်အရွယ်အစားတွင် တစ် chunk အတွင်း ရှိနိုင်သော်လည်း အလွန်ကြီးသော bulk change များတွင် chunk များကွဲနိုင်သည်။
- Firestore Rules သည် Receiver ကို `stockShipments` အပြင် Product/Stock write မပေးပါ။ Receipt quantity validation ကို UI/Store နှင့် Owner Approval တွင် ထပ်စစ်သည်။ Server-side Cloud Function မပါသေးသောကြောင့် Production မတင်မီ Firebase Emulator/သီးခြား Test Project ဖြင့် Rules နှင့် concurrent approval ကို စမ်းသပ်ပါ။
- Full `npm run typecheck`, `npm run build`, Firebase Live Test နှင့် Hardware Test ကို ဒီ environment တွင် မအတည်ပြုနိုင်သေးပါ။
