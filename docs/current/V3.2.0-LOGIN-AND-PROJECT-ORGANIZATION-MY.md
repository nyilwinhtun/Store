# v3.2.0 — Standalone Login & Project Organization

## အတည်ပြုထားသော Login ပုံစံ

- Website ကို ဖွင့်လိုက်ပြီး Firebase Session မရှိပါက Root (`/`) တွင် Login Page ကို ပထမဆုံးပြမည်။
- Login သည် Sidebar၊ Navigation Menu သို့မဟုတ် Dashboard ထဲတွင် မပါဝင်ပါ။
- Firebase Authentication ကို ရှိပြီးသား API (`signInWithEmailAndPassword`) ဖြင့် ဆက်သုံးသည်။
- Password Reset ကို Firebase `sendPasswordResetEmail` ဖြင့် ဆက်သုံးသည်။
- Login Screen မှ Owner Account အသစ်ဖန်တီးခြင်း (`Sign Up`) ကို ဖယ်ရှားထားသည်။ ရှိပြီးသား Owner/Cashier Account များသာ Login ဝင်နိုင်သည်။
- Owner Account ကို ခွင့်ပြုထားသော Admin/Firebase Console provisioning နည်းလမ်းဖြင့်သာ ဖန်တီး/စီမံရမည်။ Login Page မှ `createUserWithEmailAndPassword` မခေါ်ရ။
- Team Access ရှိ Owner-only Cashier provisioning ကို သီးခြားထားသည်။ ၎င်းသည် Cashier Role/Branch Permission ကိုသာ ဖန်တီးရန်ဖြစ်ပြီး Owner Sign Up မဟုတ်ပါ။
- Login အောင်မြင်ပြီးပါက AccessBootstrap က Owner/Cashier Business Access ကို အတည်ပြုပြီးမှ Workspace ကို ဖွင့်မည်။
- Sign Out လုပ်ပါက Auth State ပြောင်းလဲပြီး Root Login Screen ကို ပြန်ပြမည်။
- Firebase Auth က ယခင် Session ကို မှတ်မိနေပါက Refresh/ပြန်ဝင်ချိန် Login Form ထပ်မတောင်းဘဲ Workspace ကို ဆက်ဖွင့်နိုင်သည်။ Sign Out လုပ်ထားမှ Login Form ပြန်ပေါ်မည်။

## Security Notes

- Login Page သည် UI Gate ဖြစ်သည်။ တကယ့် Data Authorization ကို Business Access Resolution နှင့် Firestore Security Rules က ဆက်လက်ဆုံးဖြတ်ရမည်။
- Cashier သည် မိမိ Branch တစ်ခုတည်းကိုသာ ဝင်ခွင့်ရမည်။
- Login ဝင်ခြင်းတစ်ခုတည်းကြောင့် Owner Permission မရရှိစေရ။
- Login Page မှ Account Creation UI/API ကို မပေးရ။ Firestore Business Access Check က Owner UID ကို သီးခြားစစ်ဆေးရမည်။
- Firebase Config, Firebase Project, Business ID, Login API နှင့် AccessBootstrap Logic ကို မပြောင်းထားရန် ရည်ရွယ်သည်။

## Project File Organization

- `src/features/auth/` — Standalone Login Screen
- `src/components/` — လက်ရှိအသုံးပြုနေသော Page/UI Components
- `src/lib/` — Firebase, Auth Access, Cloud Sync, Barcode နှင့် shared logic
- `src/store/` — POS Zustand Store
- `src/types/` — TypeScript Data Types
- `docs/current/` — လက်ရှိ Version Docs
- `docs/testing/` — Testing & Release Gate
- `docs/releases/` — Previous Release Notes
- `docs/archive/` — Older Version Docs
- `docs/reference/` — Firebase, Stock, Sync, Branding နှင့် Hardware Notes

Documentation ဖိုင်များကို Root မှ `docs/` အောက်သို့ ရွှေ့ထားပြီး မဖျက်ထားပါ။ Vite, TypeScript, Tailwind, `index.html`, `firestore.rules`, package files တို့ကို Root မှာထားခြင်းဖြင့် Build/Deploy Path မပြောင်းစေပါ။


## Owner Account Creation Policy

Login Screen မှ Owner Account အသစ်ဖန်တီးခြင်းကို မပေးပါ။ ရှိပြီးသား Owner/Cashier Account များသာ Sign In လုပ်နိုင်သည်။ Owner Account Provisioning ကို ခွင့်ပြုထားသော Admin/Firebase Console လုပ်ငန်းစဉ်ဖြင့်သာ ဆောင်ရွက်ရမည်။ Team Access ရှိ Owner-only Cashier Provisioning သည် Cashier Role သီးသန့်ဖြစ်ပြီး Owner Sign Up မဟုတ်ပါ။ Firebase Email/Password Sign-in Provider ကို ပိတ်မထားရ၊ ပိတ်လိုက်ပါက ရှိပြီးသား Login များပါ ရပ်သွားနိုင်သည်။
