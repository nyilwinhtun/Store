## 2. Candidate က ဘာပြောင်းသည်

Deployed Rules နှင့် နှိုင်းယှဉ်လျှင် —

1. `validCashierSaleCreate` ကို ဖယ်ရှားပြီး Cashier ၏ direct Sale create လမ်းကြောင်းကို ပိတ်သည်။
2. `validCashierSaleAuditCreate` ကို ဖယ်ရှားပြီး Cashier က `SALE_CREATED` audit ကို တိုက်ရိုက် ရေးနိုင်ခွင့် မပေးတော့ပါ။
3. `linkedProductStockReduction` နှင့် `linkedBatchStockReduction` ကို ဖယ်ရှားပြီး Cashier က Product/Batch stock ကို လျှော့ချနိုင်ခွင့် မပေးတော့ပါ။
4. `branchHasConfiguredKPay` ကို ဖယ်ရှားသည် (KPay စစ်ဆေးမှုသည် server-side သို့ ရွှေ့ပြီးဖြစ်သည်)။
5. Cashier အတွက် `stockUnitRegistries`, `saleReturns` ကို အလုပ်လိုအပ်သလောက် read-only ခွင့်ပြုသည်။
6. `saleReturns` နှင့် Owner-only finance/audit collection များကို Owner update/delete မှ ချန်လှပ်ထားသည်။

မပြောင်းလဲသော အချက်များ —

- Owner access သည် `ownerUid` အပေါ် အခြေခံဆဲ။ Hard-coded Owner fallback မရှိပါ။
- Branch restrictions၊ member email/role/active-branch စစ်ဆေးမှုများ ဆက်လက်ရှိသည်။
- Cashier အတွက် လိုအပ်သော read access (products, batches, sales, registries, returns) ရှိသည်။
- Default deny `match /{document=**} { allow read, write: if false; }` ရှိသည်။
- အခြား collection များ၏ Rules ကို မလျှော့ချပါ။

## 4. Compatibility Review — အရေးကြီးသော Deployment အစီအစဉ်

လက်ရှိ Web App ၏ Cashier Sale အားလုံးသည်
`src/lib/cashierSalesSync.ts:158-164` မှ `commitCashierUnitSaleToCloud`
callable ကို ဖြတ်သည်။ ထို callable သည် Cloud Functions (Admin SDK) ဖြစ်ပြီး
Firebase **Blaze** မရှိဘဲ Production တွင် deploy/run မရပါ။ Free-only လမ်းကြောင်း
ဖြစ်သော Cloudflare Worker checkout သည် `src/lib/workerSaleClient.ts` တွင်
ရှိသော်လည်း **default disabled** ဖြစ်သည်။

ထို့ကြောင့် —

- Candidate Rules ကို deploy လုပ်ရုံဖြင့် လက်ရှိ app ကို ချက်ချင်း မချိုးပါ
  (app သည် direct writes မလုပ်တော့ပါ)။
- သို့သော် Rules deployment သည် **legacy emergency path ကို ဖျက်လိုက်ခြင်း**
  ဖြစ်သည်။ Trusted path (Worker သို့မဟုတ် Functions) မရှိသော ပတ်ဝန်းကျင်တွင်
  Cashier Sale များ cloud သို့ ရောက်နိုင်တော့မည် မဟုတ်ပါ။
- နိဂုံး — **Staging Worker စမ်းသပ်မှု အောင်မြင်၍ checkout integration
  ဖွင့်ပြီးမှသာ** ဤ Candidate ကို Production သို့ တင်ရမည်။ ထိုအစီအစဉ်ကို
  ဖောက်လုပ်လျှင် Cashier များ၏ Sale များ pending queue တွင် ရပ်နေနိုင်သည်။
- Owner-only လုပ်ငန်းများ (product/member/branch/expense review) သည်
  Candidate အောက်တွင် ပုံမှန် ဆက်လုပ်နိုင်သည်။
