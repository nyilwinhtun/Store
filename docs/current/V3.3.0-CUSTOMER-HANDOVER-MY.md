## 3. အကောင့်နှင့် လုပ်ပိုင်ခွင့် သဘောတူညီချက်

- Owner ကို `businesses/store-mini-main` Document ၏ `ownerUid` ဖြင့် သတ်မှတ်သည်။
  Owner UID ကို မည်သည့်အခါမျှ Cashier UID ဖြင့် အစားမထိုးရပါ။
- Cashier အကောင့်များကို App ထဲတွင် အသစ်ဖန်တီး၍ မရပါ။ Firebase Console မှ
  အကောင့်ဖန်တီးပြီး Owner က **ဆိုင် / Owner Profile → ဝန်ထမ်းအကောင့် /
  Branch Permission** တွင် Firebase UID ဖြင့် ချိတ်ဆက်ရပါသည်။
- Cashier တစ်ဦးလျှင် ဆိုင်ခွဲ **တစ်ခုတည်း** သတ်မှတ်ရပါသည်။
- Cashier သည် မိမိ UID ဖြင့် မှတ်တမ်းတင်ထားသော အရောင်းများ၊ ကိုယ်ပိုင်
  အသုံးစရိတ်နှင့် ငွေရှင်းမှတ်တမ်းများကိုသာ မြင်ရပါသည်။
- ပိတ်ထားသော (disabled) အကောင့်သည် Login ဝင်နိုင်မည် မဟုတ်ပါ။
- Admin PIN သည် ဤ Device ၏ Local UI Guard သာဖြစ်ပြီး Server-side
  Permission မဟုတ်ပါ။ စတင်အသုံးပြုသည်နှင့် Default `1234` ကို ပြောင်းပါ။

## 4. Data နှင့် လုံခြုံရေး သတိပေးချက်များ

- Demo/seed data ကို Production သို့ မတင်ရပါ။ `npm run seed:emulator` သည်
  Local emulator (`demo-minimart-staging`) အတွက်သာ ဖြစ်သည်။
- Production သို့ ဖောက်သည်အချက်အလက် မှန်ကန်စွာ ထည့်ပြီးနောက် စမ်းသပ်ရန်
  အတုအယောင် Sale များ မဖန်တီးရပါ။ စမ်းသပ်မှုကို Emulator သို့မဟုတ်
  သီးခြား Staging ပရောဂျက်တွင်သာ ပြုလုပ်ပါ။
- Browser Site Data / Local Storage / IndexedDB ကို မရှင်းပါနှင့်။ ရှင်းလိုက်လျှင်
  ထို Device ၏ Local စာရင်းများ ပျောက်နိုင်ပါသည်။
- နေ့စဉ် **Settings → Export JSON Backup** ကို ပြုလုပ်ပြီး Device အပြင်
  လုံခြုံသောနေရာတွင် သိမ်းပါ။ App Backup သည် Device တစ်ခုအတွက် ဖြစ်ပြီး
  Cloud recovery backup ကို အစားထိုးနိုင်သည့် အရာ မဟုတ်ပါ။
- Password, KPay PIN/OTP, Firebase Service Account Key များကို မည်သူ့ကိုမျှ
  မပေးပါနှင့်။ Support လုပ်ရန် လိုအပ်ပါက Screenshot တင်ရာတွင် ငွေပမာဏနှင့်
  ဖုန်းနံပါတ်များကို ဖုံးပါ။
- Real KPay ငွေလွှဲစမ်းသပ်မှုကို Owner ခွင့်ပြုချက်ဖြင့် သေးငယ်သော
  ပမာဏဖြင့်သာ ပြုလုပ်ပါ။ App သည် KPay Transaction ID ကို လူကိုယ်တိုင်
  စစ်ဆေးသည့် စနစ်ဖြစ်ပြီး ငွေလွှဲကို အလိုအလျောက် အတည်ပြုသည် မဟုတ်ပါ။
