လက်ရှိ v3.1.4 ကို မူရင်းအတိုင်း ထိန်းသိမ်းထားပြီး v3.2.0 အတွက် သီးခြား working copy ကို ပြင်ဆင်ထားသည်။ မူရင်း Source ကို မပြင်ထားပါ။ Firebase Authentication, API Config, Login flow, Production Firestore data ကို မထိထားပါ။

**ဒီ Audit ပြီးချိန်အထိ Application source code ကို မပြင်ရသေးပါ။** အကြောင်းမှာ Unit Barcode, POS sale, Cashier Cloud transaction, Firestore Rules တို့ကို တစ်စုတစ်စည်းတည်း စမ်းသပ်ပြီးမှသာ ပြောင်းလဲသင့်သောအတွက် ဖြစ်သည်။

## 2. လက်ရှိ Source မှ အတည်ပြုတွေ့ရှိသော Release Blockers

### P0-A — Unit Barcode သည် End-to-End အလုပ်မလုပ်သေး

1. `src/components/StockUnitRegistrationPage.tsx` ရှိသော်လည်း `src/App.tsx` တွင် import / Page route / menu entry မတွေ့ရ။ ထို့ကြောင့် အဓိက UI မှ ဝင်အသုံးပြုလို့မရသေး။
2. POS scan handler (`src/App.tsx`) က `product.barcode` သို့မဟုတ် `product.sku` ကိုသာ ရှာသည်။ `stockUnitRegistries` ထဲက individual sticker barcode ကို မရှာသေး။
3. Checkout / `addSale` လမ်းကြောင်းက Product quantity ကို လျှော့သော်လည်း သက်ဆိုင်ရာ physical unit ကို `sold` ပြောင်းတဲ့ flow မတွေ့ရ။
4. Unit Registration page မှာ App-generated barcode mode ရှိနေသေးသည်။ ဆိုင်က ဝယ်ထားသော unique sticker များကိုသာ အသုံးပြုမည့် ဆုံးဖြတ်ချက်နှင့် မကိုက်ညီ။
5. Registration function က Product Stock ရှိပြီးသားမှသာ Unit barcode ထည့်နိုင်သည်။ Registration က Product Stock ကို တိုးမပေးသလို Stock Receiving နှင့်လည်း မချိတ်ဆက်ထား။
6. Firestore Rules မှာ Cashier အတွက် ဖတ်ခွင့်ပေးထားတဲ့ collection များထဲ `stockUnitRegistries` မပါ။ ထို့အပြင် Cashier create/update allow rule တွေမှာလည်း Unit Registry update path မပါ။ ဒါကြောင့် Cashier က Cloud မှ unit list ဖတ်ခြင်း/ရောင်းပြီး status ပြောင်းခြင်း မလုပ်နိုင်သေး။
7. Unit တွေကို 250 ခုစီ registry document တစ်ခုအတွင်း array အဖြစ်သိမ်းထားသည်။ တစ်ချိန်တည်းမှာ Cashier များက တူညီသော registry ကို ပြင်ဆင်ပါက concurrency / lost-update အန္တရာယ်ကို စမ်းသပ်ရမည်။

**Release Gate:** Barcode Sticker တစ်ခုချင်းကို Stock Receiving မှ မှတ်ပုံတင်နိုင်ခြင်း၊ POS က အဲဒီ Sticker နဲ့ပဲ ရောင်းနိုင်ခြင်း၊ ရောင်းပြီးသားကို ထပ်မရောင်းနိုင်ခြင်း၊ Cloud/Offline/Branch Transfer မှန်ကန်ခြင်းတို့ အားလုံးကို စမ်းသပ်ပြီးမှသာ Unit Barcode ကို ဆိုင်သုံးအတွက် အဆင်သင့်ဟု သတ်မှတ်ရန်။

### P0-B — Owner Dashboard ရဲ့ All Branches အမြင် မပြည့်စုံသေး

- Main `App.tsx` Dashboard data (`products`, `sales`, `expenses`) သည် `activeBranchId` အလိုက် filter လုပ်ထားသည်။
- `AnalyticsPage.tsx` တွင် All Branches နှင့် Branch တစ်ခုချင်းစီ Filter ရှိသည်။
- ထို့ကြောင့် Owner ရဲ့ Analytics မှာ စုစုပေါင်းကြည့်နိုင်ပေမယ့် Main Dashboard ကို All Branches mode ဖြင့် မပြသေး။

**ပြင်ဆင်ရန်:** Main Dashboard မှာ All Branches / Branch 1 / Branch 2 selector (သို့) အပေါ်ပိုင်း consolidated summary ထည့်ရန်။ ဒီ UI filter သာမက underlying query/data scope ကိုလည်း မှန်ကန်စေရန်။

### P0-C — Branch Transfer ရဲ့ Exception Mode မပြောင်းရသေး

- လက်ရှိ `BranchShipmentManagementPage.tsx` မှာ Status သည် `dispatched` → `received` → `approved` ဖြစ်သည်။
- `received` ဖြစ်သော်လည်း Owner Approval မလုပ်မချင်း Destination Stock မဝင်သေး။
- အသစ်အတည်ပြုထားသော လိုအပ်ချက်မှာ ပစ္စည်း/အရေအတွက် အပြည့်ကိုက်ညီပါက Auto Complete၊ ကွာခြားချက်/ပျက်စီးမှုရှိမှ Owner Review ဖြစ်သည်။

**အကြံပြုချက်:** လက်ရှိအလုပ်လုပ်နေသော Shipment ကို မဖျက်ဘဲ Feature Flag / Preview branch တစ်ခုတွင် Exception workflow ကို အရင်စမ်းသပ်ရန်။ Production flow ကို စမ်းသပ်အတည်မပြုဘဲ အစားမထိုးရန်။

## 3. P1 — သေချာပြင်ဆင်သင့်သော Data Reliability အချက်များ

### Cashier Sync Query 100-record issue

`src/components/CashierAutoSync.tsx` တွင် own expenses, settlements, sales query သုံးခုလုံး `where(...)` + `limit(100)` သာရှိပြီး Date `orderBy` မပါ။ ရလဒ် 100 ခုကို Client မှ sort လုပ်သော်လည်း Query က ရွေးချယ်ပြီးသား 100 ခုအတွင်းသာ sort လုပ်နိုင်သည်။ ရှေးဟောင်း/မတော်တဆရွေးထားသော 100 records ကြောင့် နောက်ဆုံး Sales မပါနိုင်သည့်အန္တရာယ်ရှိသည်။ Date-based ordering + index + pagination / listener design ကို စမ်းသပ်ပြီး ပြင်ရန်။

### Local Store / Session separation

`src/store/usePosStore.ts` သည် Zustand Persist ဖြင့် `minimart-pos-data-v1` တစ်ခုတည်းသော `localStorage` key ထဲတွင် Branch များ၊ Products၊ Sales၊ Expenses၊ Unit Registries အပါအဝင် POS data အားလုံးကို သိမ်းသည်။ Authentication ပြောင်းလဲချိန် Access state ကို reset လုပ်သော်လည်း persisted POS data ကို UID/session အလိုက် partition လုပ်ထားခြင်း မတွေ့ရ။ Shared device မှာ Owner → Cashier account ပြောင်းသုံးမည်ဆိုပါက local data isolation ကို စမ်းသပ်ပြီး harden လုပ်ရန်။ လက်ရှိ Local Data ကို အလျင်စလို clear မလုပ်ရ။

### Products are Branch-scoped today

`products` records များကို `branchId` အလိုက် filter လုပ်ထားသည်။ Business-wide shared Product Master ပုံစံကို လက်ရှိ Database မှာ မတွေ့ရ။ Deadline နီးနေသောကြောင့် Product IDs / stock migration ကြီးကို Release မတိုင်မီ မလုပ်ဘဲ existing Branch-scoped structure ကို ထိန်းထားရန်။ Shared Product Master ကို သီးခြား Migration Project အဖြစ်သာ ပြင်ဆင်ရန်။
