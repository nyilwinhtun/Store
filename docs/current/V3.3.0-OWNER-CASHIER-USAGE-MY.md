# V3.3.0 Owner နှင့် Cashier အသုံးပြုလမ်းညွှန်

> ဒီလမ်းညွှန်ကို Training နှင့် လက်တွေ့စမ်းသပ်မှုအတွက် အသုံးပြုပါ။
> Production တွင် အသုံးမပြုမီ **Customer Handover Pack** ၏ Blocker များကို
> Owner က အတည်ပြုပြီးဖြစ်ရပါမည်။ ဒီလမ်းညွှန်ထဲက မည်သည့်အချက်မျှ
> Deployment ခွင့်ပြုချက် မဟုတ်ပါ။

## 1. App ဖွင့်ခြင်းနှင့် Login

1. Owner ပေးထားသော URL ကို Chrome (Android) သို့မဟုတ် Safari (iPhone)
   တွင် ဖွင့်ပါ။
2. ဖုန်း/Tablet တွင် နေ့စဉ်အသုံးပြုမည်ဆိုလျှင် **Add to Home Screen** လုပ်ပါ။
   Home Screen မှ ဖွင့်ခြင်းက Browser Tab အသစ်များထက် Local Data ကို ပိုမို
   တည်ငြိမ်စွာ ထိန်းထားနိုင်ပါသည်။
3. Email နှင့် Password ဖြင့် Login ဝင်ပါ။
   - Owner သည် ဆိုင်အားလုံးနှင့် စီမံခန့်ခွဲမှု စာမျက်နှာများကို မြင်ရပါသည်။
   - Cashier သည် သတ်မှတ်ထားသော ဆိုင်ခွဲတစ်ခုတည်းအတွက် ခွင့်ပြုထားသော
     စာမျက်နှာများကိုသာ မြင်ရပါသည်။
4. Login မဝင်နိုင်လျှင် Password ကို ထပ်မံမကြိုးစားမီ Owner ထံ ဆက်သွယ်ပါ။
   ပိတ်ထားသော အကောင့်နှင့် ဆိုင်ခွဲမသတ်မှတ်ရသေးသော အကောင့်များကို
   စနစ်က ဝင်ခွင့်မပြုပါ။

**အရေးကြီး —** Browser ၏ Site Settings ထဲမှ Local Storage / Cookies /
Site Data ကို မရှင်းပါနှင့်။ ရှင်းလိုက်လျှင် ထို Device ရှိ စာရင်းများ
ပျောက်နိုင်ပါသည်။ App ကို Update လုပ်ရန် Page ကို Refresh လုပ်ရုံဖြင့် ရပါသည်။
စက်ဝိုင်းတွင် Update ခလုတ် ပေါ်လာလျှင် နှိပ်ပါ။

## 2. Owner — ပထမဆုံးအကြိမ် ပြင်ဆင်ခြင်း

### 2.1 Settings

**Settings → Store Preferences**

- ဆိုင်အမည်၊ ငွေကြေး `MMK` နှင့် Receipt အောက်ခြေစာသားကို စစ်ပါ။
- **Admin PIN** ကို Default `1234` မှ ကိုယ်ပိုင် PIN သို့ ပြောင်းပါ။
  PIN သည် ဤ Device ၏ Local UI Guard သာဖြစ်ပြီး Server-side လုံခြုံရေး
  မဟုတ်ပါ။ PIN ကို ဝန်ထမ်းများအား မမျှဝေပါနှင့်။
- Receipt Paper Width (58 mm / 80 mm) ရွေးပြီး **Test Print** ဖြင့်
  စက်နှင့် စက္ကူအကျယ် ကိုက်ညီမှုကို စမ်းပါ။

### 2.2 ဆိုင်ခွဲနှင့် Category

**ဆိုင်ခွဲ / Category**

- ဆိုင်ခွဲအသစ် ဖန်တီးပါ။ ဆိုင်ခွဲတစ်ခုစီတွင် သီးခြား Product, Stock,
  Sales နှင့် Finance ရှိပါသည်။
- Category အမည်များ ထပ်မနေစေရန် စစ်ပါ။
- ဆိုင်ခွဲများကို Archive လုပ်ခြင်းသည် သမိုင်းစာရင်းများကို ဖျက်ခြင်း
  မဟုတ်ပါ။ လက်ရှိအသုံးပြုနေသော ဆိုင်ခွဲကို မတော်တဆ မ Archive ပါနှင့်။

### 2.3 ပစ္စည်းများ

**ပစ္စည်းစာရင်း → ပစ္စည်းအသစ်**

- အမည်၊ SKU၊ Barcode၊ Category၊ Cost / Retail / Wholesale Price နှင့်
  လက်ကျန် Stock ကို ထည့်ပါ။
- Barcode တစ်ခုတည်းကို Product နှစ်ခုတွင် မထည့်ပါနှင့်။ စနစ်က
  ထပ်နေသော Barcode ကို ငြင်းပယ်ပါသည်။
- ယူနစ်အလိုက် အရေအတွက် (ခု/ထုပ်/ပုလင်း/ကီလို) နှင့် အလုံးပဲ/ဒသမ
  ရောင်းမည်ကို မှန်ကန်စွာ ရွေးပါ။
- Stock ကို လက်တွေ့ရေတွက်ပြီးမှ ထည့်ပါ။ စမ်းသပ်ရန် အတု Stock များကို
  Production တွင် မထည့်ပါနှင့်။
- Stock ပြင်ဆင်ရန် **Stock ±** ကို အသုံးပြုပါ။ ပြင်ဆင်မှုတိုင်း Activity Log
  တွင် မှတ်တမ်းတင်ပါသည်။

### 2.4 KPay လက်ခံမှု

**Cash & KPay စာရင်း**

- ဆိုင်ခွဲအလိုက် KPay လက်ခံမှုကို ဖွင့်/ပိတ်ပါ။
- KPay Account အမည်၊ နံပါတ် နှင့် QR ပုံကို ထည့်ပါ။
- KPay Sale တစ်ခုစီတွင် အသုံးပြုခဲ့သော Account အချက်အလက်ကို Snapshot
  အဖြစ် သိမ်းထားပါသည်။ နောက်ပိုင်း Account ပြောင်းလဲသော်လည်း သမိုင်း
  Receipt များသည် မူလ Account ကို ဆက်လက်ပြပါမည်။
- KPay ပိတ်ထားလျှင် POS တွင် KPay ရွေးမရပါ။ လက်ရှိ KPay ရွေးထားမှုရှိနေလျှင်
  Cash သို့ အလိုအလျောက် ပြောင်းပါသည်။

### 2.5 ဝန်ထမ်းအကောင့်များ

**ဆိုင် / Owner Profile → ဝန်ထမ်းအကောင့် / Branch Permission**

1. Firebase Console တွင် Cashier ၏ Email/Password အကောင့်ကို အရင်ဖန်တီးပါ။
   App ထဲတွင် အကောင့်အသစ် ဖန်တီး၍ မရပါ။
2. Firebase Authentication UID ကို Copy လုပ်ပါ။
3. ဝန်ထမ်းအမည်၊ Email၊ UID နှင့် တာဝန်ယူမည့် ဆိုင်ခွဲ **တစ်ခုတည်း** ကို
   ထည့်ပြီး ချိတ်ဆက်ပါ။
4. လိုအပ်လျှင် **ရောက်လာသောကုန် စစ်ဆေးရန်** ခွင့်ကို သီးခြား ဖွင့်ပါ။
5. ဝန်ထမ်းထွက်ခွာလျှင် အကောင့်ကို Disable လုပ်ပါ။ ဖျက်ပစ်ရန် မလိုပါ။
6. Owner UID နေရာတွင် Cashier UID ကို မည်သည့်အခါမျှ မထည့်ပါနှင့်။

### 2.6 Backup နှင့် Restore

**Settings → Backup & Restore**

- နေ့စဉ် **Export JSON** လုပ်ပြီး Device အပြင်ရှိ လုံခြုံသောနေရာတွင်
  သိမ်းပါ။ ဖိုင်တွင် ပစ္စည်း၊ အရောင်း၊ Customer Credit၊ ငွေပေးချေမှု၊
  Supplier၊ Purchase၊ Expiry Batch၊ Expense နှင့် Cash Shift များ ပါဝင်ပါသည်။
- **Import / Restore** သည် လက်ရှိ Local Data ကို အစားထိုးပါသည်။
  မလုပ်မီ လက်ရှိ Data ကို အရင် Export လုပ်ပါ။
- JSON Backup သည် ဤ Device အတွက်သာ ဖြစ်ပြီး Production Cloud recovery
  backup ကို အစားထိုးနိုင်သည့် အရာ မဟုတ်ပါ။
- **Reset Local Data** သည် ဤ Device ရှိ Data ကို အပြီးဖျက်ပါသည်။
  Backup မရှိလျှင် ပြန်မရနိုင်ပါ။ ဖောက်သည်ကို မိမိသဘောဖြင့် မနှိပ်ခိုင်းပါနှင့်။

## 3. Owner — နေ့စဉ် စီမံခန့်ခွဲမှု

### 3.1 Dashboard နှင့် ဆိုင်အားလုံး

- **ဆိုင်အားလုံး** — ဆိုင်ခွဲ ၂ ခုအထက်ရှိလျှင် ဆိုင်အားလုံး၏ အရောင်း၊
  Stock နှင့် ငွေကြေးအခြေအနေကို ပေါင်းစပ်ကြည့်ရှုနိုင်ပါသည်။
- **ဤဆိုင် Dashboard** — လက်ရှိဆိုင်ခွဲ၏ ယနေ့အရောင်း၊ Open Shift၊
  Low Stock နှင့် လုပ်ဆောင်ရန် အချက်များကို ကြည့်ပါ။
- ဆိုင်ခွဲပြောင်းလျှင် Cart ရှိနေပါက ရှင်းလင်းမည်ဟု သတိပေးပါသည်။
  Checkout လုပ်နေဆဲဖြစ်လျှင် ဆိုင်မပြောင်းပါနှင့်။

### 3.2 အရောင်းမှတ်တမ်းနှင့် Void

- **အရောင်းမှတ်တမ်း** တွင် Voucher ရှာခြင်း၊ Receipt ပြန်ထုတ်ခြင်း၊
  Copy လုပ်ခြင်းနှင့် CSV ထုတ်ခြင်း ပြုလုပ်နိုင်ပါသည်။
- Void ခလုတ်သည် Owner အတွက်သာ ဖြစ်ပြီး Cash Sale သို့မဟုတ်
  Credit ငွေမရသေးသော Sale များအတွက်သာ ပေါ်ပါသည်။
  Credit ငွေတစ်စိတ်တစ်ပိုင်း ရပြီးသော Sale ကို Void မလုပ်ပါနှင့်။
- Void ပြုလုပ်လျှင် အကြောင်းရင်း အနည်းဆုံး ၃ လုံး ထည့်ပါ။ Void သည်
  ငွေပြန်အမ်းခြင်း မဟုတ်ပါ။ လိုအပ်လျှင် ငွေပြန်အမ်းမှုကို သီးခြား မှတ်တမ်းတင်ပါ။
- Void ပြီးနောက် Product Stock နှင့် Stock Batch နှစ်ခုစလုံး ပြန်ပေါင်းပါသည်။
  Void ပြီးလျှင် Stock ကို ပစ္စည်းစာရင်းတွင် ပြန်စစ်ပါ။

### 3.3 Customer Credit နှင့် Statement

- **Customer / အကြွေး** တွင် Customer အသစ်ထည့်ခြင်း၊ Credit Sale ၏
  လက်ကျန်ကြည့်ခြင်းနှင့် ငွေလက်ခံခြင်း ပြုလုပ်ပါ။
- ငွေလက်ခံပြီးတိုင်း Receipt/Reference ကို မှတ်တမ်းတင်ပါ။
- **Statement** ဖြင့် Customer တစ်ဦး၏ ဆိုင်ခွဲအလိုက် Invoice၊ ငွေပေးချေမှု
  နှင့် လက်ကျန်ကို ကြည့်နိုင်ပါသည်။ 58 mm / 80 mm ဖြင့် Print သို့မဟုတ်
  Copy/Share လုပ်နိုင်ပါသည်။ Void လုပ်ထားသော Invoice များကို
  လက်ကျန်တွင် မထည့်ပါ။
- Cashier သည် မိမိဆိုင်ခွဲ၏ Customer လက်ကျန်ကိုသာ မြင်ရပါသည်။

### 3.4 Stock လုပ်ငန်းစဉ်များ

- **ကုန်ဝင်စာရင်း** — Supplier ထံမှ ကုန်လက်ခံပြီး Batch၊ သက်တမ်းနှင့်
  ကုန်ကျစရိတ်ဖြင့် Stock တင်ပါ။
- **ကုန်ပို့ / လက်ခံစီမံ** — ဆိုင်ခွဲအချင်းချင်း ကုန်ပို့ခြင်း၊ လက်ခံခြင်း၊
  ကွာဟမှုစစ်ဆေးခြင်းနှင့် Owner Approve လုပ်ခြင်း။ ကွာဟမှုရှိလျှင်
  လက်ခံရရှိသည့် အရေအတွက်ကိုသာ Stock ထဲ ထည့်ပါသည်။
- **Expiry Tracking** — သက်တမ်းကုန်ဆုံးမည့် Batch များကို ကြိုတင်စစ်ပါ။
  သက်တမ်းကုန် Batch များကို POS တွင် ရောင်းချနိုင်မည် မဟုတ်ပါ။
- **ရောက်လာသောကုန် စစ်ဆေးရန်** — Cashier ကို ခွင့်ပြုထားလျှင်
  Cashier က လက်ခံစစ်ဆေးနိုင်ပါသည်။ ကွာဟမှုကို Owner က အတည်ပြုရပါသည်။
- Stock စာရင်းနှင့် လက်တွေ့မကိုက်ညီလျှင် အကြောင်းရင်းကို မှတ်တမ်းတင်ပြီး
  **Stock ±** ဖြင့် ပြင်ပါ။ ပြင်ဆင်မှုကို Activity Log တွင် စစ်ပါ။

### 3.5 Cash, Expense နှင့် Finance

- **Cash Register / Shift** — Shift ဖွင့်ခြင်း၊ လက်ကျန်ငွေ စစ်ဆေးခြင်း၊
  Cash-in/Cash-out နှင့် Shift ပိတ်ခြင်း။
- **အသုံးစရိတ်** — Cashier သတ်မှတ်ချက်ထက် ကျော်သော Expense များကို
  Owner Approve လုပ်ရပါသည်။
- **Cashier ငွေရှင်း** — Cashier ၏ ငွေလက်ခံ/ငွေရှင်းမှတ်တမ်းများကို
  စစ်ဆေးပါ။ ထပ်နေသော ငွေရှင်းမှုများ မရှိစေရန် Receipt/Reference ကို စစ်ပါ။
- **Cash & KPay စာရင်း** — Cash နှင့် KPay Ledger ကို နှိုင်းယှဉ်ပါ။
  KPay Sale တစ်ခုစီတွင် Transaction ID နှင့် Account Snapshot ရှိပါသည်။
- **စာရင်းခွဲခြမ်းစိတ်ဖြာ** — အရောင်း၊ အမြတ်၊ ပစ္စည်းနှင့် ဆိုင်ခွဲ
  စွမ်းဆောင်ရည်ကို ကြည့်ပါ။

### 3.6 Activity Log

- Checkout, Void, Stock ပြင်ဆင်မှု၊ ငွေလက်ခံမှု၊ KPay ပြောင်းလဲမှုနှင့်
  အခြားအရေးကြီးသော လုပ်ဆောင်ချက်များကို **Activity Log** တွင် စစ်ပါ။
- သမိုင်းဟောင်းများကို လိုအပ်လျှင် On-demand Load လုပ်ပါ။
- မသင့်လျော်သော လုပ်ဆောင်ချက် တွေ့လျှင် Screenshot နှင့် Voucher/Reference
  ကို မှတ်တမ်းတင်ပြီး စစ်ဆေးပါ။

## 4. Cashier — နေ့စဉ် အလုပ်လုပ်ငန်းစဉ်

### 4.1 အလုပ်စတင်ခြင်း

1. မိမိ Email/Password ဖြင့် Login ဝင်ပါ။ ဆိုင်ခွဲကို စနစ်က သတ်မှတ်ပေးထားပြီး
   ဆိုင်ခွဲပြောင်း၍ မရပါ။
2. **Cash Register / Shift** တွင် Shift ဖွင့်ပြီး Opening Cash ကို ရေတွက်ထည့်ပါ။
3. POS သို့ သွားပြီး လက်ရှိ Product/Price များ မှန်ကန်ကြောင်း စစ်ပါ။
4. Receipt Printer နှင့် Barcode Scanner ကို အလုပ်မစမီ စမ်းပါ။

### 4.2 အရောင်းပြုလုပ်ခြင်း

1. **အရောင်း POS** တွင် Product ကို နှိပ်ပါ သို့မဟုတ် Barcode ဖတ်ပါ။
   ဖုန်း Camera Scanner ကို လိုအပ်လျှင် အသုံးပြုနိုင်ပါသည်။
2. ပစ္စည်းအရေအတွက်နှင့် ဈေးနှုန်း (လက်လီ/လက်ကား) ကို စစ်ပါ။
3. လျှော့ဈေးပေးလျှင် Owner သတ်မှတ်ထားသော Cashier Discount Limit ကို
   မကျော်ရပါ။ ကန့်သတ်ချက် ကျော်လျှင် Owner ထံ တင်ပြပါ။
4. ငွေရှင်းမည့်နည်းလမ်း ရွေးပါ —
   - **Cash** — လက်ခံငွေထည့်ပြီး ပြန်အမ်းငွေကို စစ်ပါ။
   - **KPay** — ဖောက်သည်ထံမှ ငွေလွှဲပြီးမှ KPay Transaction ID ကို ထည့်ပါ။
     အနည်းဆုံး ၄ လုံးနှင့် အနည်းဆုံး ဂဏန်းတစ်လုံး ပါရမည်။
     ငွေလွှဲမှန်ကန်ကြောင်းကို ကိုယ်တိုင် စစ်ပြီးမှ အတည်ပြုပါ။
   - **Credit** — Customer ရွေးပါ၊ ကြိုတင်ငွေရှိလျှင် ထည့်ပါ။
     လက်ကျန်ကို Customer Page တွင် ပြန်စစ်ပါ။
5. **ငွေရှင်းမယ်** ကို တစ်ကြိမ်သာ နှိပ်ပါ။ ခလုတ်ကို ထပ်ခါတလဲလဲ
   မနှိပ်ပါနှင့်။ စနစ်က တစ်ကြိမ်တည်း Sale တစ်ခုသာ သိမ်းပါသည်။
6. Receipt ပေါ်တွင် Voucher No၊ ပစ္စည်း၊ ပမာဏ၊ ငွေရှင်းနည်းနှင့်
   ပြန်အမ်းငွေကို စစ်ပြီးမှ ဖောက်သည်ထံ ပေးပါ။

### 4.3 ငွေရှင်းပြီးနောက်

- Receipt ကို ပြန်ထုတ်ရန် **အရောင်းမှတ်တမ်း** တွင် Voucher No ဖြင့် ရှာပါ။
- မှားယွင်းမှု တွေ့လျှင် ကိုယ်တိုင် Void မလုပ်ပါနှင့်။
  **Void တောင်းဆို** ဖြင့် အကြောင်းရင်းနှင့်အတူ Owner ထံ တင်ပြပါ။
- Credit ငွေလက်ခံလျှင် Customer Page တွင် ငွေပေးချေမှု မှတ်တမ်းတင်ပါ။
  Receipt/Reference မပါဘဲ ငွေမလက်ခံပါနှင့်။

### 4.4 Offline အခြေအနေ

- Internet မရှိလျှင်လည်း အရောင်းကို ဆက်လုပ်နိုင်ပါသည်။ Sale သည်
  Device ထဲတွင် Queue ဖြစ်ပြီး Internet ပြန်ရလျှင် Cloud သို့ ပို့ပါသည်။
- **အရောင်းမှတ်တမ်း** တွင် `Cloud Sync စောင့်နေ` ဟု ပြလျှင် Page ကို
  မပိတ်ပါနှင့်၊ မဖျက်ပါနှင့်။ Internet ပြန်ချိတ်သည်အထိ စောင့်ပါ။
- Cashier Cash Record (Shift/Cash Movement/Customer Payment) များလည်း
  Offline Queue ဖြစ်နိုင်ပါသည်။ Sync မပြီးမချင်း App ကို မရှင်းပါနှင့်။
- Sync မအောင်မြင်သော အကြောင်းရင်း (Internet, Rules, Quota) ကို
  Status Message တွင် ကြည့်ပြီး Owner ထံ တင်ပြပါ။

### 4.5 Shift ပိတ်ခြင်း

1. နေ့စဉ်အရောင်းပြီးလျှင် **Cash Register / Shift** သို့ သွားပါ။
2. လက်ရှိ Cash၊ Cash-in/Cash-out နှင့် ငွေလက်ခံမှုများကို စစ်ပါ။
3. လက်တွေ့ရေတွက်ငွေ (Counted Cash) ထည့်ပြီး Shift ပိတ်ပါ။
4. ကွာဟမှု (Variance) ရှိလျှင် အကြောင်းရင်းကို မှတ်တမ်းတင်ပြီး Owner ထံ
   ချက်ချင်း တင်ပြပါ။
5. ပိတ်ပြီးသော Shift ကို ပြန်ဖွင့်၍ မရပါ။ မှားယွင်းလျှင် Owner ထံ တင်ပြပါ။

### 4.6 Cashier ခွင့်ပြုချက် နယ်ပယ်

Cashier သည် အောက်ပါတို့ကိုသာ အသုံးပြုနိုင်ပါသည် —

- POS အရောင်း
- မိမိအရောင်းမှတ်တမ်း
- Customer / Credit (မိမိဆိုင်ခွဲ)
- Cash Register / Shift
- မိမိအသုံးစရိတ်
- မိမိငွေလက်ခံမှတ်တမ်း
- Owner ခွင့်ပြုထားလျှင် ရောက်လာသောကုန် စစ်ဆေးရန်

Owner စာမျက်နှာများ၊ အခြားဆိုင်ခွဲ Data နှင့် အခြား Cashier ၏
မှတ်တမ်းများကို Cashier မြင်ခွင့် မရှိပါ။

## 5. KPay အသုံးပြုမှု စည်းမျဉ်း

- KPay Sale တစ်ခုတည်းအတွက် Transaction ID တစ်ခုတည်း။ ထပ်နေသော
  Transaction ID ကို စနစ်က ငြင်းပယ်ပါသည်။
- ဖောက်သည်က ငွေလွှဲပြီးကြောင်း ပြသသည့် KPay Receipt/Screenshot ကို
  စစ်ပြီးမှ Transaction ID ကို ထည့်ပါ။
- App သည် ငွေလွှဲကို KPay API ဖြင့် အလိုအလျောက် အတည်မပြုပါ။
  Owner/Cashier က ကိုယ်တိုင် စစ်ဆေးရပါသည်။
- ငွေမရသေးဘဲ Sale ကို အတည်မပြုပါနှင့်။ မှားယွင်းလျှင် Owner ထံ
  ချက်ချင်း တင်ပြပါ။
- သမိုင်း Receipt များတွင် ထို Sale အချိန်က KPay Account အမည်/နံပါတ်
  ကို ပြပါသည်။ လက်ရှိ Account နှင့် မတူလျှင် သမိုင်းမှတ်တမ်းအရ ဖြစ်ပါသည်။

## 6. Backup, Update နှင့် Device ပြောင်းခြင်း

- Device အသစ်သို့ ပြောင်းမည်ဆိုလျှင် ဟောင်းစက်တွင် **Export JSON Backup**
  လုပ်ပြီး ဖိုင်ကို သိမ်းပါ။ ထို့နောက် စက်အသစ်တွင် Login ဝင်ပြီး
  **Import / Restore** လုပ်ပါ။
- Import မလုပ်မီ စက်အသစ်တွင် မလိုအပ်သော Local Data မရှိကြောင်း စစ်ပါ။
- App Update ရလျှင် Page ကို Refresh လုပ်ပါ။ Site Data ကို မရှင်းပါနှင့်။
- iPhone တွင် Safari က Site Data ကို အလိုအလျောက် ဖျက်နိုင်သည့်
  Storage Pressure ရှိနိုင်ပါသည်။ နေ့စဉ် Backup လုပ်ခြင်းကို မမေ့ပါနှင့်။
- Backup ဖိုင်ကို ဖုန်းထဲတင်မကဘဲ Cloud/ကွန်ပျူတာတွင် နှစ်နေရာအထိ
  သိမ်းပါ။

## 7. ပြဿနာဖြေရှင်းခြင်း

| ပြဿနာ | လုပ်ဆောင်ရန် |
|---|---|
| Login မဝင်နိုင် | Password စစ်ပါ။ အကောင့် Disable ဖြစ်နေလျှင် Owner ထံ ဆက်သွယ်ပါ။ ဆိုင်ခွဲ မသတ်မှတ်ရသေးလျှင် Owner က Profile တွင် UID ချိတ်ရပါမည်။ |
| Cashier က ဆိုင်ခွဲ မှားနေသည် | Owner က ဝန်ထမ်းအကောင့်၏ Branch Permission ကို ပြင်ရပါမည်။ Cashier ကိုယ်တိုင် မပြောင်းနိုင်ပါ။ |
| KPay ရွေးမရ | Owner က Cash & KPay စာရင်းတွင် KPay ဖွင့်ထားခြင်း ရှိ/မရှိ စစ်ပါ။ Account အမည်/နံပါတ် လိုအပ်ပါသည်။ |
| KPay Transaction ID လက်မခံ | အနည်းဆုံး ၄ လုံး၊ ဂဏန်းတစ်လုံးပါရမည်။ Space သို့မဟုတ် မသင့်လျော်သော သင်္ကေတ မပါစေရန် စစ်ပါ။ |
| Checkout မဖြစ် | Product Stock နှင့် Batch လက်ကျန် လုံလောက်မှု၊ KPay Account ဖွင့်ထားမှု၊ Duplicate Transaction ID ကို စစ်ပါ။ Error စာသားကို မှတ်တမ်းတင်ပါ။ |
| `Cloud Sync စောင့်နေ` | Internet ပြန်ရသည်အထိ စောင့်ပါ။ Page မပိတ်ပါ၊ Data မရှင်းပါ။ ကြာလျှင် Owner ထံ တင်ပြပါ။ |
| Stock နှင့် လက်တွေ့ မကိုက် | ရောင်းချမှု/Void/Receive/Transfer မှတ်တမ်းများကို စစ်ပြီး လက်တွေ့ရေတွက်ပါ။ ပြင်ဆင်မှုကို Stock ± ဖြင့် မှတ်တမ်းတင်ပါ။ |
| Receipt Printer မထုတ် | OS Print Service တွင် Printer ချိတ်ထားမှု၊ Paper Width နှင့် Browser Print Dialog ကို စစ်ပါ။ App သည် Browser/System Print ကို အသုံးပြုပါသည်။ |
| Myanmar စာလုံး ပျက် | Device Font (Pyidaungsu/Myanmar Unicode) နှင့် Printer Font Support ကို စစ်ပါ။ Screenshot နှင့် အတူ တင်ပြပါ။ |
| Data ပျောက် | Site Data ရှင်းခြင်း၊ Browser ပြောင်းခြင်း၊ Private Mode သုံးခြင်း ရှိ/မရှိ စစ်ပါ။ Backup ရှိလျှင် Restore လုပ်ပါ။ Owner ထံ ချက်ချင်း တင်ပြပါ။ |

## 8. နေ့စဉ် ပိတ်ပွဲစစ်ဆေးရန်

- [ ] ယနေ့ Sale အားလုံး Completed ဖြစ်ပြီး Void/Queue မကျန်ရှိ။
- [ ] Cash Shift ပိတ်ပြီး Variance ကို မှတ်တမ်းတင်ပြီး။
- [ ] KPay Sale များ၏ Transaction ID ကို စစ်ပြီး။
- [ ] Credit Sale နှင့် ငွေလက်ခံမှုများ မှတ်တမ်းတင်ပြီး။
- [ ] Stock Receive/Transfer/Void များ စစ်ပြီး။
- [ ] Expense နှင့် Owner Approval လိုအပ်သည့် အချက်များ စစ်ပြီး။
- [ ] **Export JSON Backup** လုပ်ပြီး Device အပြင်တွင် သိမ်းပြီး။
- [ ] Activity Log တွင် မသင့်လျော်သော လုပ်ဆောင်ချက် မရှိ။
- [ ] Device ကို လုံခြုံစွာ Lock လုပ်ပြီး မလိုအပ်သော Login များ Sign Out လုပ်ပြီး။
