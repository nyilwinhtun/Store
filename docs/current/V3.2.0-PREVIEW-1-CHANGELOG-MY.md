# Minimart POS v3.2.0 — Barcode Unit Preview 1

## ပြင်ဆင်ထားသောအပိုင်းများ

- ဆိုင်မှ ဝယ်ထားသော Unique Barcode Sticker ကို ပစ္စည်းတစ်ခုချင်း Scan ဖတ်ပြီး Stock Unit အဖြစ် စာရင်းသွင်းနိုင်ရန် `StockUnitRegistrationPage` ကို Inventory ထဲမှ ဝင်ရောက်အသုံးပြုနိုင်အောင် ချိတ်ဆက်ထားသည်။
- App က Barcode အသစ်ထုတ်ပေးခြင်း၊ Sticker Print ထုတ်ခြင်း မပါဝင်ပါ။
- POS မှာ Unit Sticker Barcode Scan လုပ်လျှင် အဲဒီ Physical Unit တစ်ခုတည်းကို Cart ထဲ ထည့်သည်။
- Unit-tracked Product အတွက် Cart Quantity ကို Sticker Scan မလုပ်ဘဲ တိုးခွင့်မပြုပါ။
- Sold / non-stock Unit Barcode ကို ထပ်ရောင်းခийг တားထားသည်။
- Cashier Cloud Sale Transaction ထဲမှာ Sale, Product Stock, Stock Batch, Barcode Registry update များကို တစ် Transaction အဖြစ် ချိတ်ထားသည်။
- Cloud Owner Void Transaction မှာ Sale နဲ့ ချိတ်ထားသော Barcode Unit ကို History မဖျက်ဘဲ `in_stock` ပြန်ထားနိုင်ရန် ထည့်ထားသည်။
- Manual Stock Adjustment, Supplier Purchase, Stock Receiving, Supplier Return, Shipment Cancel နဲ့ Quantity-only Branch Transfer တို့မှ Unit-tracked Product Stock မကိုက်ညီစေမည့် လမ်းကြောင်းတွေကို ပိတ်ထားသည်။
- Barcode Unit Registration အတွက် သီးခြား Side Menu မထည့်ဘဲ Inventory ထဲက Button ဖြင့် ဖွင့်နိုင်သည်။
- CashierAutoSync ထဲတွင် Branch `stockUnitRegistries` listener ထည့်ထားသည်။
- Firestore Rules ထဲတွင် Cashier Unit Registry update ကို linked Sale ပါသော transaction အတွင်းသာ ခွင့်ပြုမည့် helper ထည့်ထားသည်။

## မပြောင်းထားသော အပိုင်းများ

- Firebase Authentication Logic, API Keys / Firebase Config, Login Validation ကို မပြင်ထားပါ။
- Existing Product/Sales/Stock/Shipment data ကို Migration မလုပ်ထားပါ။
- မူရင်း Project ZIP ကို မပြင်ထားပါ။
- လက်ရှိ Branch Shipment UI/approval flow ကို မပြင်ထားပါ။

## မပြီးသေးသော / Production မတင်သေးရမည့်အပိုင်းများ

1. `npm install` သည် package registry cache မရှိသောကြောင့် offline install မအောင်မြင်ပါ။ Internet/package download မရသောကြောင့် Full `npm run build` မလုပ်နိုင်သေးပါ။
2. ပြင်ထားသော TS/TSX ၉ ဖိုင်ကို Global TypeScript `transpileModule` parser ဖြင့် စစ်ရာ syntax error မတွေ့ပါ။ ဒါဟာ Full TypeScript typecheck/build အောင်မြင်တယ်လို့ မဆိုလိုပါ။
3. Firebase CLI/Emulator မရှိသဖြင့် Firestore Rules syntax/emulator test နှင့် deploy မလုပ်ရသေးပါ။
4. Barcode-aware Branch Transfer မပါသေးပါ။ Unit-tracked Product ကို Quantity-only Transfer လုပ်ခြင်းကို ယာယီတားထားသည်။
5. Exception-based Auto Complete Transfer workflow မပြီးသေးပါ။ လက်ရှိ Shipment approval flow ကို ထိန်းထားသည်။
6. Owner sale သည် Existing Owner Auto Sync လမ်းကြောင်းကို သုံးနေသေးသည်။ Cashier သီးသန့် cloud transaction path နှင့် တူညီသော dedicated unit sale transaction မဟုတ်သေးသည့်အတွက် Owner POS unit barcode sales ကို Production မတင်မီ သီးခြား စမ်းသပ်ရန်လိုသည်။
7. Security Rules ပြင်ဆင်မှုကို Production Firebase ထဲ မတင်ရသေးပါ။ Test project / Emulator တွင် validate လုပ်ပြီးမှ ထည့်ရမည်။

## လုပ်ငန်းအသုံးပြုရန် အရေးကြီးသတိပေးချက်

- Product အသစ်အတွက် Opening Stock ကို 0 ထားပြီး Sticker တစ်ခုချင်း Scan လုပ်ပါ။ Scan တစ်ခုစီက Stock တစ်ခု တိုးစေသည်။
- Stock ရှိပြီးသား Product ကို ပထမဆုံး Unit Barcode Tracking စလုပ်ပါက လက်ရှိ Stock အရေအတွက်နဲ့ တိတိကျကျ တူညီသော Sticker အရေအတွက်အားလုံးကို Scan လုပ်ရမည်။ ဒါက Stock နှစ်ခါတိုးခြင်းကို ကာကွယ်ရန်ဖြစ်သည်။
- Unique Barcode Sticker တစ်ခုကို Physical Item တစ်ခုတည်းအတွက်သာ သုံးပါ။
- ဒီ Preview ကို လက်ရှိ Production URL / Firebase Project ထဲ တိုက်ရိုက်မတင်ပါနှင့်။ Build + Emulator + Branch 1/2 regression tests ပြီးမှသာ Release Candidate ဖြစ်နိုင်သည်။
