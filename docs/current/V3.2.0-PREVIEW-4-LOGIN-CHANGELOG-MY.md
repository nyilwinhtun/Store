# Minimart POS v3.2.0 Preview 4 — Standalone Login & File Organization

## Login ပြင်ဆင်မှု

- Website Root ကို ဝင်လာသော၊ Firebase Session မရှိသော အသုံးပြုသူအတွက် Standalone Login Page ကို ပထမဆုံးပြသည်။
- Login Form ကို Sidebar / Navigation Menu / Profile Menu မှ ခွဲထုတ်ထားသည်။
- လက်ရှိ Firebase Email/Password Authentication API ကို ဆက်သုံးထားသည်။
- Password Reset နှင့် ရှိပြီးသား Owner Account Creation Workflow ကို Login Screen သို့ ရွှေ့ထားသည်။
- Login ပြီးလျှင် AccessBootstrap မှ Owner/Cashier Business Permission ကို အတည်ပြုပြီးမှ Workspace ကို ပြသည်။
- Owner နှင့် Cashier နှစ်မျိုးလုံးအတွက် Topbar တွင် Sign Out ထည့်ထားသည်။
- Sign Out ပြီးနောက် Auth State ပြောင်းလဲမှုကြောင့် Login Screen ကို ပြန်ပြသည်။
- Firebase Session ရှိပြီးသားဆို App က Access ကို ပြန်စစ်ပြီး Workspace ကို ဆက်ဖွင့်နိုင်သည်။

## Documentation ပြင်ဆင်မှု

- Root ထဲက Markdown ဖိုင် 81 ခုကို မဖျက်ဘဲ `docs/` အောက်တွင် အုပ်စုခွဲရွှေ့ထားသည်။
- `docs/current/`, `docs/testing/`, `docs/releases/`, `docs/archive/`, `docs/reference/` ဖွဲ့စည်းထားသည်။
- Root `README.md` ကို အသစ်ပြန်ရေးထားပြီး `docs/README.md` မှာ Documentation Index ထည့်ထားသည်။
- Vite/Firebase/TypeScript configuration files များကို Build/Deploy Path မပြောင်းစေရန် Root မှာပဲ ထားထားသည်။

## မပြောင်းထားသောအရာများ

- Firebase Project ID, API Key, Auth Domain, Business ID။
- Firebase Email/Password Auth API behavior။
- AccessBootstrap မှ Owner/Cashier Business Access Resolution Logic။
- Firestore Security Rules နှင့် Shipment/Barcode/Sales Logic။

## စမ်းသပ်မှုအခြေအနေ

- TypeScript/TSX Syntax parse: အောင်မြင်။
- CSS brace balance: ကိုက်ညီ။
- Documentation files: Root မှ docs အောက်သို့ စီစဉ်ပြီး။
- Full Vite Build / Firebase Emulator: Dependency မရှိသေးသောကြောင့် မပြီးသေး။
- Production Login Regression: Test Firebase Project နှင့် ဆိုင်နှစ်ဆိုင် Device များဖြင့် ထပ်စမ်းသပ်ရန် လိုအပ်သည်။

ဒီ Preview ကို Production သို့ မတင်မီ `docs/testing/V3.2.0-LOGIN-REGRESSION-TEST-PLAN-MY.md` ကို လိုက်နာစမ်းသပ်ပါ။
