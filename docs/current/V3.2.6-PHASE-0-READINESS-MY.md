### 2.1 Environment defects found (tooling, not product)

1. **System Node is not a supported release.**
   `/usr/local/bin/node` reports `v27.0.0-alpha.0.0.0`. `firebase-tools` 15.35.0 enforces
   `semver.satisfies(process.version, engines.node)` in `lib/bin/firebase.js:17` and exits
   before the emulator starts. There is no supported bypass flag. This does **not** affect
   the application, the Vite build, or the unit tests; it blocks only the Firebase CLI.
   - Workaround used: an unmodified official Node 24.22.3 runtime in `/tmp/node24`.
   - No project file was changed to work around it.
   - If `/tmp` is cleared, re-extract the tarball before running emulator tests.
2. **TCP port 8080 is occupied by a user process.**
   `python3.1` (PID 2068) is listening on `127.0.0.1:8080`. It was **not** stopped or
   modified. The emulator was run on port **8099** using a temporary config at
   `/tmp/phase0-emu/firebase.json` with a byte-identical copy of `firestore.rules`
   (SHA-256 `a2177b0a…8047d` matched both files).
   Because `tests/firestore.rules.test.mjs` passes the repository's rules text directly to
   `initializeTestEnvironment`, the tested content is the repository file, not the copy.

Consequence: `npm run qa` on this machine fails at the rules step unless Node 24 is on
`PATH` and port 8080 is free. The product is not at fault; the runner environment is.
This is recorded as a known limitation, not a test failure.

### 5.3 Restore procedure

1. Confirm HEAD is still `eedbb63`. If it is not, stop: the patch targets that commit.
2. `git status --porcelain=v1 | diff - <backup>/git-status.txt` to see what drifted.
3. Reapply tracked changes: `git apply "<backup>/tracked-changes.patch"`.
4. Restore untracked files: `tar -xzf "<backup>/untracked-files.tar.gz" -C <repo-root>`.
5. Re-verify: status equals `git-status.txt`, and `shasum -a 256 -c SHA256SUMS.txt` passes.

Ignored, regenerable outputs (`node_modules/`, `dist/`, `.qa-build/`) are intentionally not
archived; they rebuild from `package-lock.json`.

copied to `Store-backups/phase1-pre/` preserving relative paths. Rollback of any Phase 1
step then means copying those files back and deleting only files that Phase 1 created
(`src/lib/syncManifestStorage.ts`). This avoids touching the pre-existing 19+16 changes,
avoids `git stash`, and creates no commits.

## 10. Migration strategy

All changes are additive and optional. No production migration is proposed.

### 10.1 KPay sale snapshots (Firestore)

- Add optional `kpayAccountNameSnapshot`, `kpayAccountNumberSnapshot`,
  `kpayAccountLabelSnapshot`, `kpayQrVersionSnapshot` to `Sale`.
- Populate from the branch settings the cashier saw at sale time.
- Never backfill historical sales. Legacy rows render "Not recorded".
- Old clients ignore unknown fields; new clients fall back cleanly. No rewrite, no index
  change, no collection change.
- Rollback: stop writing the fields; readers already tolerate absence. No data cleanup
  required.

### 10.2 Manifest storage migration (device-local)

- Create an IndexedDB object store (new module `syncManifestStorage.ts`), keep a parsed
  in-memory cache, and retain a small LocalStorage marker for fast/supersession checks.
- **Dual-read:** read IndexedDB first; if absent, read and validate the legacy
  LocalStorage manifest, then write the IndexedDB copy and mark migration complete. Do not
  delete the LocalStorage value until the IndexedDB write is confirmed by read-back.
- **Atomicity:** write the full manifest in one transaction; a failed or interrupted write
  leaves the previous manifest intact.
- **Guard:** never push without a valid baseline; preserve reset/rebaseline markers and the
  existing conflict halt.
- **Proof:** 25k-record test, interrupted-write test, reload test, and a manual
  reset/restore rehearsal.
- Rollback: legacy key remains readable; revert the module and continue from LocalStorage.

### 10.3 Activity-log bounds (Firestore untouched)

- Remove `activityLogs` from the full-listener set; sync a recent window/incremental slice.
- Keep every cloud document. Older history loads on demand (pagination + CSV export).
- Trim only merged local state, and never drop pending unsynced local entries.
- Unify the 300/1,000 caps into one constant and correct the UI copy.
- Rollback: restore the full listener; no cloud data was lost, so recovery is lossless.

### 10.4 What will not happen

No collection replacement, no field deletion, no destructive rewrite, no production
backfill, no archive deletion, no billing change.
