## Phase 1 — P0 data safety, KPay history, audit-log bounds — COMPLETE

### Implemented

1. Durable sync manifest (`src/lib/syncTypes.ts`, `src/lib/syncManifestStorage.ts`)
   - Manifest moved to IndexedDB (`readDurableValue`/`writeDurableValue`) with an
     in-memory cache for synchronous reconcile reads.
   - `preloadManifest()` runs before the sync engine mounts, so a missing cache can
     no longer masquerade as a first-time device.
   - Legacy LocalStorage manifest is migrated with read-back before deletion.
   - `parseManifest()` validates version/business/entries; superseded baselines are
     rejected by the existing reset-safety marker.
   - `saveManifest()` is async and reports marker-only fallback as a durable failure.
2. Activity-log retention (`src/lib/activityLogPolicy.ts`)
   - Cloud history is never deleted. Devices keep the newest 1,000 entries.
   - Owner listeners sync a 90-day window (`activityLogWindowStart`) instead of a
     full collection scan, with the usual 120-second overlap clamped to the cutoff.
   - `importCloudItems` merges cloud logs with local unsynced logs (dedupe by id,
     newest-first) instead of replacing them.
   - Owner can page older cloud history on demand (`loadBranchActivityLogs`,
     50 per page, bounded server reads, no listener).
3. KPay account history
   - `Sale`, `CustomerPayment` and `CashierSettlementRecord` carry immutable
     `kpayAccount{Name,Number,Label}Snapshot` + `kpayQrVersionSnapshot`.
   - `addSale`, `addCustomerPayment` (Transfer) and `addCashierSettlement` (kpay)
     freeze the branch account at transaction time.
   - `saleFingerprint` / `legacySaleMatches` include the snapshots so retries stay
     idempotent.
   - Owner changes are audited as `KPAY_ACCOUNT_UPDATE` / `KPAY_QR_UPDATE` with the
     account number masked to the last four digits.
4. Firestore Rules
   - Cashier sale and customer-payment payloads accept bounded snapshot fields.
   - Snapshots are deliberately **not** compared with current branch KPay settings,
     so an Owner account change cannot invalidate historical records.
5. UI
   - Receipt (print + copy text), Sales table, dashboard recent sales and Sales CSV
     now show the frozen KPay account instead of only the transaction ID.
   - Activity Log page documents the 90-day sync window and 1,000-entry local copy,
     and adds on-demand cloud history paging.

## Phase 2 — Firebase cost reduction + KPay QR — COMPLETE

### Implemented

1. Branch KPay QR (`src/lib/kpayQr.ts`, `BranchFinanceManagementPage.tsx`, `App.tsx`, `index.css`, `firestore.rules`)
   - Branch settings gain `kpayQrDataUrl`, `kpayQrVersion`, `kpayQrUpdatedAt`, `kpayQrUpdatedBy`.
   - Owner can upload/replace/remove a QR image. Input is raster-only
     (PNG/JPEG/WebP), max 5 MB source; the image is re-encoded through a canvas
     to 720/560/440/360 px with a 4% quiet zone and a white background, trying
     PNG → WebP 0.86 → JPEG 0.86 until the data URL is ≤60,000 characters.
   - SVG, remote URLs and non-image data URLs are rejected in the library, on
     save and again at render time, so a tampered cloud document cannot inject
     markup or load a remote asset.
   - The QR lives inside the branch payload, so cashier devices render it from
     the cached branch document while offline; no Firebase Storage or extra reads.
   - Every add/replace/remove bumps `kpayQrVersion`; `updateBranch` already emits
     the masked `KPAY_QR_UPDATE` audit entry.
   - Rules: `validBranchKpayQr` enforces the size cap, raster prefixes and version
     type on Owner branch writes; deletion tombstones (payload `null`) stay valid.
   - Cashier payment panel shows the QR next to the frozen account name/number
     with a copy action.
2. Cashier cash-collection cost bounds (`src/lib/cashierSyncCursor.ts`, `CashierAutoSync.tsx`)
   - `cashShifts`, `cashMovements` and `customerPayments` no longer re-read the
     whole collection on every cashier startup. After one full read the device
     stores a per-business/cashier/branch cursor and listens with
     `updatedAt >= cursor − 120 s`.
   - A cursor is only used when the store is hydrated, the local dataset for that
     branch is non-empty and no reset/replacement is pending; otherwise the
     listener falls back to a full read. Reset events clear all cashier cursors.
   - Snapshot results are unioned with the persisted records (`mergeById`), so
     older history is never deleted locally and shift totals, the customer credit
     ledger and CSV exports keep the exact same values. This replaces an earlier
     date-window plan that would have changed ledger totals.
   - Append-only ledger entries are not deleted by any app workflow, so filtering
     the listener cannot strand a remotely deleted record (documented limitation).
3. Archived-branch exclusion (`OwnerAutoSync.tsx`)
   - Realtime listeners now attach only for branches whose payload `status` is
     `active`. Archiving a branch unsubscribes its record listeners and clears
     their readiness; restoring it re-attaches all kinds (incremental cursors
     replay the changes made while archived).
   - `coreListenersReady` requires only active branches. The last known cloud
     items of an archived branch stay cached in `remoteItems` and the 3-way merge
     treats unlistened branch records as unchanged instead of missing, so
     archiving can never produce false conflicts or cloud deletions.
   - Permanently removed branches still purge their cached items.
4. Listener metadata callbacks (`OwnerAutoSync.tsx`)
   - `includeMetadataChanges: false` for Owner listeners (cashier listeners were
     already switched in this phase).
   - Readiness is only added by server-confirmed snapshots and is no longer
     withdrawn by cache snapshots; offline still clears readiness.
   - `pendingWrites` gating was removed. With metadata callbacks disabled,
     acknowledgment-only snapshot events never arrive, so a pending flag would
     stay set forever and block sync. Write safety is preserved by the merge
     idempotence, the shipment commit guard and the baseline compare-and-write.
   - Added a hydration gate in `reconcile()` plus `onFinishHydration`: a merge can
     no longer run against the pre-hydration default store and misread empty
     collections as cloud deletions.
5. Cost measurement
   - `recordFirestoreActivity` now counts initial reads, change reads and listener
     starts per collection (`cashier-listener-initial:*`,
     `cashier-listener-changes:*`, `listener-initial:*`).
   - Expected effect (no production Console access, so UNVERIFIED):
     cashier startup reads for the three cash collections drop from the full
     collection size to (documents changed since the last sync), archived
     branches stop generating listeners entirely, and metadata events no longer
     bill as listener events.

- The cart panel had a fixed height with `overflow:hidden`. Title, customer /
  payment switch and summary were fixed-height children, so at 390×844 the
  summary and the checkout button overflowed past the panel bottom and were
  clipped under the fixed bottom navigation.

  passed it. Both Cash and Credit flows created duplicate sales and duplicate
  stock decrements in the emulator before the fix.

- `src/App.tsx`: cart is now `cart-title` (fixed) + `cart-scroll` (customer,
  items, held list) + `cart-summary` (total, checkout) in normal flow.

  `addSale` runs and is released on every exit path; the retry path for a failed
  local persistence write is locked the same way.
- `src/index.css`: non-shrinking summary footer, scrollable middle, mobile
  overrides that keep `.checkout-button` static inside the footer.
- `src/lib/kpayReference.ts`: Transaction ID validation (trimmed, 4–120 chars,
  at least one digit, `A-Z a-z 0-9 . _ -` only) with Myanmar error messages.
- KPay confirm stays disabled until the reference is valid; the modal shows
  pending vs ready verification and the result labels the payment as
  `Manual verification`. The normalized value is persisted with the sale, and
  branch account snapshots are unchanged.
- `tests/pos-checkout.test.mjs` + `scripts/test-pos-checkout.mjs` +
