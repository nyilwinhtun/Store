```bash
# (Rules history) before changing anything. Keep it for rollback.

# docs/reference/firestore/production-rules-2026-11-15.rules (69406119…).

# passed the Staging matrix. Owner-approved change window only.

```

Do **not** deploy `completeCashierUnitSale` / `cashierSaleVoid` /
`cashierSaleReturn` to Production: Cloud Functions requires Blaze, which is
forbidden by the free-only policy. Those callables remain the local/Staging
trusted path; the Production free path is the Cloudflare Worker.

Build/deploy the Web App through the existing GitHub Pages workflow only after
the Rules and the trusted Worker path are live and smoke tests are ready.

Before deployment, re-read the live Rules and compare with the local
`firestore.rules`; do not reuse an old hash from this document.

## 5. Post-Deploy Smoke Test (read-only first)

- Owner login; Cashier login with assigned branch only.
- Cash, KPay, Credit sale each commit exactly once.
- Tracked sticker sale: Sale + Product + Batch + Unit Registry + Audit update.
- Retry the same Sale ID/fingerprint → `already-committed`, no second stock move.
- Cashier Return (restock + damaged) and Void; retry replay.
- Credit Return adjusts due; KPay Return shows `kpay-pending`.
- Owner Dashboard: confirmed sale, pending queue, Owner Review, stock/batch/
  barcode totals, Cash/KPay/Credit totals, customer balance.
- Offline queue: pending survives reload, reconnect commits once, rejection stays
  in Owner Review and is not auto-deleted.

## 6. Free-Only Recovery Options and Limitations

- **Firestore managed backups / point-in-time recovery are not used** — they
  require paid capabilities. Do not enable Blaze to obtain them.
- Prepared free tool: [`V3.3.0-FREE-BACKUP-RECOVERY-MY.md`](V3.3.0-FREE-BACKUP-RECOVERY-MY.md)
  with `scripts/firestore-export.mjs` / `scripts/firestore-restore.mjs`.
  It exports root collections and subcollections with pagination and a SHA-256
  manifest, then restores into a separate project. It is **not** a managed
  backup: Rules, indexes, Auth users, Storage and point-in-time history are
  excluded, and create/update timestamps are not restored.
- The tool refuses `minimart-production` unless `--allow-production` is passed
  with explicit Owner authorization. No Production export has been performed.
- Application-level JSON backup and Console per-record export remain manual and
  partial. The local emulator seed is **not** a Production backup.
- **A verified full Production recovery backup does not exist.** This remains a
  release blocker. Do not claim otherwise.

## 7. Rollback

1. Keep the previous Ruleset release ID from the pre-deploy check. The archived
   snapshot is `docs/reference/firestore/production-rules-2026-11-15.rules`
   (SHA-256 `6940611978…`).
2. On a Rules problem: republish the recorded previous Ruleset release from
   Firebase Console → Firestore → Rules → History (see the candidate document).
3. On a Functions problem: delete/disable the newly deployed callables or
   redeploy the previous known-good Functions source; verify Cashier checkout
   fails closed to Owner Review rather than silently committing local-only.
4. On a Web App problem: redeploy the previous GitHub Pages artifact.
5. Do not delete Sales, Returns, pending queue entries, reservations, or audit
   records during rollback.
