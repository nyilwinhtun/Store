### 2.1 Void ပြီးနောက် Stock Batch Coverage ပျက်ခြင်း

- ပြဿနာ — `batchAllocations` မပါသော ဟောင်း Sale/Cashier Sync v1 Sale ကို
  Void လုပ်လျှင် Product Stock ပြန်တိုးသော်လည်း Stock Batch မပြန်တိုးပါ။
  ထို့နောက် Stock လုံလောက်သော်လည်း နောက် Sale ကို
  "Stock သို့မဟုတ် Stock Batch လက်ကျန် မလုံလောက်ပါ" ဖြင့် ငြင်းပယ်သည်။
- ပြင်ဆင်မှု — `voidSale` သည် ပြန်တိုးသည့် Product အတွက် Batch Coverage ကို
  ပြန်ဖြည့်သည်။ ရှိပြီးသား Opening Batch ရှိလျှင် Duplicate ID မဖြစ်စေရန်
  ထိုး Batch ထဲ ပေါင်းထည့်သည်။
- Regression test — `tests/pos-store-inventory.test.mjs`
  (legacy void → coverage ပြန်တိုး → နောက် Sale အောင်မြင်၊ allocated void
  idempotent၊ opening batch duplicate မဖြစ်)။
- သက်ရောက်မှု — ဟောင်း Sale များကို Void လုပ်ပြီးနောက် ဆက်လက်ရောင်းချနိုင်မည်။

## 3. Cashier Unit Barcode Sale (နောက်ဆုံး Blocker ဖြေရှင်းချက်)

### 3.1 ပြဿနာ

Cashier သည် `stockUnitRegistries` ကို လုံးဝ Read မရသောကြောင့် Sticker Scan
မလုပ်နိုင်ခဲ့ပါ။ Unit တစ်ခုချင်း ရောင်းချမှုကို Local တွင် ပြီးစီးအောင်
မှတ်ပြီးနောက် Registry ကို မရေးနိုင်ဘဲ Owner Review သို့ ရပ်ထားရပါသည်။
ထို Review သည် အမြဲတမ်း ကွဲလွဲမှု (Cloud Unit က `in_stock` ဖြစ်နေခြင်း)
ဖြစ်စေပါသည်။

### 3.2 ရွေးချယ်ထားသော ဖြေရှင်းချက် (Rules မလျော့ချပါ)

1. **Read-only Rules** — Cashier သည် မိမိ Branch ၏ `stockUnitRegistries` ကို
   get/list သာ ရသည်။ create/update/delete လမ်းကြောင်း မဖွင့်ပါ။
   `firestore.rules` ရှိ Cashier Read Allowlist တွင် `stockUnitRegistries`
   ထည့်ထားပြီး Write Path ကို မပြောင်းလဲပါ။
2. **Server-authoritative Callable** — `completeCashierUnitSale`
   (`functions/src/cashierUnitSale.ts`, region `asia-southeast1`) သည်
   Admin Transaction တစ်ခုတည်းဖြင့် Sale + Product Stock + Batch Stock +
   Unit `sold` Status + Audit Record ကို Commit သည်။
3. **အတည်ပြုချက်များ** — Cashier Membership/Branch, Receipt/Amounts,
   Payment Method (Cash/KPay/Credit), KPay Reference တစ်ကြိမ်သာ,
   Cloud Stock/Batch လုံလောက်မှု, Expiry, Shared Price Version,
   Unit Registry/Barcode/Batch တိုက်ညီမှု, တူညီသော Unit နှစ်ကြိမ်
   မပါဝင်မှု၊ Fingerprint Idempotency နှင့် Concurrent Duplicate
   (တစ်ခုသာ အောင်မြင်) ကို Server မှ စစ်သည်။
4. **Client Fallback** — Function မရောက်ရှိသေးလျှင် သို့မဟုတ်
   `permission-denied`/`failed-precondition` ဖြစ်လျှင် Sale ကို
   Local-only အဖြစ် မပြီးစီးစေဘဲ Owner Review သို့ ရပ်ထားသည်။
5. **Registry Sync** — CashierAutoSync သည် Registry ကို Listen လုပ်ပြီး
   မိမိ Device တွင် ပြီးစီးထားသော Sale ၏ Unit Status ကို Cloud
   Snapshot ဖြင့် မဖုံးလွှမ်းစေရန် `mergeCashierUnitRegistries` ဖြင့်
   ပေါင်းစပ်သည်။

Owner ၏ ရှင်းလင်းသော ခွင့်ပြုချက်မရှိဘဲ မ Run ပါနှင့်။ ၎င်းတို့သည်
Commit မလုပ်ရသေးသော RC နှင့် Untracked ဖိုင်များကို ဖျက်ပစ်နိုင်ပါသည်။
လိုအပ်လျှင် အထက်ပါ Patch နှင့် RC Archive ကို အရင် Backup လုပ်ပါ။

### 6.3 Deployed Build ကို ပြန်လည်ရယူခြင်း

- မည်သည့် Deployment မျှ ဤအလုပ်တွင် မလုပ်ထားပါ။
- အနာဂတ်တွင် Bad Build တင်မိလျှင် ယခင် Known-good Build Artifact ကို
  ပြန်တင်ပါ။ Production Data ကို မဖျက်ပါနှင့်။
- Production Data ပျက်စီးလျှင် ဤ RC တွင် Recovery Backup မရှိသေးပါ။
  Owner က Blaze/Backup လုပ်ဆောင်ချက် မအတည်ပြုမချင်း Data Rollback
  မလုပ်နိုင်ပါ။

### 6.4 Device ပေါ်ရှိ Local Data

- Deployment ကို ပြန်လည်ပြောင်းခြင်းသည် Device ၏ Local Storage/IndexedDB
  Data ကို မဖျက်ပါ။
- မလိုအပ်ဘဲ **Reset Local Data** သို့မဟုတ် Browser Site Data ရှင်းခြင်း
  မလုပ်ပါနှင့်။
- လိုအပ်လျှင် App ၏ **Settings → Export JSON Backup** ကို အရင် လုပ်ပါ။

## 7. ဤ RC တွင် မပါဝင်သေးသည့် အရာများ

### 7.1 Owner ခွင့်ပြုပြီးနောက် Deploy အစီအစဉ်

```bash
cd /Users/user/Documents/GitHub/Store
npm ci && npm --prefix functions ci
npm run typecheck && npm --prefix functions run build && npm run build
npm run check:security
npm run qa:quick
firebase deploy --only firestore:rules --project minimart-production
firebase deploy --only functions:completeCashierUnitSale --project minimart-production
```

Deploy ပြီးနောက် —

1. `firebase firestore:rules` သို့မဟုတ် Console မှာ Live Rules Version ကို
   စစ်ပါ။
2. Emulator မဟုတ်သော Production တွင် Cashier Account တစ်ခုဖြင့်
   Unit Barcode Scan → Cash Sale → Cloud Unit `sold` ဖြစ်ကြောင်း
   စမ်းသပ်ပါ။ ဤစမ်းသပ်မှုကို Owner က ကြီးကြပ်ပါ။
3. Function Deploy မအောင်မြင်လျှင် Cashier Unit Sale သည် Owner Review
   သို့ Fail-closed ဖြစ်မည် (Local-only Sale မဖြစ်ပါ)။ Rules Deploy
   မလုပ်လျှင် Cashier သည် Registry ကို Read မရသေးပါ။
