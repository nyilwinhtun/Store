# Minimart POS v3.1.0 Preview — Stock Unit Registration

## ဒီ Preview မှာ ပါဝင်တာ

- Owner Menu ထဲမှာ `တစ်ဘူးချင်း Barcode` စာမျက်နှာ ထည့်ထားသည်။
- ရှိပြီးသား unique manufacturer barcode ကို Bluetooth Scanner / Camera / Input ဖြင့် မှတ်ပုံတင်နိုင်သည်။
- Barcode မရှိသော ဘူးများအတွက် App က 64-bit random internal ID ပါသော Code 128B Barcode ထုတ်ပေးပြီး Label Print လုပ်နိုင်သည်။
- Barcode တူညီမှုကို လက်ရှိ Device တွင် Sync ရောက်နေသော Unit Registry အားလုံးနှင့် Product SKU / Product Barcode များအပေါ် စစ်ဆေးသည်။
- Product Barcode / EAN တစ်ခုတည်းကို ဘူးတိုင်းမှာ တူညီစွာ ရိုက်ထားပါက ၎င်းကို Unit Barcode အဖြစ် ပြန်သုံးခွင့်မပြုပါ။ Unique serial မရှိပါက App-generated Label ကို အသုံးပြုရမည်။
- App-generated ID ကို Secure Random 64-bit အခြေခံ၍ ဖန်တီးပြီး HTTPS သို့မဟုတ် localhost တွင်သာ Generate လုပ်နိုင်သည်။
- Product + Branch အလိုက် Registry Record ထဲမှာ Unit များကို စုထားသည်။ Unit တစ်ခုစီအတွက် Firestore Document သီးခြားမဖန်တီးပါ။ Record တစ်ခုလျှင် Unit ၂၅၀ အထိသာ ထည့်ပြီး ပိုလာလျှင် chunk အသစ်ဖန်တီးသည်။
- Unit အရေအတွက်သည် Product လက်ရှိ Stock ထက် မကျော်နိုင်ပါ။ Whole-number Product များအတွက်သာ ဖွင့်ထားသည်။
- Stock Unit Registry ကို LocalStorage Backup/Restore နှင့် Owner Cloud Sync ထဲ ထည့်ထားသည်။

## ဒီ Preview မှာ မလုပ်သေးတာ

- Product Stock ကို မတိုး၊ မလျှော့ပါ။
- Shipment ထဲ Unit Barcode အတိအကျ ရွေးချယ်ခြင်း မပါသေးပါ။
- Cashier Receiving တွင် Scan / Quantity Mode ဖြင့် Unit Status ပြောင်းခြင်း မပါသေးပါ။
- POS တွင် Unit Barcode တစ်ခုချင်းစီကို Sold သတ်မှတ်ခြင်း မပါသေးပါ။
- Offline Device များစွာမှ တစ်ပြိုင်တည်း ရှိပြီးသား Barcode တူညီမှုအတွက် Server-side atomic reservation မပါသေးပါ။ Owner Auto Sync Conflict ကို အခြေခံကာကွယ်မှုသာ ရှိသည်။

## Data Model

`stockUnitRegistries` သည် branch record ဖြစ်ပြီး Product + Branch + chunk အလိုက် သိမ်းသည်။ Registry ID ပုံစံမှာ `unit-registry-{branchId}-{productId}-{chunkIndex}` ဖြစ်သည်။ `units[]` ထဲတွင် Unit ID, barcode, source, status, registration time, actor နှင့် optional batch/note သိမ်းသည်။

Registry တစ်ခုလျှင် Unit ၂၅၀ အထိသာ ထည့်သည်။ 50 ဘူး register လုပ်လျှင် 50 Firestore documents မဟုတ်ဘဲ Product + Branch Registry Document တစ်ခုကိုသာ sync လုပ်သည်။ 251 ခုကျော်လာလျှင် Registry Document အသစ် ထပ်ဖန်တီးမည်။

## စမ်းသပ်ရန် အဆင့်များ

1. Development copy ကို ဖွင့်ပြီး Owner ဖြင့် Login ဝင်ပါ။
2. `တစ်ဘူးချင်း Barcode` Menu ကို ဖွင့်ပါ။
3. Whole Quantity Product တစ်ခုရွေးပြီး Stock လက်ကျန်ကို စစ်ပါ။
4. ရှိပြီးသား Unique Barcode ၂ ခုကို Scan လုပ်ပြီး Register လုပ်ပါ။
5. Barcode တူညီသော Code ကို ပြန် Scan လုပ်ပါ — Reject ဖြစ်ရမည်။
6. Product Barcode သို့မဟုတ် SKU နဲ့ တူညီသော Code ထည့်ပါ — Reject ဖြစ်ရမည်။
7. App Generate မှာ ၃ ခု ထုတ်ပါ။ Label Print လုပ်ပြီး Scanner ဖြင့် ဖတ်စစ်ပါ။
8. မှတ်ပုံတင်နိုင်သည့် အရေအတွက်ထက် ပိုထည့်ပါ — Reject ဖြစ်ရမည်။
9. Page Refresh လုပ်ပြီး Registry မပျောက်ကြောင်း စစ်ပါ။
10. JSON Backup ထုတ်ပြီး Restore Test လုပ်ပါ။
11. Owner Cloud Sync Status ကိုစစ်ပြီး အခြား Owner Device မှာ Registry ရရှိကြောင်း အတည်ပြုပါ။
12. `npm run typecheck` နှင့် `npm run build` လုပ်ပါ။

## သတိပြုရန်

ဒီ Preview ကို Production ဆိုင်မှာ တန်းအသုံးမပြုပါနှင့်။ အရင်ဆုံး Backup ထုတ်ပြီး Test Branch / Test Device တွင် စမ်းသပ်ပါ။ Firestore Rules ကို ဒီအဆင့်မှာ မပြောင်းထားပါ။ Cloud Sync မအောင်မြင်ပါက Local Data သာ ရှိနေကြောင်း သတိပြုပြီး Owner Sync Status ကို ပြန်စစ်ပါ။
