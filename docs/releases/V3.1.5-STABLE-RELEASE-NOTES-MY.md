# Minimart POS v3.1.5 Stable Edition — ပြင်ဆင်ပြီးသော အချက်များနှင့် အသုံးပြုပုံ လမ်းညွှန်

ဤ `Minimart-v3.1.5-Stable-Fixed` ဗားရှင်းတွင် လက်တွေ့ဆိုင်သုံးရာ၌ Error မတက်စေရန်၊ Cashier နှင့် Owner ကြား လုပ်ငန်းစဉ် ချောမွေ့စေရန်နှင့် Firebase Free Tier (Spark Plan) လုံလောက်စွာ အသုံးပြုနိုင်စေရန် အောက်ပါအချက်များကို အသေးစိတ် ပြင်ဆင်ပေးထားပါသည်။

## ၁။ အဓိက ပြင်ဆင်ပေးထားသော အချက်များ (Key Fixes & Optimizations)

1. **Firebase Free Quota (Read/Write) 50% ခန့် သက်သာစေရန် ပြင်ဆင်ချက် (`cashierSalesSync.ts`, `CloudSyncPanel.tsx`, `OwnerAutoSync.tsx`)**
   - Cashier က ဘောင်ချာ (Sale) တစ်စောင် ရောင်းတိုင်း `stockBatches` စာရွက်စာတမ်းများကိုပါ Cloud Transaction ဖြင့် လိုက်ပြင်နေခြင်းကို ရပ်ဆိုင်းပြီး `products` stock နှင့် `sales` ကိုသာ Atomic Transaction ဖြင့် သိမ်းဆည်းအောင် ပြင်ဆင်ထားပါသည်။
   - မလိုအပ်ဘဲ Cloud သို့ အချိန်ပြည့် Sync လုပ်နေသော Local `activityLogs`, `heldItems` နှင့် အသုံးမပြုသည့် `stockUnitRegistries` Listener များကို ဖြုတ်ချထားပြီး `stockBatches` ကိုလည်း Incremental Cursor စနစ်သို့ ပြောင်းထားပါသည်။
2. **Cashier ဘောင်ချာ ၁၀၀ ကျော်လျှင် အရောင်းအသစ်များ ပျောက်သွားသည့် Bug ပြင်ဆင်ချက် (`App.tsx` & `CashierAutoSync.tsx`)**
   - ဘောင်ချာအသစ်နှင့် အသုံးစရိတ်အသစ်များ၏ ID ကို အချိန်အလိုက် အသစ်ဆုံးက အပေါ်ဆုံးရောက်သည့် Sortable ID (`sale-...`, `exp-...`) ပုံစံသို့ ပြောင်းလဲထားပြီး Local မှတ်တမ်းများကိုပါ ပေါင်းစပ်ထိန်းသိမ်းပေးထားသဖြင့် ဘောင်ချာ ၁၀၀ ကျော်သွားသော်လည်း အရောင်းအသစ်များ လုံးဝမပျောက်တော့ပါ။
3. **Cashier နှင့် Owner ကြား လုပ်ငန်းစဉ် တိုးမြှင့်ချက်များ**
   - **Cash Shift & Customer Credit**: Cashier အကောင့်ဖြင့် နေ့စဉ် ငွေကောင်တာ အဖွင့်/အပိတ် (`Cash Register / Shift`) နှင့် ဝယ်သူအကြွေးစာရင်း / အကြွေးပြန်ဆပ်ငွေ လက်ခံခြင်း (`Customer / အကြွေး`) တို့ကို အသုံးပြုနိုင်ပြီး Cloud သို့ အလိုအလျောက် Sync လုပ်ပေးပါသည်။
   - **Cashier Discount Limit**: POS တွင် Cashier ပေးနိုင်သော အများဆုံး Discount ရာခိုင်နှုန်း (Default `10%`) ကို ကန့်သတ်ထားပြီး Owner က `Settings` တွင် စိတ်ကြိုက် ပြောင်းလဲသတ်မှတ်နိုင်ပါသည်။
   - **Cashier Void Request (ဘောင်ချာပယ်ဖျက်ခွင့် တောင်းဆိုခြင်း)**: Cashier က ဘောင်ချာမှားရိုက်မိပါက `အရောင်းမှတ်တမ်း (Sales History)` တွင် **`Void တောင်းဆို`** ခလုတ်နှိပ်၍ အကြောင်းပြချက် ပို့နိုင်ပြီး၊ Owner ၏ Sales History တွင် အဝါရောင် သတိပေးချက်ဖြင့် ပေါ်လာကာ Owner က အတည်ပြု Void လုပ်ပေးနိုင်ပါသည်။
   - **Owner Expense Review ခလုတ်**: `Expense Management` စာမျက်နှာတွင် Cashier တင်ပြထားသော အသုံးစရိတ်များကို Owner က **`ကြည့်ရှုပြီး`** နှိပ်၍ အတည်ပြုမှတ်သားနိုင်ပါသည်။
   - **Offline Stuck Sale ရှင်းလင်းခြင်း**: Offline ရောင်းထားစဉ် Cloud Stock မလောက်၍ ပို့မရသော ဘောင်ချာရှိပါက POS ရှိ Queue Status bar မှတစ်ဆင့် တစ်ချက်နှိပ်ရုံဖြင့် ပယ်ဖျက်ပြီး Local Stock ပြန်ညှိနိုင်ပါသည်။
4. **Browser `localStorage` Quota ကာကွယ်မှုနှင့် Shared Device လုံခြုံရေး (`usePosStore.ts`)**
   - Browser `localStorage` 5 MB ပြည့်သွားသော်လည်း POS မရပ်သွားစေရန် Safe Storage Wrapper ထည့်သွင်းထားပြီး၊ Device တစ်ခုတည်းတွင် အကောင့်ပြောင်းဝင်ပါက ယခင်အကောင့်၏ Local Data များ ရောထွေးမနေစေရန် အလိုအလျောက် သန့်ရှင်းပေးပါသည်။

## ၂။ Run ရန်နှင့် Deploy လုပ်ရန် အဆင့်များ

```bash
npm install
npm run dev
```

Production Build ထုတ်ရန်:
```bash
npm run build
```

Firebase Console → Firestore Database → **Rules** ထဲတွင် ပါဝင်သော `firestore.rules` ဖိုင်အသစ်ကို ကူးထည့်ပြီး **Publish** နှိပ်ပေးပါ။
