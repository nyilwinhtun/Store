# Minimart POS v3.1.0 — Shipment Stock Count & Direct Cloud Fix (Preview 4)

## ဒီ Preview မှာ ပြင်ထားတာ

### 1. Shipment Form မှာ လက်ရှိ Stock ကို ပြန်ပြထားသည်
- Product ရွေးပြီးတာနဲ့ `လက်ရှိ Stock: N [unit]` ကို ပြမည်။
- `ပို့နိုင်သည့်အရေအတွက်` နှင့် `ပို့ပြီးနောက် ကျန်မည့်အရေအတွက်` ကို Form မှာ မပြပါ။
- အရေအတွက်ထက်ပိုပို့ခြင်း၊ Expired Batch၊ Batch မကိုက်ညီခြင်းတို့ကို နောက်ကွယ်မှာ ဆက်စစ်သည်။
- Stock အတည်ပြုမှုကို UI မှာ ဖျောက်ထားခြင်းသာဖြစ်ပြီး Stock Validation ကို မဖယ်ထားပါ။

### 2. Barcode ကို မူလနေရာမှာပဲ ဆက်သုံးသည်
- Sidebar မှ သီးခြား Barcode Menu မထည့်ပါ။
- Product Add/Edit ရဲ့ `Barcode (EAN / UPC)` Field ကို ဆက်သုံးသည်။
- POS Barcode Scanner ကို မပြောင်းထားပါ။
- ဒီ Shipment Fix မှာ ဘူးတစ်ဘူးစီ Serial Barcode ထုတ်ပေးသည့် Stock Unit စနစ်ကို မဖွင့်ပါ။ Product Barcode + Quantity မူလလုပ်ငန်းပုံစံကိုပဲ ထိန်းထားသည်။

### 3. Send ခလုတ် မတင်းကျပ်စွာ ပိတ်မနေစေရန်
- အရင် Preview မှာ App-wide Auto Sync `synced` ဖြစ်မှသာ ခွင့်ပြုထားသည့် Gate ကို ဖယ်ထားသည်။
- ပို့ရန်ခလုတ်က Owner Auth / Online စစ်ဆေးမှုကို Handler ထဲမှာ ရှင်းလင်းသော Message ဖြင့် ပြမည်။
- Form မှာ Branch နှစ်ခုနှင့် အနည်းဆုံး Product တစ်ခု ရွေးထားလျှင် ခလုတ်ကို နှိပ်ပြီး အကြောင်းရင်းကို ပြန်ရနိုင်သည်။
- Owner Firebase Session မမှန်ခြင်း သို့မဟုတ် Internet မရှိခြင်းကို လျစ်လျူရှု၍ Local-only Dispatch မလုပ်ပါ။

### 4. Shipment ကို Firebase Transaction ဖြင့် တိုက်ရိုက်သိမ်းသည်
- Source Branch ရဲ့ မူလ Product Stock နှင့် ပြောင်းလဲမည့် Batch များကို Firebase Server မှ ပြန်ဖတ်ပြီး Local snapshot နဲ့ နှိုင်းယှဉ်သည်။
- Source Product Stock, ပြောင်းလဲသော Stock Batch များနှင့် Destination Branch ရှိ `stockShipments` ကို Firestore Transaction တစ်ခုထဲမှာ သိမ်းသည်။
- Activity Log ရှိပါက Transaction နဲ့အတူ သိမ်းသည်။
- Server data က Local data နဲ့ မကိုက်ညီလျှင် Shipment ကို မသိမ်းဘဲ Local Stock ပြန်ထားသည်။
- Firestore Transaction အောင်မြင်မှသာ UI မှ ပို့ပြီးကြောင်း ပြသည်။
- Network acknowledgement မသေချာလျှင် Server Shipment ကို ပြန်စစ်သည်။ ပြန်စစ်လို့မရလျှင် Local dispatch ကို rollback လုပ်ပြီး ထပ်မပို့ရန် သတိပေးသည်။ Server က တကယ် commit လုပ်ခဲ့ပါက Owner Realtime Listener မှ Server အခြေအနေကို ပြန်ယူမည်။

### 5. Auto Sync နှင့် Direct Shipment Transaction ကို မတိုက်မိစေရန်
- Shipment Transaction အလုပ်လုပ်နေစဉ် Owner Auto Sync Store Listener က ထို Local mutation ကို သီးခြား Push မလုပ်စေရန် Event Lock ထည့်ထားသည်။
- Transaction အောင်မြင်ပါက Commit လုပ်ထားသော Record များကို Auto Sync ရဲ့ Live Map / Baseline ထဲ ထည့်ပေးသည်။
- `stockShipments` ကို Local Change Watch List ထဲ ထည့်ထားသည်။

### 6. Cashier လက်ခံမှု
- Cashier က သက်ဆိုင်ရာ Branch တစ်ခုတည်းနဲ့ ချိတ်ထားပြီး Owner က `Stock Receiver` Permission ဖွင့်ထားရမည်။
- Cashier Listener က Branch ရဲ့ `stockShipments` ကို Server Snapshot မှ ရယူသည်။
- Shipment အသစ်/လက်ခံရန်ကျန်နေသော Shipment ရှိလျှင် In-app Notification ပြမည်။ Notification ကိုနှိပ်လျှင် Receiving Page သို့ သွားမည်။
- ဒီ Preview မှာ App ပိတ်ထားချိန် FCM Background Push Notification မပါသေးပါ။

### 7. Local Cache စာတန်း
- Sidebar ရဲ့ `Offline Ready / Local data storage active` စာတန်းကို `Local Cache` ဟု ပြောင်းထားသည်။
- Local cache ရှိခြင်းသည် Firebase Cloud Sync အောင်မြင်ကြောင်း မဆိုလိုကြောင်း ရှင်းပြထားသည်။

## စမ်းသပ်ရန်

1. Owner Mac နဲ့ Cashier Phone နှစ်ခုလုံး Internet ချိတ်ပါ။
2. Owner App မှာ `Owner · Business Access` ဖြစ်ကြောင်း Profile / Firebase Account နဲ့ UID ကိုစစ်ပါ။
3. Owner ရဲ့ Auto Sync သည် Source Branch ရဲ့ Products / Stock Batches ကို အရင် Cloud ထဲ သိမ်းပြီးသားဖြစ်ရမည်။ Transaction က Server Stock ကို ပြန်စစ်သောကြောင့် Cloud မှာ မရှိသေးတဲ့ Product ကို Local ကနေ တိတ်တဆိတ်ပို့မည်မဟုတ်ပါ။
4. Shipment Form မှာ Source Branch, Destination Branch ရွေးပါ။ Product ရွေးလိုက်လျှင် `လက်ရှိ Stock` အရေအတွက် ပေါ်ရမည်။ `ပို့နိုင်` / `ပို့ပြီးနောက်ကျန်` မပေါ်ရ။
5. ပို့မည့်အရေအတွက်ကို လက်ရှိ Stock ထက် ပိုထည့်ပြီး စမ်းပါ။ Handler က တားရမည်။
6. မှန်ကန်သော Quantity ဖြင့် ပို့ပါ။ Firebase Server Transaction အောင်မြင်မှ Success Message ပြရမည်။
7. Cashier Member Document မှ `canReceiveStock: true` ဖြစ်ပြီး `branchIds` မှာ Destination Branch တစ်ခုတည်းသာ ရှိကြောင်း စစ်ပါ။
8. Cashier မှာ Shipment Notification / Receiving Record ရောက်ကြောင်း စစ်ပါ။
9. Cashier လက်ခံပြီး Owner Approve လုပ်မှ Destination Stock တိုးကြောင်း စစ်ပါ။
10. Network ဖြုတ်/Permission ပယ် စမ်းသပ်ပါ။ Failure ဖြစ်လျှင် Local Source Stock ပြန်မူလအတိုင်း ဖြစ်ရမည်။

## သတိပြုရန်

- Full `npm run typecheck` / `npm run build` ကို ဒီပြင်ဆင်မှုပြုလုပ်သည့် runtime တွင် Dependencies မရှိခြင်းကြောင့် အတည်မပြုနိုင်သေးပါ။ TypeScript / TSX Syntax Parsing သာ စစ်ဆေးထားသည်။
- Firebase Live Transaction နှင့် Cashier Device Receipt ကို Project ပိုင်ရှင်ရဲ့ Firebase ပတ်ဝန်းကျင်မှာ စမ်းသပ်ရမည်။
- `firestore.rules`, Firebase Project ID, Firebase API Config, Authentication, POS checkout နှင့် Product Add Barcode Flow ကို မပြောင်းထားပါ။
- Production မတင်မီ JSON Backup ထုတ်ပြီး Folder အသစ်တွင် စမ်းသပ်ပါ။
