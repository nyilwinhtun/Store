# v3.2.3 Hotfix 4 — Firestore Cashier Membership Rule Fix

## Root cause
`validCashierMember()` referenced `businessId` without accepting it as a function argument. Firestore Rules functions declared at service scope do not capture the `{businessId}` variable from a later `match` block. This caused a null-value Rules evaluation error when an Owner attempted to create a Cashier membership.

## Changes
- Added `businessId` to the `validCashierMember(businessId, memberId)` signature.
- Updated the `/businesses/{businessId}/members/{memberId}` create rule to pass the matched `businessId` explicitly.
- Changed `isActiveBranch()` to check `exists(path)` before reading branch document fields. Missing branches now fail closed without attempting to read null document data.

## Preserved
- Existing Owner UID validation.
- Cashier role, status, email, UID, and single-active-branch checks.
- Existing Firebase Authentication accounts and configuration.
- Branch/product/sales identifiers and business data.

## Verification required
Run `npm run test:rules` with Java and the project dependencies installed. The test `Owner can create a Cashier membership for one active Branch` must pass. Also verify that archived and missing branches remain denied.

This hotfix does not create Firebase Authentication accounts. The target Cashier Auth account must be provisioned by an authorized administrator before the Owner creates its membership mapping.
