# v3.1.2 — Branch Cash & KPay Ledger

## Objective

Branch-level Cash/KPay accounting ကို POS, Expenses, Cashier Settlements, Cash Shift နှင့် Customer/Supplier Payment records များမှ ခွဲခြားပြီး Double Counting မဖြစ်စေရန်။ ဒီ update သည် KPay API ဖြင့် ငွေလွှဲပေးခြင်း မဟုတ်ပါ။

## 1. Branch KPay Account

Account Name, Account Number, Label ကို Branch Settings ထဲတွင် သိမ်းသည်။ Branch ကိုယ်ပိုင် KPay လက်ခံ Account ဖြစ်ပြီး Cashier Personal KPay Account (ငွေလက်ခံသူ) နှင့် မတူပါ။ Ledger Start Date နှင့် Opening Cash/KPay Balance သတ်မှတ်နိုင်သည်။ Owner သာ ပြင်ဆင်နိုင်သည်။

## 2. POS Payment

POS မှ Cash / KPay / Credit ရွေးနိုင်သည်။ KPay ရွေးပါက Branch KPay Account ကိုပြပြီး transfer ပြီးကြောင်း Transaction ID ထည့်ရမည်။ `Sale.paymentMethod = 'KPay'`, `paidAmount = total`, `dueAmount = 0` အဖြစ် သိမ်းသည်။ KPay သည် Cash Shift Cash Drawer ကို မတိုးစေပါ။ Branch Finance Ledger ၏ KPay Inflow မှာသာ တိုးသည်။

## 3. Cashier Settlement

Owner က Active Cashier ကိုရွေးပြီး Expense Reimbursement / Cash Advance / Salary / Other Payment အဖြစ် Cash သို့မဟုတ် KPay ဖြင့် paid record တင်သည်။ KPay သည် လက်တွေ့ငွေလွှဲပြီးမှ Receiver Account နှင့် Transaction ID ဖြည့်ရန်လိုသည်။ Cashier သည် မိမိ UID record များကိုသာ ဖတ်နိုင်သည်။ KPay API integration မပါဝင်ပါ။

## 4. Branch Ledger

Ledger ကို Source Records ကနေ တွက်ချက်ပြီး Cash/KPay ခွဲထားသည်။ Manual Entries သည် Source Transaction အဖြစ် အခြားနေရာတွင်မရှိသော ငွေဝင်/ထွက်များအတွက်သာ ဖြစ်သည်။ Cashier Settlement Cash Out သည် CashMovement နှင့် ထပ်တွက်မိခြင်းကို `sourceSettlementId` ဖြင့် ကာကွယ်သည်။ Customer/Supplier Payments ကဲ့သို့ CashMovement ထပ်တူ records များကို source-note/sourceId ကနေ deduplicate လုပ်သည်။

## 5. Cash Advance

Advance payment သည် ထုတ်ပေးချိန်မှာ Cash/KPay Outflow ဖြစ်သည်။ နောက်ပိုင်း Branch-funded Expense တစ်ခုကို Advance နဲ့ reconcile လုပ်လျှင် Ledger ထဲတွင် Expense Outflow ကို ထပ်မတွက်ပါ။ Cashier က ကျန်ငွေပြန်အပ်လျှင် သက်ဆိုင်ရာ Channel Inflow အဖြစ်တွက်သည်။ Reconcile amount စုစုပေါင်းသည် Advance amount ထက် မကျော်ရ။

## 6. Duplicate KPay Reference

Local Store တွင် Branch တစ်ခုအတွင်း POS KPay Sale, Cashier KPay Settlement, Manual KPay Entry, Advance Return တို့အကြား reference ကို case-insensitive စစ်ထားသည်။ Deterministic IDs ကို Settlement နှင့် Manual Ledger မှာ အသုံးပြုထားသည်။ ဒီ Preview တွင် Cross-device global KPay Reference Registry မပါသေးပါ။ Live concurrent double-submit အတွက် server-side registry/transaction ကို နောက်ဆင့်တွင် ထပ်တိုးနိုင်သည်။

## 7. Cloud Sync & Permissions

`branchFinanceLedgerEntries` နှင့် `cashierAdvanceReconciliations` ကို Owner Auto Sync/Backup/Restore ထဲ ထည့်ထားသည်။ Branch KPay Account သည် Branch document ထဲက settings အနေဖြင့် Sync ဖြစ်သည်။ Firestore Branch Records generic owner rule သာ အသုံးပြုသည်။ Cashier သို့ finance ledger collections များ list/read permission မပေးထားပါ။

## 8. Known Limitations

- KPay transfer ကို app က အလိုအလျောက်လုပ်ခြင်း မဟုတ်ပါ။
- Supplier/Customer legacy `Transfer` method တွင် KPay reference/account fields မပါသေးသောကြောင့် အလိုအလျောက် KPay ledger line မဖန်တီးပါ။
- Full dependency install, Typecheck, Production Build, Firebase Live Device Test မအတည်ပြုရသေးပါ။
- Opening balance/start date ကို ပြန်ပြင်လျှင် ပြသမည့် historical balance ပြောင်းနိုင်သည်။ Production စသုံးမီ အဖွင့်လက်ကျန်နှင့် Start Date ကို မှန်ကန်စွာ သတ်မှတ်ပါ။
