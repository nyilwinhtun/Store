# Minimart POS v3.2.5 — Data Integrity & Offline Reliability

**အမျိုးအစား:** Release Candidate (QA မပြီးသေး)

## ရည်ရွယ်ချက်

v3.2.4 ၏ Multi-Branch, Shared Pricing, Login နှင့် Performance အခြေခံကို မပြောင်းဘဲ Cashier Offline Sale Queue၊ Duplicate Sale ကာကွယ်မှု၊ Product Stock နှင့် Stock Batch တစ်ပြေးညီဖြစ်မှုကို ခိုင်မာစေရန်။

## ပြင်ဆင်ချက်များ

1. **Durable Offline Queue** — Cashier Sale Queue ကို IndexedDB အဓိကသိမ်းဆည်းမှုဖြင့် ပြောင်းထားသည်။ IndexedDB မရနိုင်ပါက LocalStorage fallback ကို အသုံးပြုသည်။ Store နှစ်ခုလုံး မရပါက Queue Save အောင်မြင်ကြောင်း မပြောဘဲ Error ပြန်ပေးသည်။
2. **Legacy Queue Migration** — `minimart-cashier-sale-queue-v1` မှ v2 key သို့ ကူးယူသည်။ v2 ကို အောင်မြင်စွာရေးပြီးမှသာ v1 ကို ဖယ်ရှားရန် ကြိုးစားသည်။ မဖတ်နိုင်သော/UID သို့မဟုတ် Branch မကိုက်သော Queue ကို ဖျက်မပစ်ဘဲ ရပ်ထားသည်။
3. **Queue Race Protection** — Queue read-modify-write ကို တူညီသော UID/Branch အတွက် serialize လုပ်ထားသည်။ Browser Web Locks ရှိပါက Tab အချင်းချင်းလည်း Queue Mutation Lock သုံးသည်။
4. **Idempotent Cloud Commit** — Sale fingerprint နှင့် Voucher ID ကို အသုံးပြုပြီး Cloud Transaction ပြီးသွားသော်လည်း Response ပျောက်သွားသော Retry တွင် Stock ကို ဒုတိယအကြိမ် မလျှော့စေပါ။
5. **Atomic Product + Batch Stock** — Sale တစ်ခုတည်းသော Firestore Transaction ထဲတွင် Product Stock၊ ချိတ်ထားသော Stock Batch Quantity၊ Sale Record နှင့် Audit Record ကို သိမ်းသည်။
6. **Full Batch Coverage** — ရောင်းမည့် Product Quantity ကို Batch Allocation အပြည့်အဝ မဖုံးလွှမ်းနိုင်ပါက Checkout/Cloud Commit ကို အတည်မပြုဘဲ Owner စစ်ဆေးရန် ထားသည်။
7. **Offline Recovery Status** — Queue ထဲသိမ်းမရခြင်း၊ Cloud မရခြင်း၊ Rules ငြင်းပယ်ခြင်းနှင့် Stock/Price Conflict တို့ကို Sale တစ်ခုချင်းစီအလိုက် Pending/Review အဖြစ် ပြသနိုင်သည်။
8. **Firestore Rules v2** — Cashier Sync Version 2 Sale အတွက် Product/Bath delta metadata လိုအပ်စေပြီး Batch Stock Reduction ကို ချိတ်ဆက်ထားသော Sale ၏ `batchDeltas` နှင့် `batchLines` များနှင့် ကိုက်ညီစေသည်။

## Data Compatibility

- Branch ID၊ Product ID၊ Sale ID၊ Voucher No၊ Purchase၊ Stock Transfer နှင့် ယခင် Sales History ကို မပြောင်းပါ။
- ယခင် Cloud Sale Records များကို ပြန်ရေး/ပြောင်းလဲခြင်း မလုပ်ပါ။
- Firestore Rules တွင် `cashierSyncVersion: 1` အတွက် ယခင် Sale Create ပုံစံကို compatibility အဖြစ် ဆက်လက်ခွင့်ပြုထားသည်။ v3.2.5 Client အသစ်မှ ပို့သော Sale များမှာ Version 2 ဖြစ်သည်။
- LocalStorage v1 Queue ကို migration မအောင်မြင်မီ မဖျက်ပါ။
- Sale Voucher ထဲရှိ အရောင်းအချိန် Unit Price/Cost Snapshot ကို မပြောင်းပါ။

## Deploy သတိပြုရန်

**Cashier v3.2.5 ကို အသုံးမပြုမီ Test Firebase Project တွင် `firestore.rules` အသစ်ကို အရင်စမ်းသပ်/Deploy လုပ်ပါ။** v2 Sale တွင် Batch Metadata လိုအပ်သည်။ Rules အဟောင်းသာရှိနေပါက Cashier Sale ကို `permission-denied` ဖြစ်နိုင်သည်။ Production Rules ကို Emulator/Test Project QA ပြီးမှသာ Deploy လုပ်ပါ။
