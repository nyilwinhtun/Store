# Minimart v2.8.5 — React Runtime / Zustand Hook Fix

## Screenshot-based diagnosis

The reported browser error was:

`TypeError: Cannot read properties of null (reading 'useCallback')`

The stack points to `OwnerAutoSyncProvider` and `App` when they call the shared `useBusinessAccess` Zustand hook. Their ordinary React hooks begin executing, but the React hook dispatcher used by Zustand is not the same active runtime as the renderer. This is consistent with duplicate/mismatched React module resolution in the local Vite development dependency graph.

The project declared `react` but did not declare `react-dom` as a direct dependency, and Vite did not force React deduplication. That is a concrete dependency configuration defect. The patch addresses it by:

- Declaring `react` and `react-dom` as exact matching `18.3.1` dependencies.
- Pinning `zustand` to `5.0.3` for a deterministic React binding.
- Adding Vite `resolve.dedupe` for `react` and `react-dom`.
- Pre-optimizing `react`, `react-dom`, and `zustand` in Vite development mode.
- Updating the visible version to v2.8.5.
- Adding the modern `mobile-web-app-capable` meta tag. The existing Apple-specific tag remains for iOS; its Chrome warning was not the crash cause.

## Apply to the existing local project

1. Back up the current project folder. Do not delete browser storage or Firebase data.
2. Extract this ZIP into a separate folder.
3. Copy the v2.8.5 project files into the existing working project, keeping any private local `.env` file and Git settings that are not in the ZIP.
4. In Terminal, change directory to the project root (the folder containing `package.json`).
5. Stop the running Vite server with `Control + C`.
6. Run:

```bash
npm install
npm ls react react-dom zustand
npm run dev -- --force
```

7. Open the local URL again and hard-refresh Chrome with `Command + Shift + R`.

`npm ls react react-dom zustand` should show one React version (`18.3.1`), one ReactDOM version (`18.3.1`), and Zustand (`5.0.3`). If it lists multiple React versions, run `npm dedupe`, then stop and restart Vite with `npm run dev -- --force`.

## What was not changed

- Firebase API configuration and Authentication flow.
- Firestore paths/rules and Cloud Sync logic.
- LocalStorage keys/data schema and IndexedDB.
- POS, stock transfer, sales, branch, and Cashier business logic.

## Validation limitation

The available working container has no project `node_modules` and network package installation was not completed, so a full `npm run build` and live Firebase authentication test were not performed here. Source syntax, JSON validity, and ZIP integrity are checked separately. The local `npm install` + dev-server restart steps above are required to test the fix in the user's environment.
