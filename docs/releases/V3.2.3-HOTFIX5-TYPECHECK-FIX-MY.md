# Minimart POS v3.2.3 Hotfix 5 — TypeScript Fixes

## Issues reported from the user's local `npm run typecheck`

1. `src/components/SharedPricingPage.tsx`: legacy Product records allow an optional `branchId`, so the member branch set inferred `(string | undefined)`. Passing that value to `Map.get(string)` produced TS2345.
2. `src/lib/persistentStateStorage.ts`: the IndexedDB `new Promise(...)` constructor inferred `unknown`, and returning the nullable module-level cache produced TS2322 diagnostics.

## Changes

- Filter invalid / missing branch IDs before building `memberBranches`.
- Require a valid non-empty Product `branchId` before candidate Branch membership checks.
- Explicitly type the IndexedDB open operation as `Promise<IDBDatabase>`.
- Return a local typed Promise while retaining the shared cache and reset-on-error behaviour.

## Preserved

- Existing Product IDs and optional legacy `branchId` compatibility.
- `minimart-pos-data-v1` storage key and existing LocalStorage-to-IndexedDB migration behaviour.
- Firebase Authentication, Firestore Rules, Branch IDs, Price Group behaviour, Sales and Stock Transfer logic.

## Verification

The two reported type patterns were checked with strict TypeScript snippets and all TS/TSX files were parsed with the installed TypeScript compiler API. A full application typecheck / Vite build still must be run in the user's project environment after `npm install` because this packaging environment does not contain the complete application dependencies.
