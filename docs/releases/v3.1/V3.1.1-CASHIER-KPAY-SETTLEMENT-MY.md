# Minimart POS v3.1.1 — Cashier KPay & Cash Settlement (Preview 7)

## ရည်ရွယ်ချက်

Owner က Cashier တစ်ယောက်ချင်းစီကို Cash သို့မဟုတ် KPay ဖြင့် အမှန်တကယ်ပေးချေပြီးနောက် မှတ်တမ်းတင်နိုင်ရန်၊ Cashier က မိမိရရှိငွေမှတ်တမ်းကိုသာ ကြည့်နိုင်ရန် ဖြစ်သည်။ ဒီ Module က KPay ငွေလွှဲကို အလိုအလျောက် မလုပ်ပါ။ Owner သည် KPay App / အခြား Payment Channel မှ အရင်လွှဲပြီး Transaction ID ကို မှတ်တမ်းတင်ရသည်။

## ငွေရှင်းအမျိုးအစားများ

- `expense_reimbursement`: Cashier ကိုယ်ပိုင်ငွေဖြင့် အရင်စိုက်သုံးထားသော Expense ကို ပြန်အမ်းခြင်း။ Expense တစ်ခုလုံးကိုသာ ပြန်အမ်းနိုင်ပြီး တစ်ကြိမ်သာ ချိတ်ဆက်နိုင်သည်။ Expense ကို `reimbursedBySettlementId` ဖြင့် မှတ်သားထားပြီး မူလ Expense ကို ထပ်မတွက်ပါ။
- `cash_advance`: Cashier အား ကြိုတင်ငွေထုတ်ပေးခြင်း။ ဒီ Preview တွင် Advance အသုံးစရိတ်ပြန်လည်ရှင်းတမ်း / လက်ကျန် Advance reconciliation မပါသေးပါ။
- `salary`: လစာပေးချေမှု မှတ်တမ်း။
- `other`: အခြားပေးချေမှု။

## Payment Method

### Cash

- Owner က အမှန်တကယ် Cash ပေးပြီးမှ မှတ်တမ်းတင်ရသည်။
- သက်ဆိုင်ရာ Branch တွင် Open Cash Shift ရှိပါက Settlement တစ်ခုအတွက် Cash Out `CashMovement` တစ်ခု ဖန်တီးပြီး Shift ထဲတွင် ထည့်တွက်သည်။
- Open Cash Shift မရှိပါက Settlement Record ကို သိမ်းသော်လည်း Cash Shift Movement သီးခြားမဖန်တီးပါ။

### KPay

- Cashier လက်ခံသူအမည်၊ KPay ဖုန်းနံပါတ် / Account နှင့် Transaction ID မဖြစ်မနေ ထည့်ရသည်။
- Sender Account Name / Number သည် optional ဖြစ်သည်။
- Transaction ID တူညီသော Paid KPay Record ကို UI နှင့် Store နှစ်နေရာစလုံးတွင် တားထားသည်။ KPay Transaction Reference မှ Settlement Document ID ကို Deterministic ထုတ်ပေးသဖြင့် Owner Device နှစ်လုံးက တစ်ပြိုင်တည်းတင်လျှင်လည်း Cloud Sync Conflict အဖြစ် ဖော်ထုတ်နိုင်သည်။
- App မှ KPay တိုက်ရိုက်လွှဲခြင်း၊ Bank / KPay API၊ အလိုအလျောက် Balance Update မပါသေးပါ။

## အသုံးပြုပုံ

1. Owner သည် မှန်ကန်သော Branch ကို ရွေးထားရမည်။
2. `Cashier ငွေရှင်း` Menu ကို ဖွင့်ပြီး သက်ဆိုင်ရာ Branch အတွက် Active Cashier ကို ရွေးပါ။ Member စာရင်းကို Firebase `businesses/{businessId}/members` မှ ဖတ်သည်။
3. ငွေရှင်းအမျိုးအစားကို ရွေးပါ။
4. Expense ပြန်အမ်းမည်ဆိုလျှင် Cashier တင်ပြထားပြီး `cashier-personal` ဖြင့် ရန်ပုံငွေစိုက်ထားသော၊ ပြန်မအမ်းရသေးသော Expense ကို ရွေးပါ။ ပမာဏကို Expense အပြည့်အတိုင်း အသုံးပြုမည်။
5. Cash သို့မဟုတ် KPay ကို ရွေးပါ။ KPay ဖြစ်လျှင် လက်ခံသူအချက်အလက်နှင့် Transaction ID ဖြည့်ပါ။
6. ငွေကို အမှန်တကယ် ပေးချေပြီးကြောင်း Confirmation ကို အတည်ပြုပြီးမှ မှတ်တမ်းတင်ပါ။
7. Owner Auto Sync ပြီးသည်နှင့် သက်ဆိုင်ရာ Cashier ၏ `မိမိငွေလက်ခံမှတ်တမ်း` ထဲတွင် ပေါ်လာသည်။ Cashier သည် မိမိ UID နှင့် ကိုက်သော Record များကိုသာ ဖတ်နိုင်သည်။

## Data & Cloud Sync

Collection:

`businesses/{businessId}/branches/{branchId}/cashierSettlements/{settlementId}`

- Owner သည် Branch Settlement များကို ဖန်တီး၊ ဖတ်ရှုနိုင်သည်။
- Cashier သည် `payload.cashierUid == request.auth.uid` နှင့်ကိုက်ညီသော မိမိ Settlement များကိုသာ List / Get ဖတ်နိုင်သည်။ Cashier တွင် Create / Update / Delete ခွင့်မရှိပါ။
- Owner Auto Sync မှာ `cashierSettlements` ကို Branch Record အဖြစ် ထည့်ထားသည်။
- Cashier Auto Sync မှာ မိမိ UID အတွက် `where('payload.cashierUid', '==', uid)` နှင့် `limit(100)` ဖြင့် ဖတ်သည်။
- Settlement များကို Backup / Restore / Local Persistence / Cloud Sync ထဲ ထည့်ထားသည်။
- Cashier Settlement အသစ်အတွက် Firestore Realtime Listener တစ်ခု ဖွင့်ထားခြင်းမဟုတ်ဘဲ လက်ရှိ Cashier Auto Sync ကိုသာ တိုးချဲ့ထားသည်။

## Cash Ledger ချိတ်ဆက်မှု

- Cash Settlement သည် Open Shift ရှိပါက Cash Out Movement အဖြစ် စာရင်းဝင်သည်။
- KPay Settlement ကို Cash Drawer မှ မနုတ်ပါ။ KPay Account Balance Ledger / Branch KPay Account Management သည် နောက် Phase ဖြစ်သည်။
- Salary / Cash Advance / Other Payment ကို ဒီ Preview တွင် Settlement History အဖြစ်သာ သိမ်းသည်။ Profit Analytics ၏ Expense Total ထဲ အလိုအလျောက် မပေါင်းသေးပါ။ Accounting Integration ကို သီးခြား Phase အဖြစ်လုပ်ရန် ကျန်သည်။
- Expense Reimbursement သည် မူလ Expense ကို ဖျက်ခြင်းမဟုတ်ပါ။ `reimbursedBySettlementId` ချိတ်ဆက်မှုသာ ထည့်သည်။ Analytics တွင် Expense ကို တစ်ကြိမ်သာတွက်ပြီး Settlement ကို ပေးချေမှုမှတ်တမ်းအဖြစ် သီးခြားပြသည်။
