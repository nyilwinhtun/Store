# Minimart POS v3.1.0 — Cashier Expense Reporting (Preview 6)

## ဒီ Update ရဲ့ ရည်ရွယ်ချက်

Cashier က အသုံးစရိတ်ကို သုံးစွဲပြီးနောက် မှတ်တမ်းတင်ကာ Owner ထံ တင်ပြနိုင်ရန် ဖြစ်သည်။ Owner Approve မလုပ်မချင်း သုံးစွဲခွင့်ပိတ်ထားခြင်း၊ ပမာဏ Limit ကြောင့် Pending Approval ဖြစ်စေခြင်း မရှိပါ။ Owner ဘက်တွင် တင်ပြထားသော Expense စာရင်းကို ကြည့်ရှုရန်သာ ဖြစ်ပြီး Approve / Reject လုပ်ဆောင်ချက် မပါဝင်ပါ။ ငွေသုံးစွဲခွင့်၊ ငွေပေးချေမှု သို့မဟုတ် Reimbursement ကို ဒီ Module က ပိတ်ထားခြင်းမရှိပါ။

## Workflow

1. Cashier က Expense အမည်၊ Category၊ Amount၊ Funding Source၊ Payment Method နှင့် Note ထည့်သည်။
2. Save လုပ်ပြီးတာနဲ့ Local Expense Record ချက်ချင်းဖန်တီးသည်။ အသုံးစရိတ်ကို ဆက်လက်အသုံးပြုနိုင်ပြီး Owner Approval မစောင့်ရပါ။
3. Internet ရှိလျှင် Firebase သို့ တင်ပြသည်။ Offline ဖြစ်လျှင် Local Queue ထဲသိမ်းပြီး ပြန်ချိတ်သောအခါ Sync လုပ်သည်။
4. Owner ၏ Expense Management စာရင်းထဲတွင် Cashier UID / Branch အလိုက် ပေါ်လာသည်။
5. Owner သည် Expense Management စာမျက်နှာမှ တင်ပြထားသော စာရင်းကို ကြည့်ရှုနိုင်သည်။ Approve / Reject ခလုတ်နှိပ်ရန် မလိုပါ။

## Status

- `submitted`: Cashier က Owner ထံ တင်ပြထားသည်။
- `reviewed`: အဟောင်းစမ်းသပ်မှု Data တွေ ဖတ်နိုင်ရန်သာ optional field အဖြစ် ထားသည်။ ဒီ Version တွင် Owner Review Action မရှိပါ။
- `cloudSyncStatus: pending`: Internet/Cloud Sync မပြီးသေးပါ။
- `cloudSyncStatus: synced`: Cloud သို့ သိမ်းဆည်းပြီးပါပြီ။

`approvalStatus` သည် Preview 5 နှင့် အရင် Version များ၏ Record များကို ဖတ်နိုင်ရန်သာ Legacy Field အဖြစ် ကျန်ရှိသည်။ Version အသစ်သည် `not-required` သတ်မှတ်ပြီး Approval Gate အဖြစ် မသုံးတော့ပါ။ ယခင် `pending`, `approved`, `rejected` Record များကိုလည်း မဖျက်ဘဲ တင်ပြမှတ်တမ်းအဖြစ် ဆက်ဖတ်နိုင်သည်။

## Permission Matrix

| Action | Cashier | Owner |
|---|---|---|
| မိမိ Expense တင်ပြ | ခွင့်ပြု | ခွင့်ပြု |
| မိမိ Expense ဖတ် | ခွင့်ပြု | ခွင့်ပြု |
| အခြား Cashier Expense ဖတ် | မခွင့်ပြု | ခွင့်ပြု |
| Owner Expense Report ကြည့်ရှု | မိမိစာရင်းသာ | Branch အားလုံး |
| Approve / Reject | မလိုအပ် | မလိုအပ် |

## Firebase Data

ရှိပြီးသား Collection ကိုပဲ သုံးသည်။

`businesses/{businessId}/branches/{branchId}/expenses/{expenseId}`

Cashier Create သည် Expense Document တစ်ကြိမ် idempotent create ဖြစ်ပြီး Branch approval limit ကို ဖတ်ရန် Read ထပ်မလုပ်တော့ပါ။ Owner သည် Expense Document များကို ဖတ်ရှုနိုင်သည်။ Approval Update Transaction မလိုအပ်ပါ။ Firestore Rules က Cashier ကို မိမိ Expense Create/Get/List သာ ခွင့်ပြုပြီး Update/Delete မခွင့်ပြုပါ။ Owner သည် Business Owner Rules အတိုင်း ဖတ်ရှု/Update လုပ်နိုင်သည်။

## Compatibility

- Preview 5 မတိုင်မီ / Preview 5 Expense Records များကို မဖျက်ပါ။
- Legacy `approvalStatus` field ကို optional compatibility အဖြစ် ဆက်ထားသည်။
- Branch Settings ထဲရှိ `cashierExpenseApprovalLimit` ဟောင်းကို ဖျက်မထားသော်လည်း Version အသစ်တွင် မသုံးတော့ပါ။
- POS, Sales, Stock, Shipment, Branch Receiving နှင့် Firebase Login ကို မပြောင်းပါ။

## စမ်းသပ်ရန်

1. Owner Limit အဟောင်း 0 ထားထားသော်လည်း Cashier သည် Expense များစွာ တင်နိုင်ကြောင်း စမ်းပါ။
2. Owner က Expense တင်သွင်းချက်များကို ချက်ချင်းကြည့်နိုင်ကြောင်း စမ်းပါ။
3. Owner Expense Management စာမျက်နှာတွင် Cashier တင်ထားသော Expense များ ပေါ်ကြောင်း စမ်းပါ။
4. Owner မှာ Approve/Reject မလုပ်သော်လည်း Cashier က Expense အသစ်များ ဆက်လက်တင်ပြနိုင်ကြောင်း စမ်းပါ။
5. Offline တင်ပြီး Online ပြန်လာသောအခါ Duplicate မဖြစ်ဘဲ Sync ဖြစ်ကြောင်း စမ်းပါ။
6. Cashier A သည် Cashier B ၏ Expense များကို မဖတ်နိုင်ကြောင်း Rules Test ပြုလုပ်ပါ။
7. ယခင် Pending/Approved/Rejected Expense များ ဆက်ပေါ်နေကြောင်း စမ်းပါ။
8. Analytics သည် Expense တင်သွင်းပြီးသည်နှင့် အမှန်တကယ်သုံးစွဲမှုအဖြစ် စုစုပေါင်းထဲထည့်ကြောင်း စမ်းပါ။

Rules ကို Publish မလုပ်မီ မူလ Production Rules ကို Backup လုပ်ပြီး Owner UID / Business ID ကို မပြောင်းပါနှင့်။
