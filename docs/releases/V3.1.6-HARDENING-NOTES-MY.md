# v3.1.6 Hardening Notes — Minimart POS

## Scope

This is a targeted hardening update on top of v3.1.5. It is not a rewrite. The original uploaded ZIP is preserved separately. Firebase Authentication logic and the existing Firebase project configuration were not intentionally changed.

## Implemented in source

### Local persistence
- Added `src/lib/persistentStateStorage.ts` as an asynchronous Zustand storage adapter backed by IndexedDB.
- Migrates the existing `minimart-pos-data-v1` LocalStorage JSON into IndexedDB on first hydration and holds the App UI until persisted state hydration completes.
- Retains the old LocalStorage value as a recovery copy; migration does not delete it.
- Uses LocalStorage as a compatibility fallback, persists a fallback marker so an older IndexedDB snapshot cannot override a newer fallback value after restart, and surfaces a warning when the adapter falls back or cannot write.
- This applies to the main persisted Zustand state only. The Cashier offline-sale queue still uses its own LocalStorage implementation.

### Cashier expense approval
- Added a configurable per-Branch threshold in Branch Management.
- Defaults existing/new branches to 50,000 MMK when the field is absent; the stored setting remains optional for old data compatibility.
- A Cashier amount above the threshold is submitted with `approvalStatus: pending`.
- Owner can approve or reject a pending expense; rejection requires a reason.
- The expense's effective date is set to approval time so an unapproved request is not booked as a completed Branch expense before approval.
- Local Activity Log records approval-state changes.
- Pending/rejected expenses are excluded from financial totals, reports and reimbursement eligibility.

### Finance correctness
- Branch Cash Shift expected cash subtracts only `fundedBy === 'branch-cash'` expense entries, excluding pending/rejected entries and entries before the active shift opened.
- Expense CSV exports the separate Approval Status.

### Release/deployment consistency
- Updated package version and visible app version to 3.1.6.
- Bumped the PWA cache name.
- Updated the GitHub Pages workflow to avoid injecting unused `VITE_FIREBASE_*` variables which the current app does not read. The pinned config in `src/lib/firebase.ts` is retained.
- Updated README and Burmese startup notes.

## Not completed in this patch

1. Firestore security rules need a separate careful review and emulator tests. This build does not claim that existing broad record validators have been fully hardened.
2. Offline Cashier sale queue still uses LocalStorage and requires a durable queue migration.
3. Individual unit barcode registration / scan / cloud sync is incomplete.
4. Batch-level Stock allocation and expiry sync need an atomic transaction design and cross-device tests.
5. Refund/return and cross-device KPay transaction-reference uniqueness are not implemented by this patch.
6. Admin local PIN / local-mode access needs an authentication architecture review. It was not disabled because the existing login path would need redesign, not a blind UI lock.
7. Full `npm run typecheck`, production build, Firestore Emulator tests, and live multi-device tests remain to be run.

## Safety notes

- Do not clear browser storage during migration testing.
- Keep an exported backup before testing against any existing dataset.
- First test with a copied project folder and test Firebase account.
- Do not deploy to a live shop until the test plan passes, security rules have been reviewed, and a restore test succeeds.
