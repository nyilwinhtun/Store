# v3.2.5 Hotfix 3 — Server-side Shipment Auto Complete

## Customer-facing behavior (preserved)

- Cashier သည် သတ်မှတ်ထားသော Active Branch တစ်ခုအတွက် `canReceiveStock` ခွင့်ရှိမှ လက်ခံနိုင်သည်။
- ပို့ထားသော Product တစ်ခုချင်းစီ၏ အရေအတွက်အပြည့်ကို လက်ခံပြီး ပျက်စီးမှု `0` ဖြစ်ပါက Owner Approval မစောင့်ဘဲ Destination Stock သို့ Auto Complete လုပ်သည်။
- အရေအတွက်ကွာခြားမှု၊ ပျက်စီးမှု၊ Batch/Stock ကွာဟမှု၊ Duplicate Product Mapping၊ Unit Barcode Registry ရှိမှုတို့တွင် Auto Complete မလုပ်ဘဲ Owner Review သို့ fallback လုပ်သည်။
- Cashier က လက်ခံရန် အတည်ပြုခြင်းသာ ပြုလုပ်ရပြီး Server က Cloud data ကို ပြန်ဖတ်စစ်ကာ Stock ကို commit လုပ်သည်။

## Technical design

- Client သည် `completeBranchStockShipment` Callable Cloud Function ကို ခေါ်သည်။
- Function သည် Firebase Auth UID၊ email၊ Cashier membership၊ role/status၊ `canReceiveStock`၊ single-Branch assignment၊ Active Branch နှင့် Cloud Shipment status ကို စစ်သည်။
- Client ပေးသော before/after Product/Batch snapshot များကို Cloud document များနှင့် နှိုင်းယှဉ်သည်။ Product mapping ကို Cloud collection query များဖြင့် ပြန်စစ်ပြီး တစ်ခုထက်ပို match ဖြစ်ပါက ရပ်သည်။
- Product stock, weighted cost, shared price fields, Batch allocation coverage, Stock Unit Registry နှင့် duplicate IDs ကို စစ်သည်။
- Product records၊ အသစ်ဖန်တီးမည့် Batch records၊ Shipment status ကို Firestore Admin transaction တစ်ခုတည်းဖြင့် commit လုပ်သည်။
- Duplicate/retry တစ်ခုတွင် Shipment က အဲဒီ Cashier မှ Auto Complete ပြီးသားဖြစ်ပါက `alreadyCommitted` ပြန်ပေးသည်။ Client ack ပျောက်ပါက Cloud မှ Shipment status ကို ပြန်ဖတ်စစ်သည်။
- Firestore Rules ကို Cashier အတွက် Product/Batch stock တိုးရေးခွင့် ပေးရန် မဖွင့်ထားပါ။ Client direct create/update များကို Rules Test က ပိတ်ထားသည်။

## Required validation before customer pilot

1. Use Node.js 24.12.0 for the web app and Java 21 for the Firestore Emulator.
2. Run `npm ci`, `npm --prefix functions ci`, then `npm run qa`.
3. Deploy only the callable to a dedicated Test Firebase project first: `firebase deploy --only functions:completeBranchStockShipment --project <TEST_PROJECT_ID>`.
4. Ensure the Test project has the `store-mini-main` Business document, one active Branch, an active Cashier membership with `canReceiveStock: true`, Products and Batch records.
5. Test full exact receive, partial receive, damaged receive, duplicate click/retry, wrong Branch, disabled/unassigned Cashier, duplicate Product mapping, stale stock/batch, insufficient batch coverage, and unit barcode registry.
6. Verify Cloud Product stock, total Batch stock, Shipment status and audit fields after each test. Verify partial/damaged receipt does not increase stock before Owner approval.
7. Only after Test Firebase passes, deploy the callable to the configured production project and publish the website build.
