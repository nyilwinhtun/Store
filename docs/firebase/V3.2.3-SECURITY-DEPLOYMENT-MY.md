# v3.2.3 — Firebase Security Deployment Guide

## အရေးကြီးသော အခြေအနေ

ဒီ Release Candidate က Security Rules နှင့် Identity Platform Blocking Function များ၏ Source ကို ပြင်ဆင်ထားခြင်းဖြစ်သည်။ Firebase Production Project သို့ Deploy လုပ်ပြီးပြီဟု မဆိုလိုပါ။ Production Deploy မလုပ်မီ Test Project / Emulator မှာ စမ်းသပ်ပါ။

## v3.2.3 တွင် ပြင်ဆင်ထားသော Security အချက်များ

- ပုံမှန် Owner အခွင့်အရေးကို `businesses/{businessId}.ownerUid` နှင့် Firebase Auth UID ကိုက်ညီမှသာ ပေးသည်။
- Legacy Bootstrap UID သည် `store-mini-main` Business Document ကို ပထမဆုံးဖန်တီးရန်သာ အသုံးပြုနိုင်သည်။ အဲဒီ UID က Owner Data အားလုံးကို အမြဲဝင်ခွင့်ရသည့် fallback မဟုတ်တော့ပါ။
- Cashier အတွက် UID၊ Auth Email၊ `role: cashier`၊ `status: active`၊ Branch တစ်ခုတည်းနှင့် Active Branch ဖြစ်မှုကို Rules တွင် စစ်ဆေးသည်။
- Owner က Cashier Member အသစ်ဖန်တီး/Branch ပြောင်းရာတွင် Active Branch တစ်ခုတည်းကိုသာ သတ်မှတ်နိုင်သည်။
- Firestore Rules Emulator အတွက် automated test cases ထည့်ထားသည်။
- Security preflight script က Auth Function၊ Rules နှင့် public account creation မရှိမှုကို Static Check လုပ်ပေးသည်။

## 1. အရင်ဆုံး Owner UID ကို အတည်ပြုပါ

Firebase Console → Firestore Database → `businesses/store-mini-main` ကို ဖွင့်ပါ။ `ownerUid` တန်ဖိုးသည် လက်ရှိ Owner Firebase Authentication UID နဲ့ အတိအကျ ကိုက်ညီကြောင်း စစ်ပါ။

**မကိုက်ညီလျှင် Rules ကို Production မှာ မတင်ပါနှင့်။** မှားနေတဲ့ UID ကို မခန့်မှန်းပါနှင့်။ Owner UID ပြောင်းရန် သီးခြား Admin-approved migration လုပ်ငန်းစဉ် လိုအပ်သည်။

Cashier Member Document တစ်ခုချင်းစီတွင်—

- Document ID = Firebase Auth UID
- `uid` = တူညီသော Firebase Auth UID
- `email` = Firebase Auth Email (အသေးစာလုံးဖြင့် သိမ်းထားရန်)
- `role` = `cashier`
- `status` = `active` သို့မဟုတ် `disabled`
- `branchIds` = Active Branch ID တစ်ခုတည်း

ဖြစ်ရမည်။

## 2. Local Security Preflight

Project Root မှာ Terminal ဖွင့်ပါ။

```bash
npm install
npm run check:security
```

ဒီ Check က Source Code ကိုသာ Static စစ်ဆေးသည်။ Firestore Emulator Test အစားထိုးမဟုတ်ပါ။

## 3. Firestore Rules Emulator Test

လိုအပ်ချက် — Node.js 22၊ Java Runtime၊ Firebase CLI။

```bash
npm install -g firebase-tools
npm install
npm run test:rules
```

`test:rules` သည် `demo-minimart-pos-security` Project ID နှင့် Local Firestore Emulator ကိုသာ အသုံးပြုသည်။ Production Database သို့ မချိတ်ဆက်ပါ။

စမ်းသပ်ထားသော Case များ—

- Anonymous Read ပိတ်ထားခြင်း
- Business `ownerUid` သာ Owner ဖြစ်ခြင်း
- Legacy Bootstrap UID က အခြား Owner အဖြစ် ဆက်မဝင်နိုင်ခြင်း
- Cashier သည် သတ်မှတ်ထားသော Active Branch ကိုသာ ဖတ်နိုင်ခြင်း
- Email / UID mismatch ပယ်ချခြင်း
- Disabled Cashier ပယ်ချခြင်း
- Price Group Master ကို Owner သာ ဖတ်နိုင်ခြင်း
- Archived / Missing Branch သို့ Cashier ချိတ်ဆက်မရခြင်း
- Active Branch တစ်ခုတည်းရှိသော Cashier Member ကို Owner ဖန်တီးနိုင်ခြင်း

## 4. Identity Platform Blocking Functions

`functions/src/index.ts` တွင်—

1. `blockPublicAccountRegistration` (`beforeUserCreated`)
2. `allowOnlyOwnerAndActiveCashiers` (`beforeUserSignedIn`)

တို့ ပါဝင်သည်။ Function များသည် `store-mini-main` Business ကို စစ်ပြီး `asia-southeast1` Region တွင် 7-second timeout သုံးသည်။

Firebase Console မှ Firebase Authentication with Identity Platform ကို Upgrade လုပ်ပြီး Blocking Triggers နှစ်ခုကို Register/Enable လုပ်ရမည်။ Identity Platform လိုအပ်ချက်များ၊ Billing Plan နှင့် Cloud Functions အတွက် ကုန်ကျစရိတ်များကို Project Console မှ အတည်ပြုပါ။

Functions Build—

```bash
npm --prefix functions install
npm --prefix functions run build
```

Blocking Function များကို Test Project မှာ အရင် Deploy လုပ်ပါ။ Test Project အတွက် `functions/src/index.ts` ရှိ `BUSINESS_ID` တန်ဖိုးကို အဲဒီ Test Project ၏ Business ID နှင့် ကိုက်ညီအောင် သတ်မှတ်ပြီး Test Build အသုံးပြုပါ။ Production Build သို့ ပြန်ပြောင်းရာတွင် `store-mini-main` ဖြစ်ရမည်။

## 5. Production Deploy — အတည်ပြုပြီးမှသာ

Production မတင်မီ—

- [ ] Firestore Export / Backup အောင်မြင်ပြီး
- [ ] `ownerUid` ကို အတည်ပြုပြီး
- [ ] Emulator Rules Test အားလုံးအောင်မြင်ပြီး
- [ ] Owner Login Test အောင်မြင်ပြီး
- [ ] Active Cashier Login Test အောင်မြင်ပြီး
- [ ] Disabled / Unassigned / Archived-Branch Cashier ပယ်ချခံရပြီး
- [ ] Public Account Creation `beforeUserCreated` ဖြင့် ပယ်ချခံရပြီး
- [ ] Identity Platform Blocking Trigger နှစ်ခု Active ဖြစ်ပြီး
- [ ] Function Logs တွင် Error မရှိကြောင်း စစ်ပြီး

အောက်ပါ Command များသည် Production ကို တကယ်ပြောင်းလဲမည်ဖြစ်သည်။ Owner ခွင့်ပြုချက်နှင့် Backup ရှိမှသာ လုပ်ပါ။

```bash
firebase login
firebase projects:list
firebase deploy --only firestore:rules --project minimart-production
firebase deploy --only functions --project minimart-production
```

Deploy ပြီးလျှင် Identity Platform → Settings → Triggers တွင် `beforeCreate` နှင့် `beforeSignIn` တို့ မှန်ကန်တဲ့ Function ကို ညွှန်နေပြီး Active ဖြစ်ကြောင်း အတည်ပြုပါ။ Source Deploy သာလုပ်ခြင်းဖြင့် Trigger အလိုအလျောက် Register ဖြစ်မည်ဟု မယူဆပါနှင့်။

## 6. အရေးကြီးသတိပေးချက်များ

- `beforeUserCreated` သည် Firebase Project တစ်ခုလုံး၏ Client/Public Sign-up ကို ပိတ်သည်။ ဒီ Firebase Project ကို အခြား App များနှင့် မျှဝေသုံးနေပါက ထို App များ၏ Registration ကိုပါ ထိခိုက်နိုင်သည်။
- Identity Platform Blocking Functions သည် Anonymous Authentication နှင့် Custom Authentication Flow များကို မဖမ်းနိုင်ပါ။ ဒီ App တွင် ထို Flow များ မသုံးထားပါ။ Firestore Rules ကလည်း Email Claim နှင့် Active Cashier Member ကို ထပ်စစ်ထားသော်လည်း အခြား Client များအတွက် Anonymous / Custom Token ကို သီးခြားပိတ်ထားကြောင်း ပြန်စစ်ပါ။
- Firebase Console / Admin SDK မှ Admin က Account ဖန်တီးခြင်းသည် Privileged Provisioning ဖြစ်သည်။ Account အသစ်ကို Owner က Active Cashier Member အဖြစ် ချိတ်ပြီး Branch သတ်မှတ်ပြီးမှ Login အောင်မြင်ရမည်။
- Blocking Function ကို Delete လုပ်မည်ဆိုလျှင် Identity Platform Trigger ကိုလည်း Unregister လုပ်ရမည်။ မဟုတ်ပါက Authentication ပိတ်ဆို့နိုင်သည်။
- Firestore Rules သည် Web/Mobile Client SDK Request များကို ကာကွယ်သည်။ Admin SDK / Cloud Functions သည် Rules ကို Bypass လုပ်ပြီး IAM ဖြင့် အလုပ်လုပ်သည်။ Server-side Function များတွင်လည်း Authorization စစ်ဆေးရမည်။
- App Check ကို reCAPTCHA Enterprise ဖြင့် သီးခြား Configure လုပ်ပြီး Monitor Mode မှာ အရင်စောင့်ကြည့်ကာမှ Enforcement ဖွင့်ပါ။ Configure မလုပ်ဘဲ Enforce လုပ်လျှင် legitimate Web Client များ ပိတ်မိနိုင်သည်။
- Budget Alert တပ်ပါ။ Alert သည် Spend ကို အလိုအလျောက် မရပ်ပေးပါ။

## 7. ဒီ Package က မလုပ်ထားသောအရာများ

- Production Firestore Rules Deploy မလုပ်ထားပါ။
- Identity Platform Upgrade မလုပ်ထားပါ။
- Blocking Trigger Register/Enable မလုပ်ထားပါ။
- Production Owner UID / Member Data မပြောင်းထားပါ။
- Live Authentication / Firestore အပေါ် Write မလုပ်ထားပါ။
