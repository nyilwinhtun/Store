# v3.2.5 Firestore Rules Update — Deploy Guide

## ဘာပြောင်းလဲသလဲ

- Cashier Sale `cashierSyncVersion: 2` တွင် `batchDeltas` နှင့် `batchLines` လိုအပ်သည်။
- Batch stock update တစ်ခုချင်းစီကို ချိတ်ဆက်ထားသော Sale ၏ `batchDeltas` / `batchLines` နှင့် တိုက်စစ်သည်။
- v2 Sale သည် အနည်းဆုံး ရောင်းသော Product တစ်ခုချင်းအတွက် Batch allocation coverage ရှိရမည်ဟု အနည်းဆုံး key-count guard ထည့်ထားသည်။
- v1 Sale Create အတွက် အဟောင်း compatibility branch ကို ဆက်ထားသည်။

## Deploy မတိုင်မီ

1. Production မဟုတ်သော Test Firebase Project ကို ရွေးပါ။
2. `npm run test:rules` ဖြင့် Emulator Test 13/13 အောင်မြင်ကြောင်း စစ်ပါ။
3. `firestore.rules` ကို Review လုပ်ပါ။
4. `firebase use` ဖြင့် လက်ရှိ Project ID ကို ထပ်စစ်ပါ။

## Deploy Command

```bash
firebase use <TEST_PROJECT_ID>
firebase deploy --only firestore:rules
```

`<TEST_PROJECT_ID>` ကို Test Project ID ဖြင့် အစားထိုးပါ။ Project ID မသေချာလျှင် Deploy မလုပ်ပါနှင့်။

## Compatibility

ယခင် `cashierSyncVersion: 1` Cloud Sale Records များကို ပြန်ရေးရန် မလိုပါ။ v3.2.5 Client မှ ထွက်လာမည့် Sale အသစ်များကို Version 2 ဖြင့် ပို့မည်ဖြစ်သောကြောင့် Rules အသစ်ကို Client အသစ်မသုံးမီ Deploy လုပ်ထားရမည်။

## Important Limitation

Firestore Rules သည် Sale နဲ့ တစ်ပြိုင်နက်ပြောင်းသော Product/Batch Document များကို ချိတ်ဆက်စစ်ဆေးသည်။ သို့သော် Client-side checkout ကိုသာ ယုံကြည်ထားသည့် ဒီ Release Candidate သည် Server-authoritative POS ဖြစ်သေးသည်ဟု မဆိုနိုင်ပါ။ Production-grade financial authorization အတွက် နောက်အဆင့်တွင် Cloud Function/Callable Checkout ကို သီးခြားစီမံရမည်။
