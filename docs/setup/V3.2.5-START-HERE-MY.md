# v3.2.5 စတင်အသုံးပြုရန် (မြန်မာ)

## 1. အရေးကြီးသော သတိပေးချက်

ဤသည် **Pre-release Candidate** ဖြစ်သည်။ မူရင်း v3.2.4 ကို မဖျက်ပါနှင့်။ ZIP ကို Folder အသစ်သို့ Extract လုပ်ပြီး Test Firebase Project သာ အသုံးပြုပါ။ Live ဆိုင် Data ဖြင့် မစမ်းသပ်ပါနှင့်။

## 2. လိုအပ်ချက်

- Node.js `24.12.0` (`.nvmrc` အတိုင်း)
- npm
- Firestore Emulator Test အတွက် Firebase CLI နှင့် Java 21
- Test Firebase Project (Production မဟုတ်ရ)

## 3. Install နှင့် QA

Project Root Terminal မှာ အစဉ်လိုက် Run ပါ။

```bash
npm install
npm --prefix functions install
npm run check:security
npm run typecheck
npm run build
npm --prefix functions run build
```

Firestore Rules Emulator Test:

```bash
npm run test:rules
```

Full QA Script:

```bash
npm run qa
```

Java/Emulator မရသေးလျှင် Quick QA သာ:

```bash
npm run qa:quick
```

`qa:quick` သည် Firestore Emulator Test ကို ကျော်ထားသောကြောင့် Security Test အောင်မြင်ကြောင်း မဆိုလိုပါ။

## 4. Test Firebase Rules Deploy

Emulator Test အောင်မြင်ပြီးနောက်မှ Test Firebase Project ID ကို အတည်ပြုပြီး အောက်ပါ command ကို အသုံးပြုပါ။ `<TEST_PROJECT_ID>` ကို ကိုယ့် Test Project ID ဖြင့် အစားထိုးပါ။

```bash
firebase use <TEST_PROJECT_ID>
firebase deploy --only firestore:rules
```

Production Project ကို မရွေးထားကြောင်း `firebase use` ရလဒ်မှာ သေချာစစ်ပါ။ Production Rules ကို ဤ Candidate အတွက် အလိုအလျောက် Deploy မလုပ်ထားပါ။

## 5. ပထမဆုံး Device Migration

1. Owner Test Account ဖြင့် Test Project ထဲ Login ဝင်ပါ။
2. Owner Device ၏ Initial Cloud Sync ပြီးကြောင်း စစ်ပါ။
3. Product တိုင်းအတွက် Cloud Stock Batch စုစုပေါင်းသည် Product Stock ကို ဖုံးလွှမ်းကြောင်း စစ်ပါ။ မဖုံးလွှမ်းပါက Owner Sync ကနေ Opening Batch Coverage ပြည့်စုံစေပြီး Cloud သို့ Sync လုပ်ပါ။
4. Cashier Test Account ကို Branch တစ်ခုတည်း သတ်မှတ်ပါ။
5. Cashier Device မှာ Online Sale တစ်ခု၊ Offline Sale တစ်ခု၊ Internet ပြန်ချိတ်ပြီး Sync တစ်ခုစမ်းပါ။

**Cloud Stock Batch မရှိသော Product ကို v3.2.5 တွင် Cashier Sale အောင်မြင်စွာ Sync မလုပ်စေပါ။** Sale ကို Pending/Review ထားပြီး Owner က Batch Data ကို စစ်ဆေး/Sync ပြီးမှ ပြန်ကြိုးစားရမည်။

## 6. Local Data ကာကွယ်မှု

- Browser LocalStorage သို့မဟုတ် IndexedDB ကို မရှင်းပါနှင့်။
- v1 Queue Migration မအောင်မြင်ပါက legacy key ကို မဖျက်ပါနှင့်။
- Queue Parse Error တွေ့ပါက browser storage မရှင်းဘဲ Owner/Developer ထံ ပို့ပါ။
- Offline Queue Pending/Review ရှိနေစဉ် Browser Profile/Device ပြောင်းရွှေ့ခြင်း မလုပ်ပါနှင့်။
