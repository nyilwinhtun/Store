# Dependency Install Hotfix — v3.2.3 Hotfix 2

## Why npm install failed

The root app uses `firebase@^13.2.0`, while `@firebase/rules-unit-testing@^4.0.1` belongs to the Firebase 11 generation. npm correctly stopped with an ERESOLVE peer dependency conflict.

## Changes

- Updated `@firebase/rules-unit-testing` to `^6.0.0`, aligned with Firebase 13.
- Added `firebase-tools` as a local development dependency because `npm run test:rules` invokes the `firebase` CLI.
- Declared Node.js `>=24.12.0` for local development and added `.nvmrc`.
- Kept the Cloud Functions runtime in `functions/package.json` / `firebase.json` at Node 22; this local toolchain requirement does not change the deployed Functions runtime.

## Mac setup

Check the installed Node version first:

```bash
node -v
```

It should be `v24.12.0` or later. Then, from the project root:

```bash
npm install
npm run check:security
npm run typecheck
npm run build
npm run test:rules
```

The Firestore emulator tests also require Java 11 or later. `npm run test:rules` uses the local `firebase-tools` dependency.

Then build Cloud Functions separately:

```bash
npm --prefix functions install
npm --prefix functions run clean
npm --prefix functions run build
```

## Important

Do not use `--force` or `--legacy-peer-deps` to bypass this mismatch. The correct package versions should resolve normally. Do not deploy rules or functions to production until the local build and emulator tests pass.
