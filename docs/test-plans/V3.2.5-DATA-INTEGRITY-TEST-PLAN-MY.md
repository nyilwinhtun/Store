- [ ] Internet ဖြုတ်ပြီး Sale လုပ်သည်။ Pending Sale ကို IndexedDB Queue ထဲသိမ်းထားသည်။
- [ ] Page Refresh လုပ်ပြီးနောက် Pending Sale မပျောက်ပါ။
- [ ] Browser ပိတ်/ပြန်ဖွင့်ပြီး Queue ပြန်ဖတ်နိုင်သည်။
- [ ] IndexedDB မရနိုင်သော Test Browser Context တွင် LocalStorage fallback အလုပ်လုပ်ပြီး UI မှ Fallback Warning ပြသည်။
- [ ] IndexedDB နှင့် LocalStorage နှစ်ခုလုံး မရလျှင် Sale ကို safely queued ဟု မပြောဘဲ Error ပြသည်။
- [ ] v1 LocalStorage Queue ကို v2 သို့ ကူးယူသည်။ v2 Save မအောင်မြင်လျှင် v1 မဖျက်ပါ။
- [ ] Malformed Queue / UID မကိုက် / Branch မကိုက်ပါက Queue ကို မဖျက်ဘဲ Error ပြသည်။
- [ ] တူညီသော Sale ID နှင့် တူညီသော Fingerprint ကို ထပ်ထည့်လျှင် Queue Duplicate မဖြစ်ပါ။
- [ ] တူညီသော Sale ID နှင့် မတူညီသော Fingerprint ဖြစ်လျှင် Reject လုပ်သည်။
- [ ] Browser Tab နှစ်ခုမှ တစ်ချိန်တည်း Queue ပြင်ဆင်ရာတွင် Queue Entry မပျောက်ပါ။ (Web Locks ရှိသည့် Browser တွင် စမ်းရန်)

## C. Product / Batch Stock Integrity

- [ ] Product တစ်ခုကို Batch တစ်ခုမှရောင်းလျှင် Product Stock နှင့် Batch Quantity တူညီသောပမာဏ လျော့သည်။
- [ ] Product တစ်ခုကို Batch အများအပြားမှ FEFO/FIFO အလိုက် ခွဲရောင်းလျှင် Batch အားလုံးမှ မှန်ကန်စွာ လျော့သည်။
- [ ] Batch Allocation ပမာဏ စုစုပေါင်းသည် Sale Quantity အပြည့် မဖုံးလွှမ်းလျှင် Checkout ကို မအတည်ပြုပါ။
- [ ] Cloud Batch မရှိ/မတွေ့လျှင် Sale သည် Review အဖြစ် ကျန်ပြီး Cloud Product Stock မလျော့ပါ။
- [ ] Expired Batch ကို ရောင်းချမှုထဲ မပါစေပါ။
- [ ] Cloud Batch Quantity မလုံလောက်လျှင် Transaction ပျက်ပြီး Product Stock လည်း မလျော့ပါ။
- [ ] Batch Product ID သို့မဟုတ် Branch ID မကိုက်လျှင် Reject လုပ်သည်။
- [ ] Firestore Transaction အောင်မြင်လျှင် Sale, Audit, Product, Batch တို့ အားလုံးတစ်ပြိုင်နက် သိမ်းသည်။
- [ ] Transaction ပြီးပြီး Response ပြတ်သွားသည့်အခြေအနေကို Retry လုပ်လျှင် Stock ကို နှစ်ခါမလျှော့ပါ။
- [ ] မတူသော Sale Data ကို Voucher ID တူဖြင့် ထပ်ပို့လျှင် Review/Reject ဖြစ်သည်။
