# v3.2.6 Barcode & Receipt Hardware Acceptance Test Plan

**Target:** Android phone, Bluetooth HID scanner, USB HID scanner (USB-C OTG), ZYWELL ZM04, 80 mm receipt roll.

## A. Existing web/POS regression

- [ ] Owner login unchanged; public registration remains unavailable.
- [ ] Cashier login and branch/page permissions unchanged.
- [ ] Product-level barcode and SKU scans add the expected product to cart.
- [ ] Repeated product scan increments quantity exactly once per completed scanner read.
- [ ] Manual search and camera barcode scan still work.
- [ ] Retail/wholesale price mode and current shared-price checks still work.
- [ ] Cash, KPay, Credit validation is unchanged.
- [ ] Sale History, void request/approval, offline queue, backup/restore remain intact.

## B. Bluetooth HID scanner

- [ ] Android pairs with the scanner using Android Bluetooth settings.
- [ ] Scanner configured as HID keyboard works without opening the on-screen keyboard.
- [ ] Scan suffix Enter commits one scan only.
- [ ] 100 continuous scans are received without dropped, merged, or duplicated codes.
- [ ] Focus is not stolen while cashier is typing customer, cash received, discount, or KPay reference.
- [ ] Reconnect after scanner disconnect works.

## C. USB HID scanner

- [ ] Scanner connects through USB-C OTG.
- [ ] Android requests and grants USB access when required by the device.
- [ ] 100 continuous scans are received without dropped, merged, or duplicated codes.
- [ ] Unplug/replug is handled without restarting the POS.

## D. Product and unique unit barcode

- [ ] Existing product barcode scan adds product and increments quantity.
- [ ] Registered purchased-sticker barcode resolves to one matching product and one physical unit.
- [ ] Unit barcode is unique across all branches/registries as required by the data model.
- [ ] Already sold, damaged, missing, in-transit, or unknown unit cannot be checked out as in-stock.
- [ ] Two simultaneous devices attempting to sell the same unit cannot both succeed.
- [ ] Sale record and unit status are consistent after success, offline recovery, retry, or lost acknowledgment.
- [ ] Existing product-level barcode path remains backward compatible.

## E. ZYWELL ZM04 printer

- [ ] Confirm exact model/variant and Bluetooth vs Wi-Fi interface from the printer label/menu before implementation sign-off.
- [ ] Bluetooth connection from Android succeeds.
- [ ] USB-C OTG connection succeeds if supported by the exact unit and Android phone.
- [ ] Printer discovery, connect, disconnect, and reconnect statuses are accurate.
- [ ] Test print fits the selected 80 mm paper and confirmed printable width.
- [ ] Burmese Unicode item names and totals render legibly; raster fallback works if native font rendering fails.
- [ ] 1-item, 20-item, long-name, decimal-quantity, discount, Cash, KPay, and Credit receipts print correctly.
- [ ] Paper-out, printer-off, out-of-range, and connection-loss errors are displayed.
- [ ] Reprint from Sales History prints the existing voucher only.

## F. One-sale / one-voucher protection

- [ ] Confirm Sale creates exactly one sale record and one voucher.
- [ ] Double tap on Confirm cannot create a second sale.
- [ ] Print failure leaves the saved sale intact and marked print-pending/failed.
- [ ] Retry Print uses the same sale ID and voucher number and does not deduct stock again.
- [ ] Cart clears only after sale persistence succeeds; print failure does not recreate checkout.

## G. Release gates

- [ ] Web full QA passes (`npm run qa`).
- [ ] Android debug APK builds and installs on the target Android phone.
- [ ] All applicable tests above pass on physical hardware.
- [ ] No Production Firestore Rules or Cloud Functions deployment is performed without separate approved QA.
