# v3.2.5 Shipment Auto Complete Test Plan

## Test setup

- Dedicated Test Firebase project only; do not use live customer stock.
- Business document: `businesses/store-mini-main`.
- Destination Branch must be active.
- Test Cashier must be `role=cashier`, `status=active`, `canReceiveStock=true`, exact email match and exactly one `branchIds` entry.
- Test Shipment starts as `dispatched` and is stored at the destination Branch `stockShipments` collection.
- Destination Product + Batch records must be synchronized before receiving.

## Required scenarios

| # | Scenario | Expected result |
|---|---|---|
| 1 | Exact quantity, zero damage, valid Product and Batch mapping | Callable commits Product + new Batch + Shipment atomically; no Owner approval |
| 2 | Partial quantity | No stock increase; receipt saved as `received`; Owner Review |
| 3 | Damaged quantity greater than zero | No stock increase; receipt saved as `received`; Owner Review |
| 4 | Cashier lacks `canReceiveStock` | Callable denied; no Cloud write |
| 5 | Cashier assigned to a different Branch | Callable denied; no Cloud write |
| 6 | Member disabled, email mismatch or multiple Branch assignments | Callable denied; no Cloud write |
| 7 | Destination Product identity matches more than one record | Auto Complete blocked; Owner Review |
| 8 | Destination Product/Batch changed after local snapshot | Callable fails closed; no partial Cloud write |
| 9 | Destination Product Stock differs from total Batch Stock | Auto Complete blocked; Owner Review |
| 10 | Batch allocation total differs from Shipment quantity | Auto Complete blocked; Owner Review |
| 11 | Destination Product has physical Unit Barcode Registry units | Auto Complete blocked; use the unit-transfer workflow |
| 12 | Same callable request submitted twice | First call commits; retry returns already committed; stock is not doubled |
| 13 | Network acknowledgement lost after server commit | Client verifies approved/auto status from server; does not submit a second stock addition |
| 14 | Cashier tries direct Product/Batch stock create or increase from client | Firestore Rules deny it |
| 15 | Branch has no matching active category for a new Product | Auto Complete fails closed; Owner must set up the category first |

## Stock reconciliation assertions

After exact Auto Complete:

- Product `stock_after = stock_before + shipped_quantity`.
- Sum of active destination Batch quantities equals Product stock.
- Each new Batch carries the matching `sourceShipmentId`, `sourceShipmentLineIndex` and `sourceShipmentBatchIndex`.
- Shipment status is `approved`, `completionMode=auto`, and `autoCompletedByUid` is the authenticated Cashier.
- Product shared-price membership and effective prices remain unchanged when `priceGroupId` is present.

After a partial/damaged receipt:

- Product stock unchanged.
- Batch stock unchanged.
- Shipment status is `received` pending Owner review.

## Stop conditions

Stop the test and do not merge/deploy if a Cloud Function call is denied unexpectedly, Product/Batch totals differ, an exact receipt waits for Owner approval, or a retry increments stock a second time.
