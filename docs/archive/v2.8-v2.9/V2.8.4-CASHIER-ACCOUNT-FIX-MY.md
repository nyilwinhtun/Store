# Minimart v2.8.4 — Cashier Account Fix

## ပြင်ဆင်ထားသောအချက်များ

1. **Account အသစ်ဖန်တီးခြင်း** — Owner Session ကို မထိခိုက်စေဘဲ Secondary Firebase Auth App ဖြင့် Cashier Account အသစ်ဖန်တီးသည်။
2. **Existing Account ချိတ်ဆက်ခြင်း** — Firebase Authentication ထဲတွင် ရှိပြီးသား User ကို Firebase Console မှ UID အတိအကျဖြင့် Business Member အဖြစ် ချိတ်နိုင်သည်။
3. **Orphan Account Recovery** — Auth Account ဖန်တီးပြီး Firestore Member Write မအောင်မြင်လျှင် UID ကိုပြပြီး Existing Account Linking နည်းဖြင့် ဆက်လက်ပြင်ဆင်နိုင်သည်။
4. **Member မထပ်ရေးခြင်း** — Firestore Transaction ဖြင့် UID ရှိပြီးသားဖြစ်ပါက Owner/Cashier Document ကို overwrite မလုပ်ပါ။
5. **Branch Assignment** — ဖန်တီး/ချိတ်ဆက်ချိန်တွင် Active Branch အနည်းဆုံးတစ်ခုရွေးရမည်။

## အသုံးပြုနည်း

### Account အသစ်
- Owner Account ဖြင့် ဝင်ပါ။
- Profile → ဝန်ထမ်းအကောင့် / Branch Permission ကိုဖွင့်ပါ။
- “Account အသစ်ဖန်တီးရန်” ကိုရွေးပါ။
- အမည်၊ Email၊ Password နှင့် Branch များရွေးပြီး Create လုပ်ပါ။

### Firebase Authentication ထဲရှိ Account ကို ချိတ်ရန်
- Firebase Console → Authentication → Users ကိုဖွင့်ပါ။
- Cashier Email အတွက် UID ကို Copy လုပ်ပါ။
- App → Profile → ဝန်ထမ်းအကောင့် / Branch Permission → “ရှိပြီးသား Account ချိတ်ရန်” ကိုရွေးပါ။
- အမည်၊ Email၊ UID နှင့် Branch များထည့်ပြီး ချိတ်ပါ။
- UID သည် Firebase Authentication ထဲက User ၏ UID အတိအကျဖြစ်ရမည်။
- Member list ထဲပေါ်လာပြီးနောက် Password Reset Email ပို့နိုင်သည်။

## လိုအပ်သော Firestore Rules

လက်ရှိ deployed Rules ထဲတွင် အောက်ပါပုံစံနှင့် ကိုက်ညီသော Owner-only Member create permission ရှိရမည်။ Rules အားလုံးကို ဒီ snippet တစ်ခုတည်းဖြင့် အစားမထိုးပါနှင့်။

```javascript
match /businesses/{businessId}/members/{memberId} {
  allow create: if isOwner(businessId)
    && request.resource.data.uid == memberId
    && request.resource.data.role == 'cashier'
    && request.resource.data.status == 'active'
    && request.resource.data.branchIds is list
    && request.resource.data.branchIds.size() > 0;
}
```

## လုံခြုံရေးမှတ်ချက်

- Cashier User သည် Firebase Authentication ထဲမှာ အရင်ရှိရမည်။ UID ကို မမှန်မကန်ထည့်ပါက login မရနိုင်ပါ။
- ဒီ UI သည် Client-side Owner authorization ကိုသုံးသည်။ Firestore Rules သည် အမှန်တကယ် Security Boundary ဖြစ်သည်။
- Cashier Auto Sync နှင့် Server-side POS sale posting ကို ဤ update တွင် မထည့်ထားပါ။
- Firebase Admin SDK / Service Account Secret များကို Browser code ထဲ မထည့်ထားပါ။
