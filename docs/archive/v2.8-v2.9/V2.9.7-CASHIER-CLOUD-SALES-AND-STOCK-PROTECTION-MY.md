# Minimart v2.9.7 — Cashier Cloud Sales & Atomic Stock Protection

## ရည်ရွယ်ချက်

Cashier က POS မှာ ရောင်းချတဲ့အခါ Sale Record နဲ့ သက်ဆိုင်ရာ Product Stock / Stock Batch လက်ကျန်ကို Firestore Transaction တစ်ခုတည်းနဲ့ သိမ်းဆည်းရန်။ Transaction အောင်မြင်မှ Cloud ပေါ်မှာ အားလုံး commit ဖြစ်မယ်။ Transaction မအောင်မြင်ရင် Sale ကို Cashier Device ရဲ့ Local POS Data နဲ့ Local Queue ထဲမှာ ထိန်းထားပြီး Cloud မရောက်သေးကြောင်း UI မှာ ပြမယ်။

## v2.9.7 မှာ ပါဝင်တာ

- Cashier ရဲ့ Sale ကို `businesses/{businessId}/branches/{branchId}/sales/{saleId}` ထဲသိမ်းသည်။
- Sale ID ကို idempotency key အဖြစ်သုံးသည်။ အတူတူ Sale ကို Retry လုပ်လျှင် Cloud မှာရှိပြီးသား Sale ကို ပြန်စစ်ပြီး Stock ကို ထပ်မလျှော့ပါ။
- Product stock နှင့် Stock Batch quantity လျှော့ခြင်းကို Sale ဖန်တီးခြင်းနဲ့ Firestore Transaction တစ်ခုတည်းတွင် commit လုပ်သည်။
- Cloud Stock မလုံလောက်လျှင် Transaction ပျက်ပြီး Sale ကို `Needs Owner Review` အဖြစ် Local Queue ထဲ ထိန်းထားသည်။
- Internet မရှိလျှင် Sale ကို Local POS Store နှင့် LocalStorage Queue ထဲသိမ်းသည်။ Internet ပြန်ရပြီး Cashier Cloud listeners အဆင်သင့်ဖြစ်မှ အလိုအလျောက် Retry လုပ်သည်။ POS တွင် Pending Queue count နှင့် Retry ခလုတ် ပြသည်။
- Permission Denied ဖြစ်လျှင် Rules Error ဟု သီးခြားပြသည်။ Rules ပြင်ပြီးနောက် Queue ကို ပြန်ပို့နိုင်သည်။
- Credit Sale အတွက် Local မှာ Customer အသစ်ဖန်တီးထားပြီး Cloud shared customer မရှိသေးပါက Sale Transaction နဲ့အတူ Customer Snapshot ကို ဖန်တီးသည်။
- Owner Auto Sync က Cashier ရဲ့ Sale/Stock ပြောင်းလဲမှုတွေကို လက်ရှိ Listener များမှ ရရှိနိုင်သည်။

## Firebase ပြင်ဆင်ရန်

1. Owner နဲ့ Cashier စက်များတွင် JSON Backup ထုတ်ပါ။ LocalStorage/IndexedDB ကို မရှင်းပါနှင့်။
2. Project ID `minimart-production`၊ Business ID `store-mini-main`၊ Owner UID နဲ့ Firebase Config ကို မပြောင်းပါနှင့်။
3. လက်ရှိ Firestore Rules ကို Backup Copy ယူပါ။
4. ZIP ထဲက `firestore.rules` ကို စစ်ဆေးပြီး Firebase Console → Firestore Database → Rules မှာ Publish လုပ်ပါ။ ဒီ Rules က ဒီ Project အတွက် Owner UID ကို `LjZX15uSeehtIbyL4SqO1HcyLyC2` အဖြစ် သတ်မှတ်ထားသည်။ Project/Owner ပြောင်းထားလျှင် Rules ကို မတင်မီ ပြန်စစ်ပါ။
5. Firestore ထဲရှိ `businesses/store-mini-main` Owner Business Document နဲ့ Cashier Member Document တို့ ရှိနေပြီး Active ဖြစ်ကြောင်း စစ်ပါ။ Cashier `branchIds` တစ်ခုတည်းသာ ပါရမည်။
6. ZIP ကို Folder အသစ်အဖြစ် ဖြည်ပြီး VS Code မှာဖွင့်ပါ။ `.env` ကို အဟောင်းမှ လိုအပ်ပါက ကိုယ်တိုင်လုံခြုံစွာ ပြန်ထည့်ပါ။
7. `npm install`, `npm run typecheck`, `npm run build` ကို Run လုပ်ပါ။ အားလုံးအောင်မြင်မှ Deploy လုပ်ပါ။

## စမ်းသပ်နည်း

### A. ပထမဆုံး Cash Sale

1. Cashier Account နဲ့ သတ်မှတ်ထားတဲ့ Branch တစ်ခုတည်း ဝင်ပါ။
2. Cloud ထဲရှိ Product Stock နဲ့ Batch Stock ကို မှတ်ထားပါ။
3. Quantity 1 ပါတဲ့ Test Sale တစ်ခု ပြုလုပ်ပါ။
4. POS Queue Status မှ `Cloud ထဲသိမ်းဆည်းပြီး` အခြေအနေကို စစ်ပါ။
5. Firestore မှ Sale Record အသစ်တစ်ခု၊ Product Stock တစ်ကြိမ်လျော့မှု၊ Batch သုံးထားပါက Batch Quantity တစ်ကြိမ်လျော့မှုကို စစ်ပါ။
6. Owner Device ရဲ့ Sales History / Product Stock မှာ ပြောင်းလဲမှု ရောက်လာကြောင်း စစ်ပါ။

### B. Duplicate Protection

1. Network ပြန်ချိတ်ခြင်း သို့မဟုတ် Retry ခလုတ်ကို တစ်ကြိမ်ထက်ပိုနှိပ်ခြင်းကို စမ်းပါ။
2. Sale ID တူတဲ့ Sale တစ်ခုသာ Cloud မှာ ရှိရမယ်။ Product/Batch Stock ကို ထပ်မလျှော့ရပါ။

### C. Offline Queue

1. Cashier Device ကို Offline လုပ်ပြီး Test Sale ပြုလုပ်ပါ။
2. POS မှာ `Cloud သို့ မပို့ရသေးသော အရောင်း` ပြသရမယ်။
3. Internet ပြန်ချိတ်ပြီး Cashier listeners အဆင်သင့်ဖြစ်ပါစေ။
4. Queue က အလိုအလျောက် ပို့သင့်ပြီး မပြီးသေးရင် `ပြန်ပို့မည်` ကိုနှိပ်နိုင်သည်။

### D. Rules / Stock Error

- Firestore Rules မ Publish ရသေးလျှင် Sale ကို Local Queue ထဲ ထိန်းပြီး Rules Error ပြသရမယ်။
- Cloud Stock မလုံလောက်လျှင် `Owner စစ်ဆေးရန်` ပြသရမယ်။ အဲဒီ Sale ကို အလိုအလျောက် ပယ်ဖျက်ခြင်း၊ နောက်ထပ် Sale အဖြစ် ထပ်တင်ခြင်း မလုပ်ပါနှင့်။ Owner က Cloud Stock နဲ့ Local Sale ကို စစ်ဆေးပြီးမှ ဆက်လုပ်ပါ။

## အရေးကြီးသော ကန့်သတ်ချက်များ

- Offline Sale က Internet ပြန်ရပြီး Transaction အောင်မြင်မှသာ Owner ရဲ့ Cloud Sales ထဲ ရောက်မည်။ Pending Queue ရှိနေချိန်မှာ Cloud မှာ Sale အဖြစ် မပေါ်သေးပါ။ Cashier Device ရဲ့ LocalStorage Data ကို မရှင်းပါနှင့်။
- Cloud Stock နဲ့ Local Stock ကွာနေလျှင် Queue ကို Owner Review အဖြစ် ရပ်ထားမည်။ ကိုယ့်ဘာသာ Sale ကို ထပ်မံရောင်းချခြင်း၊ Queue ကို ဖျက်ခြင်း မလုပ်ပါနှင့်။
- Firestore Rules က Branch/UID/Transaction linkage နဲ့ Stock ကို အောက်သာပြောင်းနိုင်မှုကို ကာကွယ်ပေးသည်။ သို့သော် ဈေးနှုန်း၊ Discount၊ အခွန်/အမြတ် တွက်ချက်မှုအားလုံးကို ယုံကြည်ရသော Server မှ အတည်ပြုစစ်ဆေးသည့် Backend မဟုတ်သေးပါ။ Client ကို ပြုပြင်နိုင်သူကို ဆန့်ကျင်သည့် အပြည့်အဝ server-authoritative accounting လိုအပ်ပါက နောက်ပိုင်း Trusted Backend/Cloud Functions အဆင့် ထပ်လိုအပ်မည်။
- v2.9.7 Source ကို syntax/static စစ်ဆေးထားသော်လည်း Dependency install အချိန်ကုန်သွားသောကြောင့် ဒီ build environment မှာ Full `npm run typecheck`, production build နဲ့ Firebase Emulator/Live Hardware Test မပြီးသေးပါ။ Local မှာ typecheck/build အောင်မြင်ပြီးမှ Production ကို Update လုပ်ပါ။
